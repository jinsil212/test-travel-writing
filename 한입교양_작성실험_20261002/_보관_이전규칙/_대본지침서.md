### 시작 자료의 세 가지 형태 — 2026-09-13 사용자 요청

- **기본 대본이 있는 경우:** 사용자가 제공한 대본 전문을 출발점으로 삼는다. 원본을 보존하고 핵심 의도·살릴 내용·보강할 근거를 구별한다. 사용자가 확정한 내용과 초안의 제안을 구분하며, 이미 확정한 선택을 불필요하게 다시 열지 않는다. 사실 확인과 벤치마크 검토는 생략하지 않는다.
- **참고 영상 여러 개가 있는 경우:** 제공 영상의 확보 가능한 원문을 읽고 공통 사실·서로 다른 평가·출처를 대조한다. 내용 재료와 기획·문체 견본의 역할을 구분한다(P0-1). 여러 영상의 순서와 문장을 이어 붙인 대본으로 대신하지 않는다.
- **주제만 있는 경우:** 작업자가 관련 원본 영상과 신뢰할 수 있는 사실 출처를 검색·확보한다. 기존 채널 벤치마크도 확인하며, 부족한 자료를 사용자가 반드시 찾아오도록 떠넘기지 않는다.

세 형태는 함께 받을 수 있다. 자료 형태에 따라 조사 출발점이 달라지며 이후 일반/오토 절차와 제출 조건은 0-2·0-4·0-5를 따른다. 기본 대본이 있다는 말만 듣고 보관 중인 동명 원고를 최신 제공본으로 확정하지 않는다.

## 0-2. 작업 순서 — 이 순서를 바꾸지 않는다

1. **벤치마크 원고 정독** — 처음부터 끝까지. 뽑아둘 것: ① 첫 문장이 어떤 종류의 충격인지 ② 챕터 오프닝의 형식들 ③ **중간을 어떻게 끌고 가는지**(질문 밀도·인물 등장·감정 표지) ④ 클로징의 골격 (→ B4)
2. **리서치·팩트 수집** — 대본에 쓸 사실은 이 단계에서 출처를 확인한다. 다 쓰고 나서 틀린 걸 고치면 두 번 일이다 — *"검수 자체 단계에서는 실제로 걸리는 것들이 없어야"*
3. **기획** — P장 전체. 팩트 브리핑 → 3안 → 확정 → 세부(제목·썸네일·첫 문장)
4. **집필** — 아웃라인(챕터별 사건과 반전)을 먼저 짜고, **파트별로 쓰고**, 조립한다. 한 번에 통째로 쓰지 않는다
5. **자가검수** — G장. 실제 문제와 명시 요구의 누락을 **보고하기 전에 고치고 다시 확인한다.** 지켰는지 확인해 달라는 게 아니라 지켜진 결과물을 낸다
6. **산출** — 대본 전문 + 제목·썸네일 확정안과 대체 후보 + 자가검수 결과표 + 「이렇게 썼습니다」(P18). 사용자가 채널별 전달처와 게시 준비 항목을 지정한 경우, 해당 채널 설정에서 현재 단계에 지정한 항목을 준비하고 승인된 전달처에 반영·재조회한 뒤 제출한다. 대본 단계와 편집 후 최종 업로드 정보 단계의 담당·범위를 구별한다.

### 산출 후 채널별 전달 — 2026-09-14 최신 역할 분리

사용자가 지정한 전달 단계·담당·항목을 채널 설정에서 확인한다. 현재 단계의 항목은 별도 등록 요청을 기다리지 않고 승인된 작업 보드에 반영한다. 대본 단계의 제목·썸네일·본문과 편집 후의 최종 설명·타임스탬프·업로드 정보를 한 번에 강제하지 않는다. 사용자가 편집 후 처리를 다른 도구에서 한다고 지정하면, 해당 단계의 문안을 미리 만들거나 그 도구의 자동화까지 설정했다고 보고하지 않는다.

같은 편은 기존 카드를 갱신한다. 이미 선택한 문구를 유지하고, 편집자가 추가한 최종 정보는 대본을 수정한다는 이유로 덮어쓰지 않는다. 대상·상태·식별자와 현재 전달 범위는 채널 설정·이번 편 진행상태에 남기며, 카드 본문을 재조회해 실제 반영을 확인한다.

이 전달 위임은 ASK의 기획·제목·썸네일·도입 선택을 생략하는 오토 위임이나 유튜브 공개 게시 승인이 아니다. 편집본이 없으면 실제 길이·타임스탬프·영상 파일을 만들어낸 것으로 표시하지 않는다. 원고와 편집 완료의 상태를 구별한다.
### 트렐로 전달 요청은 TTS·영상 작업 시작까지 — 2026-09-25 사용자 확정

사용자: “내가 트렐로에 보내달라고 하면 항상 그때 TTS도 같이 시작하면 되거든. 영상 작업 단계로 이어서 넘어가면 되거든.”

- “트렐로에 보내줘/올려줘/트렐로 ㄱ”는 **해당 최종 원고 등록 → 채널 설정대로 TTS 생성 → 영상 프로젝트 전달 → 문장 시간 정렬·자막 생성 → 장면표·소재 준비 단계 진입**까지 요청한 것으로 처리한다. 등록만 하고 끝내거나 TTS 시작 여부를 다시 묻지 않는다. 사용자가 이번에는 원고만 보내라고 제한하면 그 제한이 우선이다.
- 대상은 사용자가 확정한 최종 원고다. 등록 직전 최신 파일과 카드 내용을 대조한다. 기존 카드·편집 프로젝트를 이어 쓰며, 원고·음성의 해시와 진행 기록으로 재실행·실패 후 재개 시 중복 카드·중복 합성을 막는다. 이미 최종 원고 및 확정 음성 설정과 일치하는 검수용 TTS가 있으면 재생성 대신 전달한다.
- 공용 실행 도구는 `_도구/trello_video_handoff.py`. 트렐로 등록 결과를 편 폴더의 `트렐로_등록결과.json`에 저장(`id`, `url`)한 뒤 `--episode "채널/원고/편" --channel-root "C:\영상편집\채널"`로 실행한다. 채널 전용 `azure_tts.py`·`autoedit`가 있는 경우 TTS→align→subs를 이어 실행한다. 다른 도구를 쓰는 채널은 해당 채널의 기존 절차로 같은 단계를 수행하고 미지원 경로를 다른 채널 도구로 임의 대체하지 않는다.
- TTS는 채널의 목소리·배속·쉼·읽기 변환 기준을 유지한다. 원고 정본과 발음용 변환을 구별하고 읽기 변환을 점검한다. 실패 시 성공으로 표시하지 말고 실패 단계부터 보완한다. 자막이 생성됐다는 것과 타이밍·발음 검수를 마쳤다는 것은 구별한다.
- 생성한 원고·음성·문장 시간·자막·제작 메모를 영상 프로젝트에 두고, 실제 완료 단계와 다음 작업을 기록한다. 장면표와 소재는 해당 채널 영상 지침에 따라 이어 준비한다. 영상 전체 제작 완료나 유튜브 공개 게시로 확대 해석하지 않는다. 기존 비용·외부 게시·소재 검수 기준은 유지한다.
- 이 연결은 **대화에서 등록 요청을 받을 때 실행하는 작업 흐름**이다. 별도 트렐로 상시 감시·예약 실행·무인 영상 완성 서비스가 설치됐다고 보고하지 않는다. 그런 서비스가 필요하면 별도 구현·실행 검증 후 구별해 보고한다.

### 전달 카드의 댓글 구성 — 원고 정보·검색 키워드·화면 타임스탬프 — 2026-09-25 사용자 확정 (전 채널 공용)

사용자: “관련 영상 키워드 올려달라고 했을 때는 딱 키워드만 올려주면 되고 순서를 그렇게 나눠서 해줘.” / “타임스탬프 내용을 댓글에 올릴 때는 TTS를 제작하고 나서 그다음에 실제 그 타이밍에 맞춰서 제대로 된 시간을 업데이트해줘.” / “지금 그 타임스탬프가 너무 잘게 쪼개져 있거든. 조금 하나의 챕터스러운 느낌으로 쪼개줄래?”

원고 카드(트렐로·클릭업 등 채널이 쓰는 보드)에는 **댓글을 역할별로 나눠서** 올린다. 한 댓글에 모두 넣지 않는다.

1. **원고 정보** — 제목, 썸네일 문구, 기획 의도, 핵심 주제, 제작 메모.
2. **참고영상 검색 키워드 — 키워드만.** 원고 순서대로 구간을 나누고, 구간마다 검색어만 줄바꿈으로 나열한다. 장면 설명·아카이브 안내·주의사항은 이 댓글에 넣지 않는다. 사용자가 직접 소재를 찾을 때 그대로 복사해 쓰는 용도다. 만드는 절차는 아래 「키워드 댓글은 대본이 완성되면 자동으로」를 따른다.
3. **화면 타임스탬프 — TTS를 만든 뒤에만.** 음성 파일의 문단별 실제 시각(`tts.chunks.json` 등 정렬 결과)으로 적는다. TTS 전에는 이 댓글을 올리지 않으며, 부득이 추정 시간을 보여줄 때는 추정치라고 밝힌다. TTS를 만든 뒤에 추정 시간을 남겨 두지 않는다.

**키워드 댓글은 대본이 완성되면 자동으로 만든다.** 사용자가 따로 요청할 때까지 기다리지 않는다.

사용자: “원고 작성 후에 내가 트렐로에 올려달라고 할 때, 너가 검색할 키워드들도 같이 메모에 추가해줘. 내가 직접 찾아서 추가해줄 수도 있어서.” / “대본 완성되면 관련 키워드 검색해서 댓글로 따로 달아주는 그 과정도 전 채널에 넣어줘.”

- **시점**: 최종 원고가 확정되어 보드에 등록하는 그 작업에서 같이 만든다. 원고 댓글과 **따로 된 댓글**로 올린다. TTS 전이어도 키워드 댓글은 올린다(타임스탬프 댓글만 TTS 뒤로 미룬다).
- **만드는 법**: 확정된 원고 본문을 처음부터 끝까지 읽고, 화면에 실제로 보여야 하는 대상을 원고 순서대로 뽑는다. 기억이나 기획안이 아니라 **최종 원고 본문**을 근거로 한다.
- **구간 나누기**: 위 챕터 구간과 같은 흐름으로 나눈다(대개 8~12개). 구간 제목은 대괄호 한 줄로 쓰고, 그 아래에 검색어만 줄바꿈으로 둔다.
- **검색어 형태**: 소재 검색에 그대로 붙여 넣을 수 있는 **영어 검색어**를 쓴다. 주제 핵심 명사 위주로, 뜻이 갈리는 단어는 보강한다(`pluto` → `pluto planet`). 화면이 나오는 말을 붙이면 좋다: `footage`, `archive`, `animation`, `timelapse`, `4K`, `no commentary`. 사람이 설명하는 영상이 걸리는 말(`interview`, `explained`, `documentary narration`)은 쓰지 않는다. 한국 자료라야 하는 대상(국내 인물·지명·사건)은 한국어 검색어를 함께 적는다.

### 극한실화 댓글 예외 — 사건 검색 키워드·챕터 목록 (2026-09-25 사용자 수정)

사용자: “해당 사건이 이름이 있다면 그 사건 관련해서 큼직한 키워드를 … 너무 세부적으로 장면별로 키워드 … 절대 금지.” / “타임스탬프도 왜 -> … 챕터를 나누는 형식”.

**극한실화에는 이 예외가 위·아래의 공용 댓글 형식보다 우선한다.**

- 키워드는 **해당 사건을 통째로 찾는 검색어**다. 알려진 사건명, 핵심 인물명, 선박·동굴·원정대 등의 고유명사에 필요한 사건·연도·지역만 결합한다. 공식 사건명이 없으면 새 이름을 만들지 않고 확인된 인물·대상의 이름을 쓴다. 한국어·원어 검색어를 함께 쓸 수 있다.
- **장면을 영어로 풀어 쓴 검색어, 소품·동작·카메라·분위기·일반 스톡 검색어는 절대 금지.** 원고 챕터마다 키워드를 배분하지 않는다. 공용 8~12구간·20~40개 기준도 적용하지 않는다. 사건 식별에 필요한 큰 검색어만 중복 없이 줄바꿈한다.
- 예: `Harrison Okene`, `Harrison Okene rescue`, `Jascon 4 sinking`, `해리슨 오케네 구조`. `underwater diver flashlight POV`, `floating wooden panel water`처럼 세부 장면을 찾는 말은 금지한다.
- 타임스탬프 댓글은 **`00:00 챕터 제목`을 한 줄씩 나열하는 챕터 목록**이다. 실제 TTS 시작 시각을 사용하고 이야기의 큰 전환으로 묶는다. **화살표(`→`, `->`), 장면 나열, 필요한 화면 칸, 컷 설명·편집 지시를 넣지 않는다.** 세부 화면 설계는 로컬 제작 문서에만 둔다.
- 키워드와 챕터는 각각 별도 댓글로 유지한다. 잘못 올린 댓글은 기존 댓글을 수정해 교체하고, 정정 댓글을 추가하여 잘못된 검색 목록을 남겨 두지 않는다. 재조회해 반영을 확인한다.

**타임스탬프는 챕터 단위로 묶는다.** 문단마다 한 줄씩 쪼개지 않는다. 아래 화면 포함 형식은 위 극한실화 예외를 제외한 공용 형식이다.

- 이야기가 바뀌는 지점으로 **8~10개 구간**을 만들고, 구간마다 `시작~끝 · 챕터 이름 · 필요한 화면`을 적는다. 12분 안팎이면 구간 하나가 대략 1~3분이다.
- 구간 경계는 **문단 시작 시각 그대로** 쓴다. 앞 구간의 끝은 다음 구간의 시작과 같은 값으로 맞춰 빈 구간이 생기지 않게 한다. 마지막 구간의 끝은 음성 전체 길이다.
- 구간 이름은 소제목이 아니라 편집자가 화면을 고를 수 있는 내용 이름으로 쓴다 (예: “그날 도장에서 벌어진 일”).
- 문단별 세부 전환은 버리지 않고 **편 폴더의 `화면_타임스탬프.md`에 편집용 참고표로만** 남긴다. 보드 댓글에는 챕터 표만 올린다.

### 클릭업 최종 전달 형식 — 2026-09-17 사용자 확정

## P0. 3안은 벤치마크의 기획 분석에서 만들고, 이번 주제의 사실로 성립시킨다

### P0-1. 주제 재료와 표현 견본을 구별한다

제공 링크·키워드는 이번에 다룰 소재의 출발점이다. 채널의 벤치마킹 원고·분석지는 그 소재를 어떻게 기획하고 표현할지의 근거다. 한 영상이 두 역할을 할 수 있지만 주제 원본의 순서에 자동 고정하지 않는다. 사실은 독립 출처로 확인하고 원본에 없는 보강 재료는 표시한다.

### P0-2. 분석지 목록을 살핀 뒤 적합한 견본을 고른다

해당 채널의 분석지 색인과 핵심 방향을 비교해 이번 주제에 맞는 견본을 고른다. 늘 같은 001·003만 읽는 방식으로 고정하지 않는다. 같은 주제라는 이유만으로 선택하지 않고, 전달하려는 질문과 전개 기능이 비슷한 다른 소재도 검토한다. 실제 사용할 견본은 분석지뿐 아니라 원문 전문을 읽는다. 제목·썸네일을 참고할 때 실제 자료도 확인한다.

### P0-3. 견본별 기획 연결을 기록한다

### P0-4. 원본의 작동 방식을 새 사실로 옮긴다

안마다 다음 연결표를 만든다:
**견본 영상·근거 구간 → 견본이 사용한 기획/표현 방식 → 이번 주제에서 대응하는 검증 사실 → 새 핵심 주제·후킹 문장 → 제목·썸네일 → 전개와 마지막 답**.

‘질문형 참고’처럼 유형 이름만 쓰지 않는다. 예: 견본이 ‘가깝다는 말 ↔ 실제 이동의 어려움’으로 기대를 바꿨다면, 이번 주제에도 두 사실이 실제로 대비되는지 확인한다. 대비할 사실이 없으면 그 방식을 버린다. 인물 사건·반전·감정 표현을 형식 충족용으로 지어내지 않는다.

### P0-5. 서로 다른 가능성을 검토한 뒤 가장 설득력 있는 3안을 남긴다

### P0-6. 화면 제작 조건도 기획 단계에서 평가한다

AI 이미지 중심·실사 중심·혼합 등 사용자 조건을 먼저 확인한다. 각 안에 **AI로 표현 가능한 핵심 장면 / 실제 자료가 필요한 장면 / 대체했을 때 잃는 의미 / 제작 적합도**를 짧게 적는다.

- AI 이미지·도식·간단한 움직임으로 비교와 설명이 가능하면 우선 그 방식으로 구성한다. ‘우주 배경’만 반복하지 않고 문장마다 보여줘야 할 대상·상태·관계를 정한다.
- 실제 사진의 발견·판독이 핵심인 기획에서는 실제 자료가 증거다. 생성 이미지를 실제 관측 사진·실제 사건 기록으로 제시하지 않는다. 재현·개념도는 그렇게 구별한다.
- 실사가 필요하다고 좋은 기획을 무조건 버리지 않는다. 소량의 실제 자료를 섞을 수 있는 안, AI 중심으로 핵심을 유지해 바꾼 안, 대체하면 핵심이 무너지는 안을 구별한다. 실제 자료 혼합을 아직 승인받지 않았다면 조건부로 표시한다.
- 시각 자료 없이도 내레이션에서 대상과 의미가 이해되는지 확인한다. 축척·거리·시점은 생성 이미지의 외관을 사실 근거로 삼지 않고 검증된 수치와 별도 도식으로 관리한다.

### P0-6a. 실사 의존 문장을 쓰면 실제 자료도 함께 준비한다

2026-09-13 사용자 요청:AI 이미지 중심 채널에서 실제 촬영 사진·영상이 있어야 성립하는 문장을 작성했으면 작성자가 자료를 찾아 원고 맨 아래에 함께 첨부한다.사용자가 다시 검색해야 하는 상태로 넘기지 않는다.

- 기획과집필에서 화면을 **AI 삽화/도식으로 설명 가능 · 실제 관측/촬영 자료 필수 · 선택적 실사 보강**으로 구별한다.‘달이 보인다’는 설명만으로실사필수라고단정하지않는다.특정사진에찍힌형태나특정관측의증거를설명할때는그실제자료를확보한다.
- 실사가 필요한 구간에는 **대응 대사 / 사용할 자료 / 원본 페이지 / 직접 다운로드 링크 또는 확보 파일 / 크레딧·확인한 사용 조건 / 삽입 위치 / 자료의 성격과 확인 상태**를 원고 아래에 붙인다.검색결과목록·‘NASA에서찾으세요’로대체하지않는다.필요없는다운로드나유료결제는추가하지않는다.
- 관측사진·사진모자이크·합성영상·시뮬레이션·AI 이미지를 구별한다.여러사진을합친이미지를실시간촬영한한장으로소개하지않는다.확인안한권리를무료사용가능이라고단정하지않는다.
- 필수 자료를 확보하지 못했으면 그 문장·화면을 AI로 사실인 것처럼 채우지 않는다.확보 상태를 표시하고 AI 도식으로 정확히 설명 가능한 문장으로 재구성한다.기획선택의핵심이바뀌면그영향을기록한다.

### P0-7. 제출과 기록

일반 진행에서는 P5-1 비교표에 ‘참고한 벤치마크와 가져온 기획 방식’, ‘이번 주제에 적용한 사실’, ‘AI 제작 적합도’를 추가하고 구체 근거는 표 뒤에 설명한다. 핵심·후킹 문장과 제목·썸네일·전개의 연결을 먼저 읽을 수 있게 한다. 오토에서는 같은 비교를 내부 기록으로 남기고 선정 이유만 최종 산출물에 짧게 제시한다.

### P0-8. 관찰·해석·적용 조건을 구별한다

벤치마크 분석과 색인을 읽을 때 각 요소를 **원본에서 확인한 관찰 / 효과에 대한 해석·가설 / 새 주제에서도 필요한 기능 / 원본이 선택한 형식**으로 구별한다. 관찰에 없는 근거를 덧붙이지 않는다.

예: ‘비교 대상 12개를 사용했다’는 관찰이고 ‘같은 기준으로 차이를 느끼게 한다’는 기능 해석이다. 12개, 반전 위치 70%, 질문 3개 같은 수치를 모든 원고의 의무 형식으로 올리지 않는다. 수치·기능을 적용할 때는 해당 주제의 재료와 목표 길이로 근거를 설명한다.

색인의 ‘필수·탈락·반드시’도 과거 분석자의 적용 가설일 수 있다. 그 요소가 없어도 같은 질문과 전개가 성립하는 대안을 먼저 검토한다. 다만 핵심 사실·인과·제목의 약속에 필요한 증거는 형식처럼 생략할 수 없다. 두 편에서 비슷한 장치가 관찰돼도 성공 원인으로 입증됐다고 쓰지 않는다.

### P0-9. 목표 길이를 버틸 이야기 재료가 있는지 기획 때 확인한다

안마다 **도입에서 생기는 질문 → 중간에 처음 밝혀지는 사실·설명 → 그로 인해 생기는 다음 질문 → 마지막에 주는 답**을 적고 각 구간의 근거를 연결한다. 이번 목표 길이에 맞는 국면 수와 설명 깊이를 판단한다. 우주 채널은 최소 10분 이상이 필수이며, 기존 15분은 목표 참고값이다. 요청 길이별 범위는 P0-15를 따른다.

중간 칸이 같은 주장·수치의 재진술뿐이면 제목만 강한 안으로 판정해 보강하거나 제외한다. 반드시 반전이나 인물 사건을 넣으라는 뜻은 아니다. 설명형도 이해가 단계적으로 깊어지면 성립한다. 재료가 부족하면 검증된 원인·과정·비교를 더 조사하고, 분량을 채우기 위한 새 소재와 억지 사건을 늘리지 않는다. B6·B8·S3의 분량·중복 기준과 함께 본다.

### P0-10. 원본을 본 사람에게도 줄 새 가치를 적는다

각 안에 **‘원본을 이미 본 사람도 이번 영상을 볼 이유’**를 구체적인 한 문장으로 쓴다. 더 이해하기 쉬운 일관된 비교, 원본에서 짧게 지나간 과정의 해설, 검증된 새 근거, 새로운 질문이나 연결 등 실제 본문에서 제공할 가치여야 한다.

‘더 재미있게·더 쉽게’만 적으면 미완성이다. 무엇을 어떻게 바꿨는지 특정한다. 차별화를 위해 사실을 뒤집거나 새로운 발견인 것처럼 과장하지 않는다. 같은 주제를 다뤄도 되며 매번 새 소재를 찾아야 한다는 규칙이 아니다. 대응하는 본문 구간을 지목할 수 없으면 그 약속을 줄이거나 기획을 보강한다.

### P0-11. 도입·중간·후반의 핵심 화면을 미리 설계한다

각 안에 대표 장면 3개를 **구간 / 보여줄 대상·상태·관계 / 시청자가 이해할 것 / AI 이미지·도식·실제 자료 중 구현 방식 / 확보 상태**로 기록한다. 이는 제작 가능성을 확인할 대표 지점이며 전체 영상의 컷 수나 동일한 3막 형식을 강제하는 수치가 아니다.

배경 분위기만 다른 장면이면 다시 설계한다. 문장의 핵심 정보가 화면에서 보이는지, 같은 우주·인물 배경만 반복되는지 확인한다. 거리·시간·크기 비교는 정확한 표시와 도식을 사용하고 생성 이미지의 외관으로 사실을 증명하지 않는다. 일반 진행은 표 뒤에 간단히, 오토는 내부 기획 기록에 남긴다. 기획 단계에서 이미지 생성 자체를 실행할 필요는 없다.

### P0-12. 선정·비선정 이유와 재검토 조건을 남긴다

제출한 3안의 추천 이유와 약점, 검토 후 제외한 유력 방향의 핵심 약점을 짧게 남긴다. 핵심 재료 부족·질문 불명확·중복·화면 의존 등 구체적으로 적고 **어떤 조건이 달라지면 다시 쓸 수 있는지** 함께 기록한다. 검토하지 않은 후보를 검토했다고 만들지 않는다.

‘점수가 낮음’만으로 끝내지 않는다. 사용자 선택으로 추천이 뒤집히면 실제 선택과 사용자 발언을 남기며, 말하지 않은 선택 이유를 추정해 사용자 의견으로 기록하지 않는다. 오토의 선정·비선정 이유는 내부 기록하고 최종 결과에는 필요한 근거만 요약한다.

### P0-13. 사용자 선택과 업로드 성과를 분리해 누적한다

채널의 기존 수정·선택 기록 파일에 이어 기록해 규칙 파일을 추가로 늘리지 않는다. 공통 기록 방법은 여기, 채널의 실제 기록은 채널 안에 둔다.

- **선택 기록:** 편·날짜, 제안/작업자 선정/사용자 선택/수정 요청/최종 원고 합격 상태, 선택·반려한 안, 사용자 발언, AI 추천과 달랐던 점. 한 항목의 채택을 원고 전체 합격으로 보지 않는다.
- **제목·썸네일 선택 기록(2026-09-18):** 채널 `수정·선택 사례.md`에 「제목·썸네일 선택 기록」 절을 두고, 사용자가 확정·직접 수정한 문구를 선택 즉시 누적한다. 다음 편 후보는 이 기록에서 출발한다(T0). 채널에 파일이 없으면 이 이름으로 만든다.
- **성과 기록:** 실제 업로드 URL·날짜·최종 제목과 썸네일, 측정 날짜·업로드 후 경과일, 확보 가능한 조회수·노출·클릭률·평균 시청·유지율 등. 확보하지 못한 값은 미확보로 표시한다. 초안 제목과 업로드 제목이 다르면 실제 사용본을 기준으로 연결한다.
- 사용자 선호와 성과는 따로 해석한다. 다른 채널·업로드 시점·길이·노출 조건의 단순 조회수 차이를 특정 문구의 인과 효과로 결론내리지 않는다. 좋은 반응뿐 아니라 낮은 반응과 반례도 남긴다.
- 다음 기획 때 관련 기록을 확인하고 반복 관찰이 있는지 검토한다. 가설을 공통 규칙으로 자동 승격하지 않는다. 아직 업로드하지 않은 원고에 성과를 채우지 않는다. 이 기록 규칙은 별도 자동 모니터링 예약이나 계정 연결을 뜻하지 않는다.

### P0-14. 소재 목차보다 먼저 핵심 질문과 답의 흐름을 설계한다

사용자 피드백:단순히 내용을 설명·나열하는 원고가 아니라 핵심 주제를 뽑고 흥미롭게 풀어내야 한다. 핵심 질문의 수는 이번 편의 승인된 범위에 맞춘다. 과거 우주 편의 질문 3개 제안은 이력이며 현재는 사용자 승인 5단계 구성을 따른다. 모든 채널·모든 원고의 본문을 3개나 5개로 강제하지 않는다. 초기 기획 후보3안(P5-1)과 한 편 안의 핵심 질문 수를 혼동하지 않는다.

각 핵심 질문에 **왜 궁금한가 / 먼저 보여줄 구체 사실 / 이해를 바꾸는 답 / 그 답 때문에 생기는 다음 질문**을 쓴다. ‘달 설명→별 설명→은하 설명’처럼 대상 이름만 바뀌는 목차로 대신하지 않는다. 최종 낭독문에 실제 답과 이어질 이유가 있는지 대조한다. 표에서만 연결되고 원고에서는 끊기면 수정한다.

### P0-15. 클릭한 이유에 필요한 내용만 남긴다

기획 방향·제목·썸네일·도입이 약속하는 **핵심 질문과 이 편에서 줄 답**을 각각 한 문장으로 적는다. 관련 분야나 같은 대상이라는 이유로 포함하지 않는다. 소제목 수를 줄여도 내부에서 배우는 개념과 갈래가 그대로면 범위를 줄인 것이 아니다.

2026-09-14 반복 실패 보완: ‘핵심에 필요하다’, ‘쉽게 설명했다’, ‘같은 가스 이야기다’ 같은 작업자의 선언은 포함 근거가 아니다. **설명을 쉽게 만들기 전에 그 설명 자체가 필요한지 먼저 검사한다.**

집필 전 구성표에 다음을 기록하고, 파트 집필 뒤 실제 문단 기준으로 다시 대조한다. 표는 해당 편 작업 기록에 두며 별도 공용 지침으로 복제하지 않는다.

| 내용 단위 | 쓰기 직전 시청자가 아는 것·남은 궁금증 | 여기서 새로 이해할 관계 | 핵심 답에 필요한 실제 이유 | 삭제해 읽었을 때 생기는 구체적 이해 공백 | 유지·축약·제외 |
|---|---|---|---|---|---|
| 실제 장면·설명·비유를 적는다 | ‘블랙홀이 궁금하다’ 같은 범주 대신 직전 내용에서 생긴 의문을 적는다 | 새 명칭만 추가한 것은 새 이해가 아니다 | 원고의 어느 후속 문장이 이 설명에 의존하는지 대조한다 | ‘이해가 어려워진다’ 대신 어떤 인과·대상·조건이 빠지는지 적는다 | 내용의 필요성과 위치를 함께 판정한다 |

판정은 다음 순서로 한다.

1. **삭제해 연결해서 읽기:** 이 설명을 빼도 핵심 답을 이해하고 다음으로 자연스럽게 갈 수 있으면 제외하거나 제작 참고로 옮긴다. 핵심의 의미·감정에 필요한 장면은 무엇이 달라지는지 실제 구절로 설명한다. 기능 없는 압축을 강제하지 않는다.
2. **의존 관계 거꾸로 확인:** 뒤 문단이 필요로 해도 그 뒤 문단 자체가 곁가지라면 둘 다 보류한다. ‘뒤에서 다시 썼다’, ‘용어를 이미 넣었다’는 이유로 살리지 않는다.
3. **등장 시점 확인:** 설명을 시작할 때 시청자가 왜 듣는지 앞 맥락에서 알 수 있어야 한다. 필요성이 뒤늦게만 드러나면 핵심 상황을 먼저 보여주거나 설명을 필요한 자리로 옮긴다. 매번 ‘이걸 설명하는 이유는’이라는 안내 문장을 붙이라는 뜻이 아니다.
4. **선행 지식 비용 확인:** 답 하나를 이해하려고 다른 대상·용어·원리를 계속 배워야 하면 익숙한 상황으로 다시 풀거나 곁가지를 덜어낸다. ‘초보자니까 기초부터 전부’는 금지한다. 최소 선행 설명과 충분한 핵심 설명을 구별한다.

## P10. 주제는 고정이다

확정된 주제는 사장님이 "주제를 바꾸자"고 명시하기 전까지 바꾸지 않는다.
기획 중 코멘트는 대부분 **"그 부분을 보완하라"**이지 "주제를 바꿔라"가 아니다.
**판정: 제목·썸네일의 주어가 바뀌었는가.** 바뀌었으면 되돌린다.

## P11. 주제가 약해도 탈락 통보로 끝내지 않는다 — 살리는 각도 3개

사장님은 그 주제를 하고 싶어서 가져온 것이다. 각도마다:
① 그대로 제목이 될 새 앵글 한 문장 ② 추천 원고 유형 ③ 재채점
⭐ **같은 계열 주제를 두 번 이상 가져오면 애착 신호다.** 거부를 반복하지 말고 **되는 각도를 찾아내는 게 일이다.**

각도를 찾는 방법 셋 — **반대편 명제**(그 사람도 그렇게 하지 못한 순간) / **다른 사람의 시점** / **한 줄로 지나간 것을 통째로**

2026-09-17 사용자 보완: 사용자가 검증된 이력·횟수를 강한 후킹 표현으로 제시하면, 문자 그대로의 사실과 다르다는 지적에서 멈추지 않는다. 그 표현으로 전달하려던 인물의 무게·의외성·궁금증을 먼저 파악하고, 비슷한 후킹 강도를 지니면서 본문으로 뒷받침할 수 있는 보완 표현과 다른 기획 방향을 제시한다. 작업자가 추천안과 구체적 전개를 함께 낸다. 비유적 압축과 새로운 사건·횟수의 주장은 구별하며, 사실 확인을 이유로 평범한 이력 소개로만 약화하지 않는다.

## P12. 이미 다룬 대상을 다시 다룰 때 — 다섯이 전부 달라야 한다

| | 확인 |
|---|---|
| 대표 명제 | 반복하지 않는다. **반대편이면 가장 좋다** |
| 콜드오픈 | 그 편이 연 장면으로 열지 않는다 |
| 서사 결 | 다른 결에 얹는다 |
| 감정선 | 후반 전환의 **도착점**이 달라야 한다 |
| **제목·썸네일 문구** | ⛔ 겹치면 **두 영상이 서로를 잡아먹는다** |

- 앞 편이 길게 다룬 국면은 **한두 문장으로 건너고**, 안 쓴 국면에 자수를 몰아준다
- ⛔ **사실은 독립 리서치로만 채운다.** 앞 원고에서 날짜·인용문을 옮기면 그 순간 표절이다
- **판정**: 두 제목을 나란히 놓고 **"다른 이야기로 보이는가."**

## P13. 기획 언어 ↔ 대본 언어 대조표를 기획 문서 맨 위에 만든다

분석하며 만든 말(「문을 좁히다」·「제3의 상태」 같은 것)은 기획서에서는 유용한데 **대본에서는 시청자가 안 쓰는 말**이다.
집필자가 기획 언어를 도로 끌어오지 못하게 막는 **유일한 장치**다.

## P14. 장면을 지어내지 않는다. 시청자의 자기의심은 추측하지 말고 실측한다

- 훅에 쓸 장면은 **댓글·확보된 사실에 있는 것만.** 실제로 창작한 적이 있는데, 정작 댓글에 **진짜 장면이 있었다**
- 자기의심을 「게을러졌다」로 썼는데 실측은 「내가 사회성이 부족해서」였다. **남이 하는 반박과 본인의 자기의심은 다른 층위다** — 섞으면 시청자가 자기 얘기로 안 듣는다
- **2026-09-19 사용자 지적(한입교양 유럽음식짠맛 도입):** “이거 진짜 대부분 겪는 경험이 맞아? ‘로마에 작은 식당’이라고 하는 건 너무 구체적이고” / “이렇게 진짜 다 짠 게 보통인 거 맞아? 이거 댓글에 나와 있던 거 보고 너 하는 거 맞지?”
  - 시청자 경험 장면은 **많은 사람이 겪는 일반 상황**으로 쓴다. 근거 없이 특정 장소·가게(‘로마의 작은 식당’)를 박아 넣지 않는다.
  - 경험의 범위는 확보한 댓글·기록이 보여 주는 만큼만 쓴다. ‘꼭 나온다·대부분·다’ 같은 일반화, 근거 없는 대상 추가(댓글엔 파스타만 있는데 피자·식전빵을 덧붙임)를 하지 않는다. 쓰기 전에 장면마다 근거 댓글·기록을 편 문서에 연결한다.

## P16. 대조표 — 기획안보다 먼저 만든다

> **왜 생겼나**: 분석지가 눈앞에 있는데도 대조를 하지 않아 격차 3연의 순서를 놓쳤다.
> 정보가 없어서가 아니라 **한 번도 안 봤기 때문**이었다.

**이 표 없이 기획안을 내지 않는다.** 기획안 맨 뒤에 붙여서 낸다.

| 왼쪽 | 오른쪽 |
|---|---|
| 고른 벤치마크 분석지가 시킨 것 (뼈대 칸별 "새 주제에서 넣을 것" · 훅 뼈대 5칸 · 도입부 검사 · 빌려 쓸 문형) | **이번 편에 실제로 넣은 문장** |

### 대조표 맨 위에 반드시 오는 네 줄

> **왜 생겼나**: 이 네 줄이 빠져서, 제목은 *"죽었는데 왜 9억 명이 쓰나"*를 물었는데
> 도입부는 *"왜 갈라졌나"*로 시작하는 걸 못 잡았다. **다른 질문을 열었다.**

```
클릭 이유 (제목을 본 사람이 궁금한 것) : ___
  ├ 제목이 던진 질문             : ___
  ├ 썸네일이 그걸 어떻게 키우나    : ___   ← 다른 질문이면 썸네일을 고친다
  └ 도입부 첫 문장이 그걸 어떻게 받나 : ___   ← 다른 질문이면 도입부를 고친다
```

- ⛔ 오른쪽에 **"○"만 적으면 미완성**이다. **실제 문장**을 적는다. 그래야 손으로 때운 것이 보인다
- 판정 열에는 근거를 적는다 — "커짐 ○"이 아니라 "①단어 ②문법 ③소통 불가 — 커짐 ○"
- **집필 중에도 챕터를 잠글 때마다 해당 칸을 다시 본다.** 조립 후 전체를 한 번 더 대조한다
- 사장님은 **대조표가 없거나 빈칸이 있으면 읽지 말고 반려**한다

사용자: “내가 예전에 골랐던 기록을 보는 것까지만 해도 훨씬 더 내 마음에 드는 결과가 나왔거든 … 베스트는 그때 골랐던 것들 보면서 그거에 맞춰서 추천하는 게 베스트야.” / “각 채널별로 … 내가 마음에 드는 거를 쌓아나가잖아. 그걸 보면서 내가 어떤 걸 좋아하는지 그거를 다 기록을 했다가, 그거에 맞는 제안을 해주는 거거든.”

## T1. 팩트 한 문장에서 다섯이 갈라진다

```
팩트 한 문장 (P3)
  ├ 제목        = 팩트에서 시청자의 관심·궁금증·곤란을 지목하는 부분
  ├ 썸네일 문구  = 팩트에서 감정이 가장 센 부분
  ├ 첫 문장      = 팩트가 시작되는 장면
  ├ 진입 선언    = 팩트가 답할 질문
  └ 본문 구조    = 제목의 명사가 시킨 것 (T11)
```

- 제목을 정하고 **그 문장에서** 썸네일을 뽑는다. 따로 만들면 **두 개의 주장**이 된다
- 관계는 셋뿐 — **일치**(같은 문장) / **확장**(뒤를 잇는다) / **반전**(뒤집는다). 어느 것도 아니면 다시 만든다
- **판정**: 둘을 나란히 읽고 **"다른 말 아니냐"**는 생각이 들면 실패다. 사장님이 그 질문을 했다면 시청자는 이미 그렇게 읽었다는 뜻이다
- **하나를 고치면 나머지 넷을 반드시 다시 확인한다**

## T2. 정합 판정 5단계 — 확정 직전에 반드시 돌린다

> *"화이트 부분이 거기가 갈림길이고 핵심이니까"*

1. **썸네일만 보고** 기대되는 것을 한 문장으로 써본다
2. **제목만 보고** 기대되는 것을 한 문장으로 써본다
3. **두 문장이 같은 것을 기대하는가?**
4. **그 기대가 확정 기획 방향과 같은가?**
5. 하나를 수정하면 **나머지 둘을 다시 확인한다**

⚠️ **"같은 곳"이지 "같은 문장"이 아니다.** 이어지되 겹치지 않는다 — 같은 정보의 반복은 금지.

### H2-1. 확정 방향과 후보의 표현 차이를 분리해 검사한다 — 2026-09-14 재발 정정

기존 H2의 전 후보 기획 적합성 규칙이 있었으나, 무서운 블랙홀 편에서 작업자가 ‘1번이 사용자 의도에 가장 가까움’이라고 평가하며 다른 후보를 제출했다. 기존 규칙의 실행 실패이며 기준 부재로 설명하지 않는다.

3. 후보 이름과 작업자의 해설을 가리고 **각 도입 전문만 읽어**, 실제로 어떤 영상을 예고하는지 한 문장으로 역요약한다. 확정 방향과 대조하고, 서로 다른 질문으로 읽히면 그 후보를 먼저 다시 쓴다. 뒤 문단에서 주제어를 다시 언급했다는 이유로 통과시키지 않는다.
4. 사용자 요청이 ‘큰 블랙홀이 더 무서울 것이라는 예상에 의외의 사실을 알려주기’라면 세 후보 모두 초반부터 그 예상과 큰/작은 비교를 드러낸다. 생존 체험·탈출·물체 변형 자체를 새로운 주제로 세우지 않는다. 세부 현상은 같은 비교를 납득시키는 재료로만 사용한다.
5. 후보별 **첫 문단 실제 문장 / 역요약 / 확정 방향 일치 근거 / 벤치마크 실제 구간과 변형 / 초보자에게 미리 요구한 지식 / 반복·결론 선공개·진입 검사 / 수정 결과**를 기록한다. 해설 없이는 읽히지 않는 적합성을 주장하지 않는다.

## H4. 클릭한 기대를 확인시키고 실제로 키우는 도입

사용자 보완(2026-09-13): 제목·썸네일을 클릭한 사람의 숨은 기대·욕구·니즈·궁금증을 충족하고, 해당 내용이라는 확신과 다음을 볼 기대를 증폭해야 한다.

- 먼저 **어떤 경험·답을 기대해서 클릭하는가**를 쓴다. 단순히 ‘우주가 궁금하다’가 아니라 ‘큰 숫자를 외우지 않고 규모를 체감하고 싶다’처럼 그 포장이 만든 기대를 특정한다. 댓글 관찰과 기획자의 추론을 구분하며 속마음을 확인된 사실처럼 단정하지 않는다.
- **관련성 확인**과 **기대 증폭**을 따로 판정한다. 관련 소재가 등장했다는 이유만으로 도입 통과로 쓰지 않는다.
- 도입 안에서 기대한 가치의 일부를 실제 문장·비교·장면·증거로 경험하게 한다. ‘쉽게 알려주겠다’ 같은 약속만으로 대신하지 않는다. 동시에 본문에서 더 알아볼 이유가 남아야 한다.
- 실제 대조표에 **클릭 기대 / 그 기대를 확인시키는 문장 / 초반에 얻는 이해·놀라움 / 다음 궁금증을 키우는 문장 / 본문에서 지급하는 위치**를 적는다. 각 기능이 여러 문장에 걸릴 수 있으며 고정 문장 수·3단 형식을 강제하지 않는다.
- 초반의 강한 결과도 처음 듣는 사람이 즉시 이해할 수 있게 쓴다. 대상·행동·조건을 먼저 또는 같은 문장에서 밝히고,놀라운 결과의 이유를 알아들을 만큼 풀어 다음 궁금증으로 잇는다. 사용자가 긍정한 실제 표현은 해당 채널의 사례로 기록하며 모든 채널의 고정 오프닝 형식으로 일반화하지 않는다.
- 질문이 앞의 사실에서 자연스럽게 생기는지 확인한다. 답이 뻔한 질문, 이미 답한 것을 모르는 척하는 질문, 내용과 상관없는 센 사실로 관심을 끄는 도입은 고친다.
- 도입에서 비교 결과를 보여줬다면 본문은 같은 결과를 되풀이하지 않고 새로운 관계·의미를 설명한다. 도입 변경 시 본문 중복과 끝의 회수도 다시 검토한다.

### H4-1. 포장의 표현에서 출발해 초반 시청 이유를 강화한다 — 2026-09-14

- 제목·썸네일의 **특정 단어·표현 → 자극한 심리·기대 → 첫 문장에서 붙잡는 지점 → 초반에 보여주는 공감·유인·사례 → 본문을 봐야 얻는 답**을 연결한다. 제목의 단어를 대사에서 반복하는 것만으로 기대 증폭을 대신하지 않는다.
- 공감은 구체적인 선택 고민·상황, 유인은 확인할 가치가 있는 차이·결과, 사례는 근거가 있는 장면·경험으로 구현한다. 주제에 맞는 장치를 선택·결합하며 ‘공감→유인→사례’의 고정 순서나 세 요소 전부 넣기를 강제하지 않는다.
- ‘오늘 소개합니다’, ‘끝까지 봐주세요’ 같은 선언만으로 시청 이유를 충족하지 않는다. 초반에 작은 발견·대비·도움을 실제로 주면서, 이어서 확인할 메뉴·선택 기준·이유·결과를 궁금하게 한다. 본문이 그 기대를 실제로 충족하는 위치를 기록한다.
- 초반 이탈 가능성을 줄이는 것을 필수 설계 목표로 삼는다. 뻔한 첫 문장, 늦은 핵심 진입, 중복 안내, 포장과 다른 질문을 먼저 수정한다. 글자 수나 감탄 횟수로 통과시키지 않는다. 실제 이탈 감소·벤치마크 대비 성과 우위는 업로드 후 유지율 등 관측이 있어야 검증 완료로 표시한다.

전:‘빛이 달라진 걸까요?’로 설명을 끼움 → 후:같은 빛인데 가까운 별까지도 긴 시간이 걸린다는 사실을 익숙한 거리 비교로 체감시킨 뒤, 별들이 모인 더 큰 대상에 대한 궁금증을 남김. 이는 이 편의 수정 사례이며 모든 채널에 거리 비교형을 강제하지 않는다.

### H4-2. 초보자의 사전 지식과 답 공개 범위를 실제 문장으로 확인한다 — 2026-09-14

- 쉬운 단어와 쉬운 이해는 다르다. 도입의 각 문장 옆에 이해에 필요한 사전 지식을 적고, 현재 채널의 초보 시청자가 알 것으로 가정할 근거가 없으면 먼저 풀거나 그 문장을 바꾼다. 뒤에 설명이 있다는 이유로 첫 문장의 이해 실패를 통과시키지 않는다.
- 비유의 실제 대상을 먼저 또는 같은 문장에서 밝힌다. ‘먹이’처럼 익숙한 단어여도 무엇을 가리키는지 모르면 쉬운 설명이 아니다. ‘어리다·거대하다·빠르다’는 비교 대상·시간의 기준·크기의 뜻이 있어야 성립한다. 수치만 늘리지 말고 그 기준이 왜 질문을 만드는지 보여준다.
- 클릭 기대를 구체적으로 적고, 도입 초반에서 그 기대와 직접 관련된 상황을 먼저 이해시키는지 본다. 문제를 느끼기도 전에 해결 원리를 길게 가르치는 도입은 순서를 재설계한다. 배경 지식 설명을 모두 도입에 몰아넣는 것으로 해결하지 않는다.
- 벤치마크는 도입 원문·분석·본문 전개를 구분해 적용 근거를 적는다. 본문 구조를 도입으로 옮겼으면 그렇게 표시하며, 도입 구조를 그대로 적용했다고 보고하지 않는다. 분석지에 지적된 난이도·약한 훅·과도한 결론 공개도 후보 선정과 수정에 반영한다.
- 결론 선공개를 일괄 금지하지 않는다. 제목이 결과의 근거나 의미를 약속하면 결과를 먼저 줄 수 있다. 원인·비결을 찾는 기획에서는 핵심 원인 후보를 처음부터 알려주는 것이 남은 궁금증을 줄이는지 확인한다. ‘~일지도 모른다’라는 유보 표현도 원인 후보의 공개다. 각 안의 공개한 내용 / 남겨둔 질문 / 그 질문을 계속 볼 이유를 대조한다.
- 2026-09-19 사용자 지적(한입교양): 도입에서 질문을 던진 뒤 곧바로 ‘흔한 답 두 가지 → 둘 다 답이 아니다 → 실마리는 ○○ 쪽’까지 말하면, 본문 답을 이미 알려 준 느낌이 난다(“그 두 가지에 대한 대답이 좀 이미 도입부에서 알려주는 것 같은 느낌”). 도입은 질문과 그 질문이 왜 이상한지까지 세우고, 흔한 답의 판정·답의 방향은 본문에서 처음 준다. 진입 문장은 판정 없이 본문 첫 과정을 가리킨다.
- ASK의 3안은 모두 초보자의 이해 기준을 충족해야 한다. 이해 불가한 안을 ‘추리형’, 답을 과하게 공개한 안을 ‘발견형’이라는 이름으로 정당화하지 않는다. 사용자에게 이해 실패 피드백이 오면 기존 추천·통과 판단을 철회하고 해당 결과를 재검토 상태로 기록한다.

#### H4-2 보완 — 초보자 이해 실패의 원인과 제출 전 교정 (2026-09-14)

도입·본문 모두 적용한다. 대상 독자의 지식 수준은 채널 설정을 따른다. 아래는 금지 단어 목록이 아니라 **문맥에서 제거할 실패 유형**이다. 단어만 바꾸고 같은 이해 공백을 남기면 수정한 것이 아니다. 실제 반려 구절·사유는 채널의 수정·선택 사례에 보관한다.

| 실패 유형 | 시청자가 막히는 이유 | 작성·교정 방법 | 제출 전 대조 |
|---|---|---|---|
| 대상·행동 생략 | ‘물체가 버틴다’만으로는 무엇이 무엇 때문에 어떻게 되는지 모름 | 실제 대상과 변화·작용을 필요한 자리에서 밝힘. 가정이면 가정임을 표시 | 낭독문에서 대상·행동·결과를 직접 지목할 수 있는가 |
| 비교 위치·조건 생략 | ‘큰 쪽에서는 멀쩡하다’만으로는 언제·어디서·무엇과 비교하는지 모름 | 같은 것과 달라지는 조건을 문장 안에서 설명. 정확성 조건을 본문 뒤나 제작 메모에만 숨기지 않음 | 비교의 뜻을 알기 위해 글에 없는 조건을 보충해야 하는가 |
| 추상적인 재진술 | ‘예상과 실제가 갈라집니다’, ‘이 차이를 가리킵니다’는 앞 주장을 평가할 뿐 새 이해를 주지 못함 | 삭제해 앞뒤를 읽고 의미 손실이 없으면 제거. 필요하면 실제 결과나 다음 인과로 전진 | 이 문장을 빼면 구체적으로 무엇을 이해할 수 없게 되는가 |
| 예고로 설명을 대체 | ‘이 차이를 이해하려면…’이 반복되어 설명은 늦고 알아들은 내용은 늘지 않음 | 다음에 설명하겠다는 안내보다 필요한 설명을 시작. 한 번의 자연스러운 진입까지 기계적으로 금지하지 않음 | 예고 뒤에 새 사실·관계가 실제로 나오는가, 또 예고만 하는가 |
| 원인을 감추다 상황까지 감춤 | 시청자는 왜인지 궁금하기 전에 무슨 말인지부터 모름 | 지금 벌어진 일과 그 뜻은 이해시키고, 본문이 답할 원인을 구별해 남김 | ‘알게 된 상황’과 ‘남은 이유’를 실제 문장 근거로 따로 적을 수 있는가 |
| 쉬운 단어만으로 통과 | 용어가 없어도 생략된 지식·비유 해석·숫자 변환 때문에 어려움 | 선행 지식 없이 듣는 순서로 확인. 비유를 이해하려고 새 설명이 필요하면 직접적인 표현을 검토 | 전문용어 개수 대신 문장 사이에서 시청자가 알아서 추론해야 하는 내용을 확인했는가 |

**실행 순서:** 채널 지식 수준·최신 반려 사례 확인 → 현재 제출할 낭독문 저장 → 화면·기획 해설 없이 연속 읽기 → 위 유형을 실제 구절과 대조 → 문제 구간 수정 → 수정본 재열람 → 해당 편 기존 검토 문서에 근거 기록. ASK의 세 후보는 각각 검사하며 대표 후보 하나의 통과를 나머지에 복사하지 않는다. 도입 한 안의 예시를 고쳤다면 그 범위만 완료로 표시한다.

기록에는 **실제 구절 / 시청자가 앞에서 알게 된 것 / 생략된 대상·조건·관계 또는 중복 / 수정·삭제·유지 이유 / 수정 후 구절과 연결**을 남긴다. 문제 없는 항목도 그 판단에 필요한 실제 구절을 짚되 검사 기록을 채우려고 대사를 늘리지는 않는다. 질문·해설을 시청자가 대신 보충해야 하거나 근거가 없으면 완료·추천으로 제출하지 않고 작성자가 먼저 보완한다. 사용자 선택 대기와 작업자가 해결할 이해 공백을 혼동하지 않는다.

같은 작성자의 재검토를 실제 중학생·초보자 이해 검증으로 표시하지 않는다. 사용자 이해 실패가 확인되면 기존 이해 가능 판단을 철회한다. 기준 저장과 실행 증거를 구별하며 G5-2에서 마지막 수정본 기준으로 확인한다.

## H5. 쓴 뒤 「모르는 사람」 눈으로 문장마다 셋을 던진다

| 질문 | 걸리면 |
|---|---|
| **"그래서 뭐?"** | 다음 문장이 안 받아준다 → 오픈루프가 닫혀 있다 |
| **"이게 무슨 말이야?"** | 앞에서 준 정보로 이해가 안 된다 → 앞에 정보를 깔아라 (S2) |
| **"이거 모순 아니야?"** | 시청자 상식과 부딪히는데 설명이 없다 → H12·H13 |

⚠️ **이 셋은 사장님이 실제로 원고를 반려할 때 쓰는 말이다.** 듣기 전에 스스로 던진다.

## H6. 훅의 사실은 하나의 질문으로 수렴해야 한다

> *"그 전의 내용들이 하나도 쓸모가 없는 상태야. 이어지는 게 하나도 없어"*

- 훅에 넣는 사실은 그 질문을 세우는 데 **필요한 최소한**만
- ⛔ **사실이 두 방향 이상으로 갈리면 실패다.** 나열이 되고 질문이 안 선다
- **판정**: 사실을 하나씩 빼봐라. **빼도 질문이 서면 안 넣어도 될 사실이다**
- ⚠️ **예외**: 정보형(총정리·가이드·리스트)에는 적용하지 않는다. 그런 편의 시청자는 궁금해서가 아니라 **정보를 얻으려고** 본다

## H7. 결론+수치를 훅에서 다 주지 않는다

전(마야 훅): *"육백만 명이 넘습니다"* → *"별로인데 내가 원하는 퀄리티로 안 나오는데"*
범주까지만 주고 수치는 본편이 지급한다. 단 **그 수치가 반전이나 대비를 만들면 훅에 둔다.** 디테일만 더하는 수치는 본편으로.

## H8. 통념 나열 → 반문형이면 반문이 있어야 한다

나열하고 곧바로 답을 말하지 말고, **시청자에게 묻고 무지를 확인시킨 뒤** 때린다.

## H9. 훅이 챕터의 요약본이면 안 된다 — 훅엔 질문 하나

**판정**: 훅 마지막 문장과 챕터 1 첫 문장을 붙여 읽어라. 사이에 **"그래서"가 안 들어가면 끊긴 것**이다.
⛔ 훅이 본편 후반 챕터의 요약본이 되면 두 가지가 동시에 망가진다 — 훅은 맥락 없는 나열이 되고, 그 챕터는 **이미 들은 얘기**가 된다.

## H10. 도입의 작은 보상과 본문의 새 정보를 구별한다

훅에 사용한 사실이 어느 본문 구간에서도 쓰이는지 표시한다. H4에 따라 클릭한 기대를 확인시키는 짧은 결과·비교는 도입에 둘 수 있다. 다만 본문이 같은 수치와 반응을 그대로 반복하면 본문의 설명을 재설계한다. 도입에 모든 후반 답을 나열하지 않는다. **도입에서 얻은 것 / 본문에서 처음 얻는 것**을 나란히 써 구별한다.

사용자 추가 보완:도입에서 이미 인사→즉시 답장→왕복 지연을 설명했다면 본문에서 대상만 별에서 달로 바꿔 같은 설명을 다시 하지 않는다.문자와통화처럼 예시 매체를 이유 없이 바꾸지 않는다.회수는 같은 설명의 재연이 아니라 새 정보·의미를 붙일 때만 한다.

## H11. 리서치 노트를 훅으로 옮기지 않는다 — 최적화 방향이 정반대다

| | 리서치 노트 | 훅 |
|---|---|---|
| 목적 | 소재를 **이해**시킨다 | **계속 보게** 한다 |
| 최적화 | **정보 최대화** | **궁금증 최대화 = 정보 최소화** |

옮기면 나오는 증상 셋 — ① 조사에서 가장 센 사실이 그대로 훅 1번이 된다 ② 병렬 나열이라 *"그런데 여기서 이상한 일이"* 같은 **억지 접속어**로 잇게 된다 ③ 대상이 명명됐다고 전제해서 **"그들"만 남는다**

**판정**: 훅을 쓸 때 리서치 노트를 **덮어라.** "이 편이 답하는 질문 하나"만 보고 쓴다. 다 쓴 뒤 나란히 놓고 같은 문장이 있으면 훅에서 뺀다.

## H12. 당연한 일을 미스터리라고 말하지 않는다 — 「원래대로라면」을 먼저 세운다

시청자가 **자기 상식으로 설명할 수 있는 현상**을 "아무도 몰랐다"고 하면, 미스터리를 느끼는 게 아니라 **화자를 의심한다.**

```
원래대로라면 이랬어야 한다  →  그런데 안 그랬다  →  그래서 이상하다
```

⚠️ **한 겹으로 부족한 경우가 많다.** 밀폐 실험에서 산소가 줄어든 것을 미스터리로 냈더니 *"사람이 숨쉬면 줄지 않나"*가 바로 나왔다.
막으려면 두 겹이 필요했다 — ① 식물이 다시 만들어 균형이 맞게 설계돼 있었다 ② **산소가 준 만큼 이산화탄소가 늘었어야 하는데 안 늘었다.**

## H13. 아직 없는 것을 있는 것처럼 말하지 않는다

계획·가정·계산 단계인 것을 이미 일어난 일처럼 쓰면 *"그럴 리가 없는데?"*에서 멈춘다.
→ "계산해 봤더니" · "종이 위에서는" · "논문에 따르면"으로 쓴다.

## H14. 사례로 열고 주제로 넘어갈 때 연결의 실질을 한 문장으로 댄다

⛔ *"이건 사실 X 이야기입니다"*는 다리가 아니라 **다리를 놓겠다는 예고**다. 시청자는 *"그게 왜 X랑 관계있지?"*에서 멈춘다.
⭕ 두 개가 **같은 문제**라는 것을 사실로 보인다 — *"6,300년 동안 공기를 자급해야 하는데, 인류가 시도해본 최대치가 2년이었다"*

## H15. 훅에서 사료 이야기를 하지 않는다

*"기록이 남지 않았다"* · *"목격자가 없다"*는 **쓰는 사람에게는 흥미로운데 듣는 사람에게는 아직 아무 의미가 없다.**
- 시청자는 아직 **장면 안에** 있다. 거기서 사료 이야기로 나가면 **이야기 밖으로 밀려난다**
- 그런 문장은 대개 **부정문이 연달아 쌓인다**(~않았다·~없다). 부정문은 자리를 비워 놓기만 하고 **그림을 그려 주지 않는다**
- → 훅의 미결 자리에는 **"모르는 것"이 아니라 "맞지 않는 것"**을 놓는다. 가장 강한 형태는 **인물 자신의 말과 인물 자신의 행동을 나란히** 놓는 것

## H16. 훅에 넣은 요소는 일을 하거나, 회수되거나, 빠진다

전: *"평범한 하루였습니다"* → 후: 삭제 — *"없어도 되는 거… 굳이 자리 차지하지 말라는 뜻이야"*
**판정**: 이 문장을 빼면 뒤가 안 돌아가는가. 돌아가면 뺀다. 남긴다면 **어디서 회수되는지**를 적는다.

## H17. 반전은 바로 뒤집지 않고 한 박자를 넣는다

> *"이게 바로 나오는 것보다, 그 사람이 말한 거잖아. 그러고 나서 사실은, 실제로는 뭐 이런 걸 넣으면서 시체가 아니었습니다라고 해줘야지"*

전: *"바위 사이에 시체가 널려 있다. 시체가 아니었습니다."* → 후: 사이에 **사람들의 반응·확인 과정**을 넣고 뒤집는다

## H18. 카메라 위치를 문장마다 고정한다

> *"그 배에 실려 있다라고 얘기해놓고 갑자기 그게 올라왔다라는 게 무슨 말이야"* — 바다 밑과 배 위를 섞지 않는다

2026-09-14 사용자 보완: 물리적인 카메라 위치뿐 아니라 **기획이 정한 시청자의 시간·장소·행동 단계**를 확인한다. 도입 작성 전에 ‘누가 / 언제 / 어떤 상태에서 / 무엇을 해결하려고 보는가’를 이번 편 문서에 적고, 각 후보의 첫 문장부터 본문 진입까지 대조한다. 예를 들어 ‘여행 출발 전 준비’ 영상에서 ‘뉴욕 공항에 도착해 캐리어를 찾았다’를 시청자의 현재 상황으로 두면 기획 시점이 바뀐다. 나중에 출발 전으로 되돌린다는 설명만으로 통과시키지 않는다. 공항 이동을 다룰 필요가 있으면 ‘출발 전에 숙소까지 갈 경로를 정한다’처럼 현재 준비 단계의 행동으로 설명한다. 회상·미래 장면은 기획에 필요한 역할이 확인될 때 사용하며, 후보의 형식을 다르게 만들기 위한 시점 이동은 허용하지 않는다.

## H19. 대상의 이름은 훅에서 밝히고, 순서는 정체 → 이름 → 기능 → 연대 → 미해결

> *"그거 이름을 여기서 알려줘야지. 알려주고 그 다음에 풀어나가야지"* / *"좀 순서가 이상한 것 같지 않아?"*

**미해결을 던졌으면 왜 그런지 방향은 준다** — *"여기서 왜 만들지 못했는지가 좀 궁금하거든. 그 이유를 조금 더 넣어서 보강해주면"*

## H20. 조연·증인의 이름은 훅에 넣지 않는다

본편이 증명할 때 쓸 물증을 미리 소비한다.
- **판정**: 훅의 고유명사를 지워봐라. **주인공을 지웠을 때만** 문장이 무너져야 한다
- ⭐ **주인공 이름조차 미룰 수 있다.** 훅 내내 "소년"으로만 부르다가 마지막에 이름을 밝히면 **그게 회수의 재료**가 된다

## H21. 상태 서술 나열이 아니라 사건의 흐름으로

> *"도입부가 설명 형식이라서 좀 재미가 없는 거 아니야? 이런 흐름으로 해야지"*

전: *"내려갔습니다. 얼마 안 돼 올라오더니"* → 후(사장님 시안): *"40m 아래로 내려갔습니다. 갑자기 올라오더니 이렇게 말했습니다."*

## H22. 밋밋한 초반 금지

> *"조금 더 극적이게 이어갈 수 있을 것 같은데, 왜 이렇게 초반부가 밋밋한 거야?"*

지시어로 거리를 만들지 말고 **이름을 다시 불러** 극적으로.

## H23. 사실만 놓고 끝내지 말고 의아함을 붙인다

- **기획의 핵심 방향 그대로** — *"그게 120년의 이야기가 메인이야? 아니지 않아?"* **수단이 주제 자리에 오면 안 된다**
- **소재 이름만 넣으면 아무것도 약속하지 않는다** — ⛔ *"지금부터 ○○의 이야기를 시작합니다"*
  **판정**: 진입 선언에서 소재 이름을 지워봐라. 남은 말이 **무엇을 알게 되는지** 말하고 있나
- **문형은 편마다 바꾼다** — (a) 컨셉이 후킹되면 다이렉트 (b) 아니면 러프하게

⚠️ 도입부가 만든 질문과 동행 선언이 약속한 것이 **다르면 동행 선언만 고치지 마라.** 둘 중 하나가 이 편의 축이 아니라는 뜻이다. **하나를 버리고** 앞의 장면과 뒤의 예고를 함께 다시 쓴다.

- 제목·썸네일 때문에 알고 싶었던 답과 본문에서 처음 경험할 구체 과정을 연결한다. 다음 장면이나 따라갈 대상을 제시해 계속 볼 이유를 만든다. 핵심 질문을 다시 묻거나 이미 설명한 내용을 다시 예고하는 것으로 대체하지 않는다(S3).

- 마지막 두 문단과 본문 첫 구간을 붙여 읽어 클릭 기대 → 이미 얻은 이해 → 다음에 보고 싶은 과정이 이어지는지 확인한다. 본문이 아직 없으면 연결은 설계 상태로 기록한다. 특정 편의 ‘가스를 따라간다’는 문장을 모든 편의 고정 형식으로 만들지 않는다.

# B장. 원고 (본문 · 클로징)

## B1. 원고는 사건과 사람으로 굴러야 한다

같은 인과라도 **조건문**으로 쓰면 아무도 없는 글이 되고, **누군가의 결정과 최후**로 쓰면 이야기가 된다.

| ⛔ 조건과 구조로 | ⭕ 사람이 한 결정으로 |
|---|---|
| *"A에 가뭄이 들면 그 나라가 곡물을 사야 합니다. 사려면 다른 나라가 팔아야 하는데…"* | *"황제가 직접 진압에 나섭니다. 지원군을 기다리라는 조언이 있었습니다. 황제는 기다리지 않았습니다. 승리를 나누기 싫었기 때문입니다."* |

**판정**: 챕터마다 **「누가 무엇을 했나」**를 한 줄로 적어라. **주어가 사람이 아니면 그 챕터는 설명이다.**
⚠️ 구조·인과 설명이 나쁜 게 아니다. **그 인과를 누군가의 결정으로 바꿔 말할 수 있는데 안 한 것**이 문제다.

## B2. 챕터는 설명 단위가 아니라 반전 단위다

⛔ 챕터가 *"물 얘기 / 숲 얘기 / 가뭄 얘기"*로 나뉘면 사실은 다 맞는데 **읽는 동안 아무 일도 안 일어난다.**
- 챕터가 끝났을 때 새로 이해한 사실·관계·예상 변화가 있어야 한다. 반전은 그 방법 중 하나이며 챕터마다 하나씩 채우는 할당량이 아니다. 설명형 소재에 가짜 반전을 만들지 않는다.
- 형태 — *"칼을 들었을까요? 아닙니다. 살려 보냅니다. 연금까지 쥐어줬습니다"*
- **판정**: 챕터 제목 옆에 **「여기서 새로 이해하거나 예상이 달라지는 것」**을 적고 실제 문장으로 확인한다. 단순히 새 숫자만 나열한 것과 구별한다.

## B3. 문체 장치가 필요한 이유와 실제 역할을 확인한다

금지 표현이 없다고 재미있는 원고가 되는 것은 아니다. 그러나 견본의 장치를 정해진 수량으로 넣어도 재미가 생기지 않는다.

| 살펴볼 특징 | 필요한 이유 | 실제 판정 |
|---|---|---|
| 질문 | 앞의 사실이 만든 궁금증을 붙잡음 | 앞 문장을 읽으면 그 질문이 생기는가,뒤에서 답하는가 |
| 반응·감정 표현 | 사실의 놀라움과 의미를 짧게 짚음 | 앞에 그 반응을 뒷받침할 대비가 있는가 |
| 인물·행동 | 결정과 결과로 과정을 구체화 | 실제 인물이 필요한 소재인가,이름만 추가하지 않았는가 |
| 인용 | 당사자의 관점이나 말과 결과의 차이를 보여줌 | 확인한 발언이며 이 문맥에 필요한가 |
| 시청자 반문 선취 | 이해를 막을 질문에 답함 | 실제로 생길 의문인가,뻔한 오해를 억지로 만들지 않았는가 |
| 익숙한 비교·좌표 | 생소한 규모·과정을 이미 아는 것으로 이해 | 비교의 대상·조건이 분명하며 새 이해가 생기는가 |

횟수·밀도는 필요한 경우 진단에 쓴다. 하한·목표 비율로 정하지 않는다. 없는 장치가 있어도 무조건 채우지 않고 그 기능이 이번 이야기에서 필요한지 판단한다. 견본의 구절과 이번 원고의 대응 문장을 대조한다.

## B4. 벤치마크 원문을 통째로 읽는다 — 발췌로는 중간이 안 잡힌다

⛔ 실제 사고: 상위작의 **첫 400자와 마지막 1,100자만** 읽고 네 편을 썼다.
훅과 클로징은 규격을 맞췄는데 **중간이 전부 설명**이 됐다. 중간을 한 번도 안 봤기 때문이다.
⚠️ **분석지가 원문을 대신하지 못한다** — 분석지에는 *무엇을 하는지*만 적혀 있고 *어떻게 말하는지*는 안 적혀 있다.

## B5. 한 번에 통째로 쓰지 않는다

아웃라인 → **파트별 집필** → 조립. 한 번에 다 쓰면 **고쳐 쓰는 단계가 통째로 사라지고**, 남는 건 수치 맞추기뿐이다.
**파트를 쓸 때마다 B1·B2와 P0-15를 실제 문단에 적용한다.** 새 설명·비유·용어를 넣었으면 기존 구성표의 통과를 그대로 붙이지 않는다. 핵심에 필요하지 않거나 등장 이유가 아직 성립하지 않으면 그 자리에서 삭제·축약·이동한 뒤 다음 파트로 진행한다.

## B6. 분량 조절은 문장이 아니라 사건 개수로 한다

| ❌ 이렇게 줄이면 안 된다 | ⭕ 이렇게 줄인다 |
|---|---|
| 문장에서 설명·해석을 빼고 짧게 | **사건(국면)을 통째로 뺀다** |
| 두 문장을 한 문장으로 합치기 | 챕터 하나를 통째로 뺀다 |
| 사건을 요약해 한 줄로 | 뺀 자리는 **한 문장으로 건너뛴다** |
| 수식·비유를 덜어내기 | **남긴 사건은 오히려 더 길게** 쓴다 |

**우선순위 — 충돌하면 아래를 포기한다:**
① **맥락과 연결이 끊기지 않는 것 (절대)** ② 문장의 밀도 ③ 목표 분량
→ 사용자가 참고로 지정한 목표 시간은 맥락에 맞춰 조정한다. **명시한 최소·최대 시간은 임의로 넘기거나 면제하지 않는다.** 충돌하면 핵심 답의 범위와 설명 순서를 다시 설계하여 함께 충족한다. 시간만 충족하거나 맥락만 충족한 초안을 완성으로 표시하지 않는다.

사용자 최종 정정(2026-09-13): **모든 대본은 최소 10분 이상이다.** 기존 ‘15분을 억지로 맞추지 않는다’는 요청은 정확히 15분으로 맞출 필요가 없다는 뜻이며, 10분 미만 허용이 아니다. 내용이 자연스럽게 끝났다는 판단으로 최소 분량을 면제하지 않는다. 10분에 못 미치면 같은 핵심 질문의 이해에 필요한 과정·구체 상황·비교를 설계부터 보강한다. 단순 재진술, 불필요한 다른 주제, 느린 낭독이나 긴 무음으로 시간을 채우지 않는다.

제출 전 실제 낭독 본문의 글자 수와 사용한 낭독 속도 가정을 기록한다. 실제 TTS가 없으면 추정이라고 명시하고, 예상 속도 범위의 빠른 쪽에서도 10분 이상이 되도록 원고 분량을 확보한다. 이번 우주 편은 공백 제외 분당 300~400자를 작업용 범위로 사용하고, 400자 기준 10분을 넘기는 여유를 둔다. 이것은 문체 할당량이 아니라 명시한 납품 분량의 검증이다. 음성을 생성한 경우에는 실제 재생 시간을 우선 확인한다. 짧은 예상치를 최종본으로 제출하지 않는다.

## B7. 뺄 수 있는 국면 / 뺄 수 없는 국면

| | 판정 |
|---|---|
| ⭕ **뺄 수 있다** | 없어도 **앞뒤가 그대로 이어진다** — 배경 묘사, 분위기, 곁가지 일화 |
| ⛔ **뺄 수 없다** | **핵심 답에 필요한** 인과·조건·대상을 이해시키는 설명, 또는 그 답의 의미를 바꾸는 회수. 단, 뒤에서 쓰는 소재나 어려운 개념 자체가 P0-15에서 필요한 것으로 확인되어야 한다 |

⚠️ **판정은 「중요한가」가 아니라 「빼면 뒤가 무너지는가」로 한다.** 중요도로 고르면 자기가 공들인 문장을 남기고 연결을 버린다.
⚠️ **뺀 뒤에는 그 자리 앞뒤를 반드시 이어 읽는다.** 뺀 자리는 본인 눈에 안 보인다.
**판정**: 줄인 대목을 소리 내어 읽어라. *"무슨 소리지?"*가 한 번이라도 나오면 잘못 줄인 것이다.

## B8. 분량 초과는 집필이 아니라 설계에서 막는다

아웃라인에서 **사건 개수 × 사건당 자수**가 목표를 넘으면 그때 사건을 뺀다.
다 쓰고 나서 줄이면 **이미 살을 붙인 문장을 깎게 되고, 그게 요약문을 만든다.**

## B9. 한 사건을 오래 붙든다

상위작은 사건 하나에 **장면 + 심리 해석 + 훗날 연결** 셋이 다 붙어 있다. **사실만 있으면 연표다.**
→ 벤치마크에서 한 사건을 어떻게 붙드는지 원문과 함께 확인한다. 글자수는 압축·장황함을 진단할 때만 참고하며 이번 원고의 할당량으로 쓰지 않는다.

## B10. 숫자 틀에 억지로 껴맞추지 않는다

항목이 실제로 3개라서 "세 가지"라고 쓰는 건 괜찮다. 문제는 **번호를 먼저 정하고 내용을 끼워넣는 것**이다.
- **판정**: 항목 하나를 빼봐라. 빼도 논지가 안 무너지면 채우려고 넣은 것이다. 항목들이 **같은 질문에 대한 답**인지도 본다
- 순서를 뒤집어라 — **내용을 먼저 다 쓰고, 자연스럽게 몇 덩어리인지 센다**

## B11. 연도·숫자는 필요한 만큼만, 표기는 아라비아 숫자로 — 배치까지 본다

> *"우리가 무슨 역사 공부하는 것도 아니고 스토리만 좀 알면 되는데, 연도가 너무 많이 나오니까 집중도가 굉장히 떨어지거든"* / *"숫자 읽는 거는 그냥 1862년 12월 이렇게 보여줘"*

- 전: 연도 표기 22건 → 후: 12건. 나머지는 **"그 무렵 · 이듬해 · 백 년이 지나 · 삼십 년 뒤"**
- ⭐ **개수만 맞추지 말고 배치를 본다** — 시간 표기가 **문장 첫머리에 오는 비율**까지 잰다.
  밀도가 상위작과 똑같아도 첫머리 비율이 92%(벤치 43~69%)면 **연표 낭독처럼 읽힌다**
- ⚠️ 한 지표를 고칠 때 **어디로 옮기는지**를 본다. 시간 표기를 줄였더니 대체 표현이 상위작의 4~9배가 된 적이 있다 (→ G6)

## B12. 숫자 벽 금지 — 나열에 판단을 얹는다

> *"그냥 단순히 금액만 나열하는 형태로 하는 건 지루함을 보여줘서 별로야."*

- 수치가 이어지는 구간에서 듣는 사람이 비교 대상을 놓치는지 확인한다. 여러 수치가 한 대비를 이해시키면 유지하고,뜻 없는 숫자 나열이면 원인·비교를 보강하거나 덜어낸다. 연속 문장 수를 맞추기 위해 빈 판단을 끼워 넣지 않는다.
- 나열형 챕터는 **갈리는 축을 먼저 선언**하고 들어간다 — *"여기서 갈리는 건 딱 두 가지예요"*
- 같은 수치를 **두 번째 말할 때는 환산·병기를 생략**한다
- **숫자를 넣기 전에 "그래서 뭐가 유리한가"를 먼저 정한다.** 그게 없으면 그 숫자는 뺄 것이다
- ⚠️ **리서치가 잘 됐을수록 이 사고가 잘 난다** — 조사 노트가 좋으면 옮겨 적기만 해도 문장이 되기 때문이다. **노트는 재료지 문장이 아니다**

## B13. 회수는 질문이 아니라 회수로 — 새 정보를 얹어서

> *"아까 처음 도입부에서 말했던 그거잖아. 이미 얘기를 했는데 이제 와서 또 그렇게 하면 재미가 하나도 없지"*

- 전: *"이 덩어리는 어떻게 사람들 손에 들어왔을까요"*(훅에서 이미 말함) → 후: *"아까 바다에서 시체를 봤다던 그 잠수부. 그 사람이 탄 배로 돌아가겠습니다"*
- **걸 때는 걸 내용을 준다** — 전: *"기억해 두세요. 이 이야기 끝에서 가장 정직한 답으로 돌아옵니다"* → 후: *"누가 만들었는지는 아직 아무도 모릅니다. 후보가 셋 있는데, 그건 마지막에 보겠습니다"*

## B14. 챕터 오프닝 형식을 반복하지 않는다

모든 챕터를 같은 틀로 열면 그 틀이 지배적 신호가 되어 **이야기가 아니라 목록으로 읽힌다.**
- 유형(인용 낙하 / 아이러니 / 전환 서술 / 인물 소개 / 회고 도입 / 시간 표기)을 벤치마크에서 뽑아 두고
- 형식 분포는 단조로움을 찾는 참고다. 절반이라는 비율을 맞추려고 오프닝을 바꾸지 않는다. 같은 형태여도 앞의 질문에 답하며 전진하는지,다른 형태여도 사실상 같은 말인지 확인한다.

## B15. 있어 보이는 멘트는 3초 안에 설명 못 하면 뺀다

## B16. 오정보 정정 화법 — 시청자가 알던 것을 부정하되 무안하지 않게

① 무엇을 틀렸다고 지목하나 — **사람이 아니라 통설을** 지목한다
② 정정한 뒤 **무엇을 남기나** — 부수고 끝내지 않는다
③ 미확정인 것은 **불확실성 자체를 이야기로** 만든다. 빼지 않는다

## B17. TTS 표기

- 이 장르에서 걸리는 **단위·약어·기호·큰 수**를 한글로 푸는 표를 만들어 두고 쓴다
- ⛔ **가운뎃점(·) 금지** — 완성 처리에서 쉼표로 바뀌어 낭독이 깨진다. **나열은 "A, B, 그리고 C"**

## B18. 플랫폼 수익화 기준을 원고 단계에서 지킨다

⚠️ **"우리는 그림을 안 보여주니까 괜찮다"는 틀렸다.** 광고 기준은 **묘사(설명) 자체**를 판정 대상으로 삼는다. 내레이션만으로도 제한된다.

**판정의 열쇠는 「초점」이다 — 사실을 빼는 것이 답이 아니다.**

| | ❌ 초점이 참사에 | ⭕ 초점이 이야기에 |
|---|---|---|
| 신체 훼손 | 무엇을 어떻게 했는지 **열거** | 그런 일이 있었다는 **사실과 그 뒤에 벌어진 일** |
| 처형·살해 | 방법과 과정을 **단계별로** | 누가 죽었고 **아무도 처벌받지 않았다** |
| 고문 | 기구와 방식을 **구체적으로** | 얼마나 견뎠고 **무엇을 인정하지 않았는지** |

→ **같은 사실을 유지하되 카메라를 옮긴다** — 훼손된 몸이 아니라 그것을 사고판 사람들 쪽으로.
⛔ **도입부는 더 엄격하게 본다. 훅에 가장 센 장면을 넣지 않는다** — 훅의 임무는 충격이 아니라 모순을 세우는 것이다.
→ 완성 전 **위반 후보 표현을 전수 검색**한다(G6).

## B-클로징

## B19. 클로징은 요약하는 자리가 아니라 깔때기다

| | 골격 |
|---|---|
| 1 | 마지막 답으로 들어간다. 필요 없는 진입 선언은 생략한다 |
| 2 | 본문에서 확보한 구체 근거·대상으로 마지막 답을 붙잡는다. 물증 개수는 고정하지 않는다. 설명형에서는 이미 이해한 관계의 새 결과로 회수할 수 있다 |
| 3 | 앞에서 얻은 이해를 선명하게 닫는다. 역설·감탄을 의무적으로 넣지 않는다 |
| 4 | **한 점으로 좁혀 닫기** — 사람 하나 · 장면 하나 · 물건 하나 |
| 5 | 내용·채널에 맞는 마무리. CTA는 실제 다음 행동이 필요할 때만,사인오프는 채널 선택에 따라 |

- ⛔ 본편에서 한 말을 **번호 붙여 정리하지 않는다** (*"이유는 세 가지입니다"*)
- 설명·비유·소품을 실제 물증이라고 세지 않는다. 물증이 없는 소재는 개수를 맞추기 위해 소품이나 사건을 만들지 않는다. 마지막에 어떤 사실·관계를 이해하게 됐는지 구체적으로 답한다.
- ⛔ **넓히면서 끝내지 않는다** — *"세상 어딘가에서 누군가…"*는 착지가 아니라 확산이다

## B20. 미해결은 「시청자가 가져갈 것」을 준 다음에 온다

*"알 수 없습니다 · 지금도 모릅니다"*로 끝나면 여운이 아니라 **답답함**이다. 시청자 반응은 *"그래서 결론이 뭔데?"*

| | 무엇을 하나 |
|---|---|
| 먼저 | **그 사람이 평생 말하려 한 것을 한 번 더, 손에 잡히게** 풀어 준다 |
| 그다음 | **그것이 이 사람에게도 어려웠다**는 것을 사실로 보여준다 |
| 마지막 | 그래서 **해냈는지는 알 수 없다**로 닫는다 |

→ **미해결의 대상은 「답」이 아니라 「그가 그것을 해냈는가」다.** 답 자체를 안 주면 미해결이 아니라 **미완성**이다.
**판정**: 클로징을 읽고 *"그래서 나는 무엇을 알게 됐는가"*에 **한 문장으로** 답할 수 있는가. 그 한 문장이 **추상어가 아니어야** 한다.

## B21. 제목이 주장을 했으면 클로징이 그 주장에 답한다

"○○는 방법이 아니다"라는 제목을 달았으면 **그럼 방법이 무엇인지**를 클로징에서 다시 준다.
**본편 어딘가에 있었다는 것으로는 부족하다** — 시청자는 끝에서 손에 쥔 것으로 판단한다.

## B22. 2인칭 호칭으로 훈계·축원하지 않는다

- ❌ 시청자를 부르며 훈계·축원하면 **설교**가 된다 (실측 최하위 편이 이 형태였다 — 상위 7편 0회, 최하위 1편만 6회)
- ⭕ **그가 남긴 것이 지금 어디에 닿아 있는지를 사실로** 보여주면 시청자가 알아서 자기 자리를 찾는다
- "우리"(1인칭 복수)는 성적과 무관했다. **2인칭과 혼동하지 않는다**

## B23. 재진술 반복 금지 — 클로징에서 같은 말을 네 번 하기 쉽다

분량이 차 있으니 검사에 안 걸리고, 문장마다 표현이 달라서 중복으로도 안 보인다.
**판정**: 클로징 **문장마다 「여기서 새로 알게 되는 것」을 한 단어로 적어라. 같은 단어가 두 번 나오면 그 문장을 뺀다.**
⚠️ 훅에서 던진 질문을 클로징에서 **글자까지 그대로** 다시 쓰면 회수가 아니라 복사다.

## B24. 추상 선언 대신 구체 장면으로 바로 간다

- 전: *"이 이야기에는 반전이 하나 더 남아 있습니다. 이번에는 여러분 쪽입니다"* → 후: 삭제하고 *"지금 여러분 손목시계를 한번 보세요"*로 바로
- 전: *"마지막으로 그 배 이야기입니다"* → 후: *"마지막으로 한 사람 이야기입니다. 이 기계를 싣고 가다 가라앉은 그 배에는 사람도 타고 있었습니다"*
- **클로징에는 본문에 나온 것만 쓴다** — **클로징의 명사를 하나씩 짚어 본문 어디에서 나왔는지 대라. 못 대면 뺀다**

## B25. 클로징 분량 비중은 참고값이다 — PASS/FAIL로 쓰지 않는다

「마지막 5% 구간 분량」 같은 지표는 **동어반복이라 아무것도 측정하지 않는다.**
자막 기반 벤치마크는 문단 구분이 없어 문단 기준 지표를 검증할 수도 없다.
→ B19의 회수와 구체적 마지막 답을 판단한다. 박자 수·물증 개수·분량 비중은 합격 기준이 아니다. 필요한 회수를 빼거나 분량을 채우려고 같은 뜻을 되풀이하지 않는다.

# S장. 문체 · 표현 · 문장 · 맥락

> **P·T·H·B 전부에 걸린다.** 기획안을 쓸 때도, 훅을 쓸 때도, 클로징을 쓸 때도 같이 돌아간다.

## S1. 기준은 언제나 「처음 듣는 사람」이다 — 방향은 양쪽이다

> *"해면을 따던이 뭐야? 한국 사람들이 이해하는 데 있어서 어려우면 안 되거든. 이거는 내용 자체에 대한 호기심이 아니라 단어나 표현이 뭔지 모르겠어서 헷갈리는 거니까, 무조건 고쳐야 되거든"*

좋은 긴장은 **"무슨 상태인지는 알겠는데 어떻게 된 건지 모르겠다"**이고, 실패는 **"무슨 말인지 자체를 모르겠다"**다.

| 방향 | 규칙 | 판정 |
|---|---|---|
| **모르는 말** | 쉬운 말 **먼저** → 이름 **나중** | 처음 나오는 명사를 **등장 순서대로** 뽑아, 각각 **그 자리보다 앞에서** 풀렸는지 |
| **아는 말** | 설명하지 말고 **동격으로** 붙인다 | 그 설명 문장을 지워봐라. **안 막히면 뺀다** |

### S1-1. 낯선 명사·용어는 설명 먼저, 단어 나중

> *"노예선은 노예들을 싣고 가는 배를 말하는 건가? 구아노는 바닷새 똥이 굳은 것? …내가 그거 무슨 내용인지, 단어인지 모르겠으면 설명 붙이고 단어 말하라고 했는데 왜 그걸 안 하는 거야"*

| ❌ 이름 먼저 | ⭕ 쉬운 말 먼저 |
|---|---|
| "페루에서 온 노예선이었습니다" | "사람을 붙잡아다 파는 배, 노예선이었습니다" |
| "구아노 광산" | "바닷새 똥이 오래 쌓여 굳은 것을 캐내는 곳입니다. 그걸 구아노라고 하는데" |
| "파피루스는 딱 두 장입니다" | "갈대 줄기를 얇게 저며… 파피루스라고 부릅니다" |

- 이름이 나올 때 시청자는 **이미 그게 뭔지 알아야 한다.** 이름은 **확인이지 학습이 아니다**
- ⚠️ **뒤에 설명이 있으면 통과가 아니다.** 시청자는 용어가 나온 자리에서 이미 멈춘다
- ⚠️ **속성 설명은 정체 설명이 아니다.** "싸고 가볍습니다"는 그게 무엇인지 안 알려준다. **무엇으로 만든 무엇인지**가 먼저다
- 분류 체계·셈 단위(N개의 단계/조건)는 개별 항목을 세기 전에 **"그게 무엇인지" 한 문단으로 먼저** 정의한다. 비유적 용어(선·문·벽)는 **실물이 아니라는 것까지** 밝힌다
- **약어·기기명·기관명은 "무엇을 하는 것인지"를 한 마디로** 붙인다

### S1-2. 반대로, 시청자가 아는 말은 설명하지 않는다

전: *"알파벳입니다. A도 B도 C도 전부 여기서 나왔습니다"* → 후: *"…글자의 조상, 알파벳입니다"*
도입부에서 한 문장은 비싸다. **아는 말은 동격으로** 붙인다.

### S1-3. 지칭 없는 「그들」 금지 — 처음엔 명명한다

> *"그들이라고 하는데 그들이 앞에서 지칭된 바가 없는데"*

### S1-4. 「우리」는 시청자와 실제로 공유하는 것에만 쓴다

> *"'우리는'이 누구야? 우리는 처음 페니키아를 아는 사람들이란 말이야. 우리 시청자들은"*

| 시청자가 | |
|---|---|
| ⭕ 아는 것 | "우리가 아는 ○○를 떠올려 보겠습니다" |
| ⭕ 모르는 것 | "우리는 그 이름조차 모릅니다" — 무지를 함께 인정 |
| ⭕ 잘못 아는 것 | "우리는 …라고 생각합니다. 정반대입니다" — 통념을 세워 무너뜨림 |
| ⛔ 방금 처음 들은 것 | "이 사람들을 우리는 ○○라고 부릅니다" → **"그 사람들은 ○○라고 불렸습니다"** |

⭐ **낯선 이름은 피동으로 준다.** 명명 주체를 비워 두면 **그 빈자리가 나중에 회수 재료**가 된다.
능동으로 "우리가 부른다"고 하면 명명 주체가 '우리'로 못 박혀 그 회수가 죽는다.
**판정**: "우리"를 지우고 시청자 혼자 읽어봐라. 실제로 아는 것이면 성립하고, **처음 듣는 것이면 배제가 된다.**

### S1-4a. 시청자에게 익숙한 위치와 경험을 설명의 출발점으로 삼는다

거리·규모·시간을 설명할 때 먼저 시청자가 어디에 있고 무엇을 보는지 정한다.우주 채널의 기본 위치는 지구에 있는 사람이다.거리 비교는 가능하면 지구→대상으로 통일하고,보낸신호·받은빛·가상여행을이유없이섞지않는다.

관측을 설명할 때는 실제 빛이 대상→관측자로 이동하므로 방향을 사실과 반대로 고치지 않는다.‘이제지구에서달을바라볼때를생각해보죠’처럼 설명 목적이 관측으로 바뀌었음을 먼저 알린다.시청자기준은관측자의위치를유지하라는뜻이지모든빛이지구에서출발한다고우기라는뜻이아니다.다른채널은그주제에서익숙한경험·위치를출발점으로선택한다.

### S1-5. 번역투 연어 금지

> *"이 표현도 조금 어색한 것 같거든? 한국인들이 많이 사용하고 듣기 친숙한 걸로"*

전: *"세상에 글자를 준 사람들입니다"* → 후: *"이 사람들 손에서 나왔습니다"*
특히 **무생물·추상명사가 주고받는 구문**이 영어 직역이라 걸린다.
전(2026-09-19 한입교양): *“‘뽀꼬 살레’를 챙겨 가는 한국 여행자”* → 후: *“외워 가는 / 익혀 가는”* — 말(표현)은 챙기지 않는다. 사용자: “너 진짜 이거 말도 안 되는 표현 쓸래?” 동사와 목적어가 한국어에서 실제로 어울리는지 낭독 전에 확인한다.
**판정**: 소리 내어 읽고 *"한국 사람이 실제로 하는 말인가."* **눈으로는 안 걸리고 귀로만 걸린다.**

### S1-6. 문장의 주어가 정확한가

행위자가 아닌 대상을 주어로 쓰면 시청자가 오해한다. 실제로 무슨 일이 벌어지는지에 맞춰 주어를 잡는다.
(대상은 그대로인데 우리 쪽이 못 보게 된 상황이라면 주어는 "우리")

### S1-7. 자연스러운 한국어와 청취자의 이해 순서를 함께 확인한다

- ‘기준을 확인할 첫 장소’처럼 작업자의 분석·설계 용어로 시청자에게 행동을 시키지 않는다. 무엇을 알고 싶은지와 무엇을 보게 되는지를 실제 대상·행동으로 쓴다.
- 설명 없이 ‘같은 그림에 넣으면’처럼 머릿속 그림 조작을 요구하지 않는다. 숫자·단위·비교 대상을 연달아 바꿔야 이해되는 비유는 쉬운 단어로 썼어도 어렵다. 그림 없이 소리만 듣고 처음의 조건부터 따라갈 수 있는지 확인한다. 비유를 풀기 위해 본래 사실보다 설명이 길어지면 더 직접적인 설명으로 바꾼다.
- ‘빛이 오는 데4.2년’처럼 출발지·도착지·시간과 거리의 관계를 생략하지 않는다. 필요한 자리에서는 ‘그 별에서 출발한 빛이 지구에 도착하려면 약4.2년이 걸립니다’로 쓴다. 시간으로 거리를 표현하는 것이 왜 가능한지 앞에서 설명한 뒤 광년을 명명한다.
- ‘모습에도 시간이 들어 있다’처럼 추상적으로 압축하지 않는다. ‘불빛을 끔→꺼지기 전에 출발한 빛이 아직 이동 중→그 빛이 도착한 뒤 꺼짐을 앎’처럼 원인이 결과로 이어지는 행동으로 설명한다. 가정은 가정이라고 밝혀 실제 사건처럼 쓰지 않는다.
- 한국어에서 자연스럽게 쓰는 주어·서술어 조합인지,지시어가 무엇을 받는지,이 문장을 듣는 순간 필요한 정보를 이미 받았는지 확인한다. 문법적으로 가능하다는 것만으로 통과시키지 않는다.

위 예문은 이번 피드백의 교정 사례다. 모든 편에서 빛·통화·가정 장면을 쓰라는 형식 규칙은 아니다.

## S2. 모호함·추상 표현 절대 금지 — 알맹이가 있는가로 판정한다

> *"추상적이고 모호한 표현은 절대 금지야"* / *"말하는 멘트도 너무 추상적이고 와닿지 않은 말을 그냥 있어 보이는 것처럼 말하는 게 너무 많거든"*

**주 판정: 이 자리에 원래 들어갔어야 할 사실이 무엇이고, 그게 문장 안에 있는가.**

| 형태 | 무엇이 빠졌나 |
|---|---|
| 추상어 — "엄청난 변화" · "놀라운 결과" · "중요한 의미" | 숫자 · 이름 · 크기 · 장면 · 비교 대상 |
| 방향만 가리키는 말 — "반대 방향으로 갔다" | **무엇이** 어떻게 됐는지 |
| 이름 없는 상태 — "이 몸으로" · "그런 자리에서" | 어떤 몸 · 어떤 자리인지 |
| 답 없는 수사의문문 — "무엇을 더 할 수 있었을까요?" | 답이 될 사실 |
| **같은 단어를 뒤집은 대구** | **새로 알게 되는 사실 0개** |
| 해독 과제 — 정보 없이 얹은 비유 | 이해에 필요한 **선행 사실** |

**보조 판정** ① 그 문장을 읽고 **머릿속에 무엇이 보이는지** ② 이 문장을 지우면 **시청자가 못 알게 되는 사실**이 무엇인가

### S2-1. 뒤집은 대구 — 사장님이 「절대 금지」로 못박은 형태
⛔ *"하찮아서 조용한 게 아닙니다. 조용한 방식으로 일했기 때문에 조용히 사라진 겁니다."* — 한 단어가 세 번, 새 사실 0개
**판정**: 반복된 그 단어를 다른 말로 바꿔 써봐라. 못 바꾸면 **그 단어에 기대서 지은 문장**이다.
⚠️ 어휘가 어려워서가 아니라 **쉬운 말만 썼는데 아무것도 안 남아서** 금지다.

### S2-2. 해독시키기 금지 — 「나중에 이해되게 하기」와 정반대다

| | ❌ 해독시키기 | ⭕ 나중에 이해되게 하기 |
|---|---|---|
| 시청자가 | **그 자리에서 멈춰** "이게 무슨 뜻이지?" | 계속 듣다가 **다 듣고 나서** "아, 그게 그거였구나" |
| 원인 | 정보를 안 주고 **표현만 얹었다** | 사실을 **먼저 다 주고** 의미를 얹었다 |
| 결과 | 이탈 | 여운 |

**가르는 것은 하나 — 그 문장을 이해하는 데 필요한 정보를 앞에서 이미 줬는가.**
- 비유·은유는 **사실을 말한 뒤에** 얹는다. 비유만 남기지 않는다
- **인용문에는 해석을 붙인다** — 낯선 이미지를 안 풀면 인용이 통째로 버려진다. 완전히 해설하지 말고 **알아들을 만큼만**
- ⚠️ **"좋은 단어를 모아 놓은 문장"을 경계한다.** 울림 있어 보이는 명사를 나열하면 쓴 사람은 완성된 것 같지만 **듣는 사람에게는 아무 그림도 안 그려진다**

### S2-3. 순서 규칙 — 사실 → 논평
*"이번에 무너진 것은 A가 아니라 B였다"* 같은 정리 문장을 **써 놓고 그다음에** 무슨 일이 있었는지 말하면,
시청자는 **결론을 먼저 듣고 근거를 나중에 듣는다.** 그 사이가 공백이다.

### S2-4. 구제 절차
> *"모호하게 표현할 거면 추가적인 설명을 꼭 덧붙여서. 그게 너무 설명이 길어지지 않고, 이해할 수 있는 정도로"*

전: *"없던 건 기술이 아니라 우리 쪽의 눈이었다"* → 후: *"기계가 없었던 게 아니라, 그걸 알아볼 눈이 우리에게 없었던 것이다"*

⚠️ **추상어는 아직 조사를 덜 했을 때 나온다.** 표현을 고치기 전에 **사실을 더 찾아본다.**
⚠️ **이 결함은 다른 검사가 전부 통과시킨다** — 쓰인 단어가 다 아는 말이라 모호 검사에 안 걸리고, 논평에는 참·거짓이 없어 정확성 검사에 안 걸리고, 대구는 매끄러워서 소리 내어 읽어도 안 멈칫한다. **없는 것은 있는 것을 찾는 검사로만 잡힌다.**

## S3. 중복 금지 — 어휘를 바꿔도 반복이다. 네 층 전부 본다

### 2026-09-14 추가: 같은 질문의 재포장과 전제 되돌리기 금지

- 같은 궁금증을 어휘만 바꿔 다시 묻는 문장은 금지한다. ‘어떻게 커졌을까 → 언제 모았을까 → 빨리 자랐을까’처럼 실제로 같은 답을 요구하면 합치고, 사이의 문장은 새 사실·인과·단서로 진행시킨다. 물음표 개수 제한이 아니라 의미 중복 금지다. 새 정보에서 생긴 별개의 질문은 허용한다.
- 문단별로 이미 알려준 사실 / 아직 남겨둔 질문 / 이번 문단이 새로 더한 내용을 적어 대조한다. 앞 질문을 다시 예고하거나 ‘답을 찾을 단서’라는 말을 다른 표현으로 반복하면 삭제한다. 수정 후 도입 전체를 연속으로 읽어 같은 답을 두 번 요구하는지 확인한다.
- 관측된 결과와 그 결과가 생긴 과정에 대한 가설을 구별한다. 앞에서 확정하지 않은 출생 상태·성장 경로를 이미 사실인 것처럼 말하지 않는다. 앞에서는 작게 시작해 커졌다고 전제하고 뒤에서는 처음부터 컸을 가능성을 처음 꺼내는 등 전제를 되돌리지 않는다. 필요하면 처음부터 관측된 무게만 진술한다.
- ‘하지만’ 뒤에는 앞 문장과 실제로 대비되는 내용이 와야 한다. ‘시간이 충분히 길다 → 조건에 따라 다르다’처럼 설명을 유보하는 문장으로 긴장을 대신하지 않는다. 대비를 이해시키는 구체 원인이 없으면 그 반론 문단을 빼거나 원인을 직접 설명한다.


> *"적당히 필요하니까 말한 거지? 그래도 되는데 중복처럼 느끼게 하면 안 되고"* / *"왜 원고 전반에 걸쳐서 계속하는 거야? 했던 소리 또 계속 금지."*

⚠️ **한 층만 검사하고 통과시키는 것이 이 사고의 정체다.**

| 층 | 무엇 | 판정 |
|---|---|---|
| **문장** | 같은 사실 재진술 | 두 문장을 나란히 놓고 **두 번째에서 새로 들어온 단어에 밑줄.** 밑줄이 없으면 복사 |
| **회수** | 심어둔 것을 꺼냄 | 「여기서 **처음** 알게 되는 것」이 하나라도 있나. 없으면 뺀다 |
| **챕터 경계** | 앞이 던진 질문을 다시 설명 | 앞 챕터가 던진 질문은 **다음 챕터가 답하거나 진행시킨다. 다시 설명하지 않는다** |
| **원고 전체** | 한 메시지를 계속 재증명 | 관련 구절을 나란히 놓고 두 번째 설명에 새로운 관계·이해가 있는지 본다. 단어 횟수는 탐색 신호이며 구간당1회·전체5회 같은 수치로 통과·탈락시키지 않는다 |

### S3-1. 문장 층
전: *"삼천 년 동안 두 장입니다"*(훅과 토씨까지 동일) → 후: *"돌에 새긴 것은 만 개, 종이에 쓴 것은 두 장. 오천 배 차이입니다"*
두 번째에 얹을 것 — **출처 · 과정 · 사람 · 대비 · 그 사이에 쌓인 것**

### S3-2. 원고 전체 층 — 어휘를 바꿔도 반복이다
*"없어졌다 · 사라졌다 · 끝났다 · 정리됐다 · 옛말이다"*는 전부 같은 말이다.
문장 단위로는 하나도 안 겹치는데 **메시지 단위로는 열여섯 번 같은 말**을 하고 있다.
- 한 편에서 **같은 메시지는 한 구간에서만** 한다. 그 구간이 그 메시지의 담당이다
- **두 번째부터는 사실만 서술한다** — "올해 1월에 2달러 90센트에서 올랐어요" → **"편도 3달러예요"**
- 팩트(P3)는 **한 번 세우면 되는 것**이지 챕터마다 재확인할 것이 아니다
- ⭐ **이 편의 「반복 감시어」를 정해서 G2 체크리스트에 넣는다.** 감시어는 편마다 다르다

### S3-3. 분량을 맞추려고 같은 말을 한 번 더 넣지 않는다
전: *"굶어 죽거나 서로 죽인 흔적이 유전자에 안 나타납니다. 굶어 죽은 게 아니다. 서로 죽인 것도 아니다."*
최소 10분 분량과 핵심 답의 충분한 설명을 함께 충족한다. 부족하면 같은 핵심 질문 안의 과정과 상황을 검증된 사실로 깊게 풀어내며, 재진술이나 무관한 주제로 채우지 않는다. B6와 P0-15를 따른다.

### S3-4. 분량이 빈 자리를 새 사실·새 수치로 채우지 않는다
> *"너무 새로운 내용을 너무 많이 넣는 것도 문제 아니야? 분량은 짧은데 다 너무 겉핥기식 될까 봐"*

⛔ 분량은 새 소재가 아니라 **척추를 한 겹 더 파서** 채운다.
새 수치가 이미 나온 수치와 **같은 대상을 두 숫자로 부르지 않는지** 확인한다 (실제 사고: 훅의 "석상 887개"와 본문의 "완성된 석상 1,043개"가 충돌).

## S4. 흐름과 연결 — 「갑자기」 등장 금지

> *"알파벳 말하고 나서 갑자기 왜 이상한 일이라고 하면서 돌에 새긴 비문이 왜 나와? 글의 흐름과 맥락이 없어"*

### S4-1. 튀는 소재는 필요성부터 확인하고, 남긴 소재를 잇는다
전: *"앞에서 본 그 얼굴들"*(빈 섬 이야기 뒤에 바로) → 후: *"그 빈 섬에 석상만 남았습니다"*로 시작
**판정**: 문장·문단 사이에 **"그래서" · "그런데" · "왜냐하면" · "그러니까"**를 넣어봐라. 어느 것도 자연스럽지 않으면 그 이음매가 끊긴 것이다.
→ 접속사를 실제로 넣으라는 뜻이 아니라 **넣을 수 있는 관계인지**를 확인하라는 뜻이다. 단, 이것은 남기기로 한 내용의 국소적인 연결 검사다. P0-15의 필요성 검사를 먼저 통과해야 하며, 접속사가 들어간다는 이유로 곁가지를 유지하지 않는다.

### S4-2. 전환은 다음에 올 것을 그 자리에서 말한다
- ⛔ *"그 고립 속에서 이 사람들이 한 일이 있습니다"* · *"이제 이 섬에서 실제로 벌어진 일을 봐야 합니다"*
- ⭕ *"그 천 년 동안 이 사람들은 돌을 깎았습니다"* · *"그런데 이 섬에서 나무가 사라졌습니다"*

### S4-3. 지시어(「그 ~」)는 받을 말 바로 옆에 — 안 되면 이름을 다시 부른다
- 전: *"2년 뒤, 그 덩어리가 갈라졌습니다"*(지시어가 문단 두 개 건너) → 후: *"그때 건져 온 청동 덩어리 하나가 갈라졌습니다"*
- 전: *"그런데 세상에 알려진 이야기는 이게 아닙니다"* → 후: *"그런데 사람들이 아는 이스터섬 이야기는 따로 있습니다"*
- **숫자 앞에는 원인을 둔다** — 전: *"섬에 남은 사람은 111명이었습니다"* → 후: *"천연두는 섬 전체로 퍼졌고, 사람들이 계속 죽었습니다. 1877년, 섬에 살아 있는 사람은 111명이었습니다"*
- **판정**: "그 ○○"를 찾아, 그 ○○를 준 문장이 **바로 앞 문장**인지 본다. **한 문장만 끼어도 헐거워진다**

### S4-4. 챕터 사이는 문장이 아니라 방향이 이어져야 한다
전: *"지금 당신 손에 있는 것도 여기서 왔습니다"*로 **넓히며** 닫고, 바로 다음 줄에 *"그런데 이 사람들이 남긴 것이 거의 없습니다"*로 **좁힘** — 문장은 각각 멀쩡한데 **방향이 정반대라 튄다.**
**판정**: 챕터 마지막 문단과 다음 챕터 첫 문단의 방향을 비교한다. 반대면 전환 자체가 핵심 답에 필요한지 먼저 확인한다. 필요하지 않으면 확장 구간을 빼고, 필요한 전환만 앞의 상황에서 생긴 이유로 연결한다. 방향을 바꾸는 문장만 붙여 통과시키지 않는다.
- ⛔ **빈 예고로 다리를 대신하지 않는다** — *"그런데 이상한 일이 벌어집니다"*처럼 무엇이 이상한지 안 말하면 다리가 아니라 **지연**이다
- ⭕ 다리는 **앞 문단이 마지막에 쥐여준 것을 그대로 들고** 건너간다

### S4-5. 시간순은 이유가 되지 못한다
"그다음에 일어났으니까 그다음에 말한다"는 **연표의 논리**다. **앞 사건이 뒤 사건을 부르는 관계**를 찾아 쓰거나, 못 찾으면 **그 사건을 뺀다.**

### S4-6. 좋은 문장이라서 넣고 싶은 문단이 흐름을 깬다
아까우면 자리를 옮기고, **자리가 없으면 버린다.**

### S4-7. 챕터 전환은 앞 답이 다음 질문을 부르도록 쓴다

소제목을 전부 지우고,앞 구간의 마지막 두 문단과 다음 구간의 첫 두 문단을 연속으로 읽는다. **직전까지 무엇을 이해했는가 / 그래서 지금 무엇이 궁금해지는가 / 왜 다음 대상이 그 질문의 답인가**를 실제 원고 문장으로 확인한다. ‘다음은 은하입니다’나 ‘더 큰 집합 안에 있습니다’만으로 연결했다고 처리하지 않는다.

앞에서 아는 대상과 새 대상의 관계를 먼저 보여주고 새 명칭을 붙인다. 예:가까운 별 하나 사이도 긴 거리→밤하늘의 다른 별들까지 모이면 얼마나 큰가→태양도 그 거대한 별 무리 안의 하나→우리 은하. 연결 문장이 한 줄 있다는 이유로 통과하지 않고 청취자가 따라갈 이유가 있는지 본다.

‘그런데’나 질문을 모든 경계에 의무적으로 붙이지 않는다. 자연스러운 연결은 원인·크기·위치·시간 등의 관계에서 나온다. 이어질 이유를 만들 수 없는 곁가지라면 브릿지를 덧칠하지 말고 국면을 옮기거나 뺀다.

멀리 있는 별로 관심을 끈 뒤 가까운 달부터 설명할 경우,‘이해가 어렵죠’라고 단정하지 말고 **먼 거리를 익숙한 가까운 거리와 비교하려는 이유**를 이동 전에 밝힌다.한 번에 이해됐다고 사용자가 확인한 사례를 곧바로 이해하기 어렵다고 되돌리지 않는다.진입 선언과 다음 파트가 같은 전환 이유를 두 번 설명하지 않게 한다.

## S5. 이름을 붙인 뒤엔 그 명칭으로

> *"그 덩어리라는 걸 언제까지 덩어리라고 하는 거야? 이름을 지어 줬잖아. 그때부터는 그 명칭으로 불러야지"*

전: 이름을 준 뒤에도 "덩어리" 12회 → 후: **톱니 서른 개짜리 안티키테라 기계**로 부른다.
장면 안 과거 시점(아직 이름을 모르던 때)만 "쇳덩어리".

## S6. 과장 금지 — 사실의 임팩트를 믿어라

> *"조금 과장이지 않아? 이 자체만으로 사실 임팩트가 큰 사건인데"*

전: *"아무도 눈여겨보지 않았습니다"* → 후: *"많은 것 중 하나였습니다"* · *"그것 하나에 집중하진 못했습니다"*

## S7. 말이 되는 문장 — 근거·이유·일관성이 앞에 있어야

> *"너 이게 말이 된다고 생각해?"* / *"이게 무슨 말이야, 도대체? 중간중간 진짜 말도 안 되는 소리 할 거야?"*

1. **이유 없이 던지지 않는다** — 전: *"정교한 톱니 기계는 한참 뒤에 나옵니다"* → 후: *"영화나 그림 속 고대 그리스에서 톱니바퀴를 보신 적 있으신가요. 없을 겁니다. 실제로 한참 뒤에 나오기 때문입니다"*
2. **앞에서 이미 말한 것을 모르는 척하는 문장 금지** — 전: *"그 뒤 사람들은 이게 무엇인지조차 몰랐습니다"*(앞에서 이미 일식 계산 기계라고 말함) → 후: *"방금 말씀드린 것, 이게 무엇이고 무엇을 계산하는지 알아내는 데만 백이십 년이 걸렸습니다"*
3. **근거 없는 물음 금지** — 전: *"우리가 배운 역사가 틀린 걸까요, 이 물건이 잘못된 걸까요"*(앞에서 안 나온 질문)
   > *"이게 왜 이런 생각을 해? 전혀 이런 생각이 나올 구간이 아닌데? …그러게? 라는 생각이 들게끔 해야 되는데"*
   **검사법**: 질문을 지우고 앞 문단만 읽어 그 질문이 **저절로 떠오르는지** 본다. 안 떠오르면 앞에 근거를 깐다
4. **앞 문장과 모순 금지** — 조립 후 **전체를 이어 읽으며** 자기모순을 찾는다. 파트별로만 보면 절대 안 잡힌다
5. **없는 근거를 지어내지 않는다** — 전: *"이 순서를 당신도 외웠습니다"* → 후: 삭제. 아무도 그걸 외운 적 없다

## S8. 압축하지 않는다 — 귀로 듣는 매체다

시청자는 되감지 않는다. **글로 읽으면 멋있게 압축된 문장이, 들으면 "무슨 소리지?"가 된다.**

- **사실만 던지고 넘어가지 않는다. 의미를 그 자리에서 붙인다**
- **시간이 지났다는 이유만으로 다시 설명하지 않는다.** 지칭이 모호하거나 다음 인과를 이해하는 데 필요한 정보가 멀어졌을 때, 필요한 대상·조건만 짧게 되짚는다. 이미 이해한 결론과 비유를 다시 풀어 분량을 늘리지 않는다(S3).
- **생소한 고유명사·기관명은 처음 나올 때 한 줄로 푼다.** 시청자는 검색하지 않는다
- **완곡하게 쓰다가 의아하게 만들지 않는다** — 자극적 표현을 피하는 것과 사실을 흐리는 것은 다르다. **흐릴 거면 차라리 그 사실을 뺀다**

**판정 셋** — 앞에서 실제로 알려준 내용을 포함해 연속으로 읽으며: ① 필요한 대상·개념을 설명 없이 이미 안다고 가정하는가 ② 머릿속에 관계나 상황이 그려지는가 ③ 지시어가 누구·무엇을 받는지 분명한가. 모든 문장을 독립적인 입문 설명으로 만들거나 앞을 안 들은 사람을 위해 정의를 반복하지 않는다. 모르는 용어를 발견하면 먼저 그 용어가 핵심 답에 필요한지 P0-15로 확인한다.

## S9. 문장 하나짜리 정확성 검사 셋

① **동사가 실제 행위와 맞는가** — 뭉뚱그리는 동사를 쓰면 *"어? 그게 맞나?"*에서 한 박자 멈춘다. 그 분야에서 **실제로 쓰는 말**로 고른다
② **앞에서 한 말과 모순되지 않는가** — 요약·전환 문장에서 특히. 앞에서 "이미 다 잃었다"고 해 놓고 뒤에서 "잃을 것이 많았다"고 쓰는 식
③ **의미를 결정하는 단어가 빠지지 않았는가** — **처음 · 마지막 · 유일한 · 다시**는 빠지면 의미가 통째로 달라진다

→ **셋 다 읽으면 안 걸리고 들으면 걸린다.** G4(통독)에서 잡는다.

## S10. 한 장면 안에서 시점이 튀지 않게 한다

도입부에서 A→B→A로 되돌아가면 시청자는 A와 B가 같은 사람인지 모른다.
**유품 발견 → 사건 → 다시 유품**처럼 한 장면에서 시점이 두 번 튀면, **그 둘이 같은 사람의 이야기라는 것이 전달되지 않는다.** 쓴 사람은 알고 있어서 안 보인다.

- **한 장면은 시간순으로 한 번에 통과**시킨다. 되감기·회상은 그 장면이 끝난 뒤
- 새 대상이 등장하면 **앞 대상과의 관계를 그 자리에서** 밝힌다 — *"그날 아침 이륙한 정찰기"* → *"그가 그날 아침 몰고 나간 정찰기"*
- **판정**: 도입부를 소리 내어 읽고 **등장하는 대상이 몇 명인지 세어라.** 의도한 수보다 많으면 연결이 안 된 것이다

## S11. 사실 나열은 재미없다 — 이해와 다음 궁금증이 생기게 쓴다

2026-09-13 보완:쉽고 재미있는 설명은 쉬운 단어만 고르는 것으로 끝나지 않는다. 익숙한 대상에 대입→예상과 사실의 차이→뜻이 이해됨→다음 의문으로 이어지는 기능을 살린다. 모든 문단을 같은 순서로 찍어내라는 뜻은 아니다.

정확성에 필요한 조건은 관련 명사·동사에 자연스럽게 붙인다. ‘~라는 뜻은 아닙니다’ 같은 해명을 반복하지 않는다. 범위·가정이 없으면 실제 오해가 생기는 문장은 유지한다. 화면 제작법·축척 표기·편집 방식은 시청자의 이해에 필요한 부분만 낭독하고 나머지는 제작 메모에 둔다. 어렵지 않은 답을 받기 위해 긴 곁가지 설명을 거치게 하지 않는다.

전:‘이번에는 자동차나 우주선으로 갈아타지 않겠습니다’처럼 제작자의 선택을 설명 → 후:실제 비교를 보여주고 다음 거리의 궁금증으로 이동. 전:그림 표시법을 계속 설명 → 후:보여주려던 대상의 크기와 관계를 설명하고 표시법은 제작 메모로 이동.


> *"그냥 사실을 나열하는 거와 가까운 건 하나도 재미가 없어"*

(구체 규칙은 B12 · B3)

## S12. 매너리즘 방지 — 여섯 자리

> *"항상 이거 모든 원고마다 복사 붙여넣기하듯 똑같으면 안 되거든"* / *"그게 너무 계속 공통되면 어떤 주제든 도입부가 비슷해서 재미도 없고 항상 지루하고 똑같이 느껴질 것 같은데"*

| 자리 | 규칙 |
|---|---|
| **훅 뼈대** | 직전 2편과 다섯 칸 — ① 여는 방식 ② 반전 자리 ③ 이름 공개 위치 ④ 끝맺음 ⑤ 진입 선언 문형 — 를 대조해 사실상 같은 도입을 반복했는지 판단한다. 차이 개수를 맞추기 위한 변경은 하지 않는다 |
| **첫 문장 충격 유형** | 매 편 직전 편들과 **다른 종류** (장면형 / 모순형 / 대사형 / 문서 인용형 / 수치형) |
| **진입 선언 문형** | 편마다 복사 금지 |
| **챕터 오프닝 형식** | 한 대본 안에서 목록처럼 들리는 반복이 있는지 확인한다. 형식 비율은 참고(B14) |
| **착지 유형** | 직전 편들과 다르게. **「개인으로 꺾지 않는 착지」**도 반드시 선택지에 둔다 — 목록이 전부 정서형이면 고를 게 없어 매번 꺾게 된다 |
| **회수 문형** | *"앞에서 걸어 둔 두 질문으로 돌아갑니다"* 같은 상용구 반복 금지 — *"내용상 흐름상 필요하면 그렇게 해야 하는 거야"* |

⚠️ **구조 반복은 시청자가 잘 못 느끼지만 착지 반복은 3편만 봐도 들킨다.**

## S13. 시청자와의 연결은 주제 안에서 한다

2026-09-14 사용자 보완: **지적 호기심도 충분한 시청 이유다.** 시청자가 가진 예상·궁금증을 풀어주는 기획을 실제로 겪을 가능성이 낮은 위기·생존·선택 상황으로 바꾸지 않는다. ‘내가 떨어진다면’ 같은 자기 대입은 이해에 필요할 때 본문의 명시한 가정으로 사용할 수 있으나, 기획의 클릭 이유를 대신하지 않는다. 제목·썸네일·도입 전부에 적용한다. 이번 우주는 큰 블랙홀이 더 무서울 것이라는 예상에 의외의 사실을 알려주는 방향이다.

"그래서 나랑 무슨 상관?"에 답이 있어야 한다. **잃는 것·걸린 것을 구체적으로** 만들어야 감정이 붙는다.
⛔ 단, **앵글이 답하는 질문 바깥으로 나가서까지 개인화하지 않는다.**
- 실제 사고: 경제 편에서 주제와 무관한 개인 부채로 엮으려 했고, 과학 편에서 닿을 데 없는 이론 검증을 *"오늘 밤의 나"*로 꺾었다. **결말에서 제일 자주 터진다**
- **판정 셋** — ① **다른 편에 그대로 붙여도 말이 되는가**(되면 이 주제에서 나온 게 아니다) ② 확정 앵글 한 문장을 옆에 놓고 결말이 그 문장의 답인가 ③ **앵글에 없던 소재가 결말에 처음 등장하는가**
- 닿을 데가 없는 주제는 **그 주제답게 닫는 게 맞다** (지적 착지 · 미해결이 남기는 것 · 태도의 문제)

## S14. 유튜브 정책 준수와 표현 순화 — 사고·사망의 과도한 묘사를 줄인다

2026-09-25 사용자 요청. **모든 채널의 기획·제목·썸네일·도입·본문·설명글·화면 및 음향 지시에 적용한다. 극한실화처럼 사고·조난·부상·사망을 다루는 원고에서는 특히 엄격하게 점검한다.** 아래 표현 기준은 사용자가 정한 공용 편집 기준이며, 모든 자극적인 단어가 유튜브에서 일률적으로 금지된다는 뜻은 아니다.

1. **유튜브 가이드라인에 위배되는 내용·표현을 넣지 않는다.** 위반 소지가 있거나 불필요하게 충격·혐오·공포를 키우는 표현은 제출 전에 삭제하거나 중립적인 언어로 순화한다. 사실·인과관계는 유지하되, 상처·신체 훼손·체액·시신 상태·죽어가는 과정을 눈앞에 재현하듯 세밀하게 묘사하지 않는다.
2. **극한실화의 긴장은 구조 과정에서 만든다.** 사람의 선택, 구조 시도, 시간과 지형의 제약으로 이야기를 끌고 간다. 고통의 강도·비명·신체 변화·최후의 순간을 반복하거나 확대해 긴장을 만들지 않는다. 피해자·유족을 조롱하거나 죽음을 오락적 구경거리로 만드는 표현도 제거한다.
3. **사실적으로 설명할 대상과 생략할 묘사를 구별한다.** 통로의 모양, 장비가 움직일 공간, 구조가 막힌 이유는 이해에 필요한 만큼 정확히 설명한다. 신체 상태는 사건 이해에 꼭 필요한 범위만 간결하게 쓴다. 사망 사실을 숨기거나 다른 결과로 바꾸지는 않는다. ‘사망했다’, ‘구조하지 못했다’ 같은 중립적인 사실 전달까지 금칙어처럼 처리하지 않는다.
4. **순화는 단어 치환으로 끝내지 않는다.** 신체 손상의 자세한 묘사는 ‘심각한 부상을 입었다’, 임종 과정의 불필요한 감각 묘사는 ‘상태가 악화됐고 끝내 구조되지 못했다’처럼 필요한 사실만 남긴다. 이는 형식 예시이며 실제 기록이 뒷받침할 때만 쓴다. 특정 단어를 별표·은어로 가려도 장면 전체가 자극적이면 해당 장면을 줄이거나 바꾼다.
5. **낭독문과 화면·소리를 함께 검토한다.** 제목·썸네일의 자극적인 문구, 상처나 시신을 강조한 확대 화면, 비명·신체 손상 효과음, 고통을 반복 재현하는 연출을 넣지 않는다. AI 이미지·재연도 같은 기준을 적용한다. 필요한 설명은 도식·지도·장비의 움직임으로 대체하고 재현물을 실제 사고 기록으로 오인시키지 않는다.
6. **커뮤니티 가이드 준수와 광고 적합성을 따로 확인한다.** 게시가 허용되더라도 연령 제한이나 광고 제한이 생길 수 있다. 다큐멘터리라는 명칭·경고문·모자이크만으로 허용이나 수익화를 보장하지 않는다. 사건을 다루는 이유와 설명 맥락이 실제 낭독문·화면 안에서 드러나야 한다.
7. **민감한 표현의 판단이 필요하면 최신 공식 정책을 확인한다.** 확인 출발점은 [폭력적이거나 노골적인 콘텐츠 정책](https://support.google.com/youtube/answer/2802008?hl=ko)과 [광고주 친화적인 콘텐츠 가이드라인](https://support.google.com/youtube/answer/6162278?hl=ko)이다(이번 확인: 2026-09-25). 주제에 따라 다른 관련 정책도 확인한다. 작업자의 표현 순화 검토를 유튜브의 승인이나 광고 게재 보장으로 보고하지 않는다.

**제출 전 실행:** 현재 제출할 제목·썸네일·낭독문·화면/음향 지시를 함께 읽기 → 위반 소지와 불필요하게 생생한 묘사 찾기 → 삭제·순화 → 사실 및 앞뒤 맥락 보존 확인 → 수정본 재열람. 해당 편의 기존 검토 기록에 실제 수정 전후 문장과 이유를 남긴다. 수정할 것이 없으면 유지한 실제 구절과 이유를 적는다. 아직 제작되지 않은 영상·음향까지 검수했다고 표시하지 않는다.

# G장. 자가검수 — 사장님에게 보여주기 전에

**스스로 재고 스스로 고친다.** 지켰는지 확인해 달라는 게 아니라 **지켜진 결과물**을 낸다.

## G1. 원칙

- 실제 이해·흐름·정확성 또는 명시 요구에 문제가 있으면 고치고 영향을 받는 부분을 다시 확인한다. 문체 수치가 견본 범위 밖이라는 이유만으로 고치지 않는다(G2·G6).
- **고친 내역을 산출물 뒤에 표로 남긴다.** 조용히 고치면 사장님이 학습할 수 없다
- **고치지 않기로 한 것도 이유와 함께** 적는다 — 판단이 필요한 항목은 사장님이 뒤집을 수 있어야 한다

## G2. 계측 — 진단에 쓰고 원고를 숫자에 맞추지 않는다

실측값을 보고할 때는 반드시 실제 파일로 측정하고 방법·범위를 밝힌다. 본문과 훅의 길이,숫자·질문·반응·반복 어휘·형식 분포는 **어디를 다시 읽을지 찾는 자료**다. 견본과 비슷한 비율을 만들기 위해 문장을 추가·삭제하지 않는다.

| 구분 | 확인 |
|---|---|
| 사용자가 지정한 산출물 | 후보 수·요청한 결과가 실제로 있는지 확인 |
| 목표 러닝타임 | 글자수와 속도 가정으로 예상,실제 음성과 구별. 목표와 차이가 크면 내용과 호흡을 조정하되 문맥 우선 |
| 문체 진단 | 필요할 때 훅·본문을 분리하여 길이·질문·반응·수치·형식 분포를 측정. 반드시 실제 구절과 함께 해석 |
| 중복·연결 | 같은 표현뿐 아니라 같은 설명의 반복을 문단·구간 사이에서 대조 |
| 명확함·정확성 | 용어 등장 순서,지칭,숫자의 범위·단위,비유 조건,제목의 약속을 실제 문장으로 확인 |
| 명시 금지·형식 | 가운뎃점 등 해당 사용자 요구 확인 |

자동자막의 문장 구분 오류를 실제 낭독 특징으로 오인하지 않는다. 측정할 필요가 없는 항목을 전부 채우느라 본문을 뒤틀지 않는다. ‘질문12개’는 질문의 자연스러움이나 재미를 검증했다는 결과가 아니다.

## G3. 문체 특징의 기능을 원문과 실제 대본으로 대조한다

B3에 따라 이번 편에 가져온 특징이 무엇을 하는지 확인한다. **견본 구절 / 특징의 역할 / 이번 대본 구절 / 필요한 이유 / 판단·수정**을 기록한다. 질문이 자연스럽게 생기는가,비교가 실제로 이해를 돕는가,설명을 붙인 뒤 전진하는가를 본다. 인물·감탄·인용이 없다는 이유만으로 추가하지 않는다. 숫자나 체크표만으로 판정을 대신하지 않는다.

## G4. 통독 — 조립한 전체를 소리 내어 읽듯이 한 번

| 멈칫한 이유 | 무엇을 볼까 |
|---|---|
| "무슨 뜻이지?" | S1 · S2 · S8 — 이해할 정보를 앞에서 줬는가 |
| "왜 지금 이 얘기지?" | P0-15로 설명 자체의 필요성과 등장 시점을 먼저 확인하고, 남긴 구간만 S4로 연결 검사. 접속사 추가만으로 해결하지 않는다 |
| "어? 그게 맞나?" | S9 — 동사 · 모순 · 빠진 핵심 단어 |
| "아까 들은 것 같은데" | S3 — 두 번째 말에 새 정보가 있는가 |
| "한국 사람이 이렇게 말하나?" | S1-5 — 번역투 |

⚠️ **파트별로 읽으면 안 잡힌다.** 자기모순과 중복은 **조립한 전체를 이어 읽어야** 드러난다.
**챕터 경계는 앞뒤 두 문단씩 붙여 읽는다.** 파트별로 쓰면 경계는 아무도 안 읽는다.

## G5. 정합 — 제출 직전

- S14 — 유튜브 정책 위반 소지와 과도하게 사실적인 고통·신체 묘사를 제목·썸네일·낭독문·화면/음향 지시에서 함께 확인하고, 필요한 삭제·언어 순화를 마쳤는가. 특히 극한실화는 구조의 제약을 설명하는 문장과 고통을 재현하는 문장을 구별한다.
- 대조표 네 줄 (P16) — 클릭 이유 ↔ 제목 ↔ 썸네일 ↔ 도입부 첫 문장이 **같은 질문**인가
- P8 — 그 질문에 벤치마크의 실제 관심 근거와 새 주제의 검증 사실이 연결되는가. 작업자의 흥미를 관측된 시청자 요구로 바꾸거나, 시청 후 댓글을 클릭 동기로 단정하지 않았는가.
- 제목의 명사가 시킨 구조를 **어느 파트가 지급하는가** (T11)
- 훅 마지막 문장과 챕터 1 첫 문장 사이에 **"그래서"가 들어가는가** (H9)
- 클로징의 명사가 **본문에 전부 나왔는가** (B24)
- H2·H18: 추천 여부와 무관하게 제출하는 모든 후보가 기획의 시청자·시점·문제·범위를 유지하는가. 첫 문장, 중간 전환, 본문 진입에서 실제로 어느 단계에 있는지 확인한다. 기획 이탈을 발견하면 후보를 교체한 뒤 제출한다.


### G5-1. 설계 의도를 내려놓고 실제 원고에서 핵심 이탈을 찾는다

제출 전 기획표·작성자의 해설을 잠시 보지 않고 제목·썸네일·최종 낭독문만 연속으로 읽는다. 각 내용 단위에 지금 해결한 궁금증과 남은 궁금증을 적은 뒤 P0-15 구성표와 비교한다. ‘이런 의도로 썼다’와 실제 읽히는 효과를 분리한다. 이 작업은 같은 작성자의 재검토이며 외부 검증이나 독립 심사라고 부르지 않는다.

- 핵심으로 되돌아올 때까지 새로 배워야 하는 개념·비유·대상이 이어진 구간을 찾아 실제 시작·끝 문장으로 표시한다. 개수 자체를 합격 수치로 삼지 않는다.
- 각 설명에 대해 가장 설득력 있는 삭제 이유를 검토한다. 남기는 경우 삭제했을 때 없어지는 **구체적 이해나 의미**를 적는다. ‘흥미롭다’, ‘초보자를 위해’, ‘같은 분야다’, ‘브릿지가 있다’만으로 통과하지 않는다. 필요성이 확인된 설명을 삭제 수량을 채우려고 빼지 않는다.
- 승인 도입 뒤에 같은 답을 늦추는 기초 수업이 붙었는지, 핵심 답 뒤에 관측법·분류·한계·비유가 또 다른 이야기로 늘어났는지 확인한다. 필요한 사실 조건과 연구 한계는 해당 주장에 붙이되 통째로 누락하지 않는다.
- 해당 채널의 기존 실패 사례에서 가장 유사한 것을 실제 문장으로 대조한다. 우주 블랙홀 v1에서는 ‘공전→원반→태양 돛→에딩턴 한계→관측 방법’을 거친 뒤에야 핵심 답을 설명한 흐름을, 같은 가스 이야기라는 이유로 통과시킨 판단이 반례다. 이 소재들을 모든 영상에서 금지하는 규칙은 아니다.
- ‘핵심 집중’ 통과에는 유지·제외의 실문장 근거가 있어야 한다. 분량 계측·검색 중복 0·같은 소재·지침 파일 존재는 이를 대신하지 못한다. 근거가 모호하면 수정하고 재검토하며, 사용자가 다시 잡아주기를 기다리지 않는다.
- 사용자가 이미 반려한 판단은 기존 검토·진행상태에서 **철회/재검토**로 표시한다. 새 판정에 이전 통과를 복사하지 않는다. 내부 검사에서 통과해도 사용자 합격·실제 시청 유지율 검증으로 보고하지 않는다.

### G5-2. 최종 제출에는 해당 원고에서 수행한 검사의 증거를 붙인다

**초보자 이해 검사는 H4-2의 실패 유형과 실행 순서를 사용한다.** 도입 후보·수정 예시 등 부분 제출에도 해당 범위에서 적용한다. 기획 일치, 벤치마크 구조 적용, 전문용어 미사용만으로 이해도를 통과시키지 않는다. 해당 편 검토에 실제 구절과 수정·유지 이유가 없으면 이해도 검사 완료로 보고하지 않는다. 알려진 공백은 먼저 고치며, 검사표에 적고 사용자에게 넘기는 것으로 끝내지 않는다.

2026-09-14 사용자 요청: 지침을 추가해도 실제 검사를 생략하는 것이 문제다. 최종 원고는 항상 검사한 뒤 보여주고, 적용된 결과로 확인할 수 있어야 한다.

**마지막 수정본 저장 → 그 파일을 다시 열어 전문 확인 → G4·G5·G5-1 검사 → 발견한 문제 수정 → 영향 구간과 전체 연결 재확인 → 근거와 함께 제출** 순서로 실행한다. 작성 전 계획, 과거 버전 검수, 도구 실행 성공을 마지막 수정본 내용 검사로 대체하지 않는다. 검토 중 본문을 바꾸면 바뀐 부분의 이전 판정을 그대로 두지 않는다.

해당 편의 기존 검토 문서에 검토한 파일·버전·검토 범위와 실제 문장을 기록한다. 사용자에게는 최종 대본 뒤 아래 항목을 간결한 표로 보여준다. 이는 공용 0-5의 확인 요약을 구체화한 것으로 별도 검토 문서를 중복 생성하라는 뜻이 아니다. 전체 결과를 첨부 파일로만 숨기거나 사용자가 검토표를 대신 채우게 하지 않는다.

| 검사 | 최종 결과에 보여줄 실제 근거 |
|---|---|
| 핵심 집중 | 이번 핵심 질문, 곁가지로 판단해 뺀 실제 내용과 이유. 뺀 것이 없으면 가장 삭제를 검토한 설명의 실제 구절과 유지 이유 |
| 초보자 이해·등장 시점 | 어려웠던 실제 구절과 수정 문장, 또는 남긴 설명 앞에서 어떤 궁금증이 생겨 그 설명이 필요한지 |
| 중복·전환 | 실제로 합치거나 옮긴 구절과 수정 후 연결. 같은 어휘 개수·물음표 개수만 제시하지 않는다 |
| 제목·썸네일 약속 회수 | 약속한 질문에 답하는 본문의 실제 구절. ‘일치함’이라고만 적지 않는다 |
| 유튜브 정책·표현 순화 | S14에 따라 수정한 실제 표현과 이유, 또는 유지한 표현의 필요성. 검토한 낭독문·화면/음향 지시의 범위와 아직 확인하지 못한 제작물은 구별한다 |
| 사실·분량 | 핵심 주장 출처와 관측/해석 범위, 최종 낭독문 측정치·속도 가정 또는 실제 음성 시간, 남아 있는 한계 |

문제·수정이 없었던 항목은 확인한 실제 구절과 이유를 적는다. 검사한 흔적을 만들기 위해 불필요한 수정을 하거나 수정 전 문장을 지어내지 않는다. 검사표는 수행한 일을 기록하며 수행을 대신하지 않는다. 문장 자동 검색·파일 해시는 동일성·누락 확인에만 쓸 수 있고 이해·재미·필요성 통과 근거로 삼지 않는다.

실제 근거가 없거나 알려진 문제가 남아 있으면 최종 제출을 멈추고 작업자가 보완한다. 사용자가 검수 승인을 해줄 때까지 기다리는 새 절차로 만들지 않는다. ASK와 오토 모두 적용하되, 사용자가 도입 등 일부만 요청하면 그 제출 범위의 검사만 수행한다. 규칙 파일 저장 자체가 실행을 기술적으로 강제하거나 오류 없는 결과를 보장한다고 표현하지 않는다.

## G6. 고칠 때 — 지적받은 유형을 원고 전체에서 확인한다

짚힌 문장만 고치지 않고 같은 종류의 문제를 전수 확인한다.

1. 지적의 패턴을 정의한다. 예:이미 답을 아는 질문,수치 나열 뒤 의미 없음,같은 결론의 재진술.
2. 원고 전체에서 해당 구절을 찾아 맥락과 함께 대조한다. 검색 횟수는 누락 탐지에 유용할 때만 기록한다.
3. 벤치마크의 실제 구절과 기능을 비교한다. 문제 표현과 필요한 설명을 구별하며 비슷한 수량을 목표로 삼지 않는다.
4. 문제가 있는 구절을 고친 뒤 전후 연결·사실·회수를 다시 읽는다. 전체에서 찾은 구절과 수정·유지 이유를 남긴다.
5. 문제가 다른 표현으로 옮겨갔는지 확인한다. 필요하면 관련 어휘를 다시 검색하되 계측을 위해 문장을 만들거나 삭제하지 않는다.

한 곳만 수정하고 전체를 고쳤다고 보고하지 않는다. 실제 수행한 검사와 미실행 검사를 구별한다.

## G7. 이 게이트를 통과했다고 품질이 보장되지는 않는다

문체 수치는 **진단 참고값**이다. 하한선도 품질 점수도 아니다. 실제 구절의 이해·흐름·흥미를 판단하고 사용자 반응과 구별한다.
그러나 **수치로 잡히는 것과 소리로 잡히는 것을 사장님에게 잡게 하지 않는다.**
