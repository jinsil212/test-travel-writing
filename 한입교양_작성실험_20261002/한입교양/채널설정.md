## 원고 작성 시 반드시 지킬 것 (사용자 확정, 2026-09-18)

> **수익화는 독창성으로 지킨다.** 여러 영상(5개 이상도 가능)의 **정보**를 교차해 모으고, 1차 자료(통계·논문·기사)로 확인하고, 한국 사례와 작업자 해석을 넣어 **문장과 구성을 새로 쓴다.** 원본 영상의 화면·내레이션·대본 문장은 한 조각도 쓰지 않는다.
>
> **화면은 직접 생성한 AI 이미지 + 직접 만든 표·지도·그래프.** 원본 캡처·원본 썸네일은 쓰지 않는다.

- **대본 본문에 화면 지시를 넣지 않는다.** `[AI 이미지: …]`, `[표: …]`, `[키워드 카드: …]` 같은 표시가 대본 중간에 있으면 읽기 어렵다(2026-09-18 사용자 지적). 화면 설계가 필요하면 별도 문서나 원고 맨 아래 제작 메모에 둔다.
- **"대본 정리해줘"라고 하면 소제목(①훅, ⑩정리, ⑪회수 등) 없이 문단만 있는 대본 전문을 보여준다.** 공용 0-2의 클릭업 형식(소제목 없는 대본 전문)과 같은 방향이다.
- **제목·썸네일은 작업자가 확정하지 않는다.** 공용 P17·T0·T6·T13 절차대로 기획 선택 뒤 후보 10개씩 내고 사용자가 고른다.

## TTS 제작 기본값 (사용자 확정 2026-09-24)

> **사용자가 "자연스럽게 읽게 해줘"라고 따로 말하지 않아도, TTS를 만들 때마다 아래 1~6을 한다.** 원고를 그대로 음성 엔진에 넣지 않는다. 맞춤법·띄어쓰기를 보고 TTS가 제대로 읽을 수 있는 읽기용 글로 바꾼 뒤 만든다.

**목소리·속도 (확정)**
- 목소리 `ko-KR-HyunsuMultilingualNeural`(현수 멀티). 속도 1.1배 = `--rate 10`(SSML +10%). 한입교양 `azure_tts.py`의 기본값으로 박혀 있어 옵션을 적지 않는다. 같은 원고를 1.0배로 만들면 43.5초, +10%면 39.5초로 재생 시간이 정확히 1.10배 차이 났다(2026-09-24 실측).
- ⛔ **`--speed 1.1`을 쓰지 않는다.** 이 옵션은 준호 Flash에 맞춘 보정(0.7)이 붙어 +7%(약 1.07배)만 나온다(우주와나에서 물려받은 코드다). 속도는 `--rate`로만 바꾼다.
- 말 사이 쉬는 시간은 **압축하지 않는다(`--max-gap 0`, 도구 기본값).** 사용자가 고른 샘플이 압축 없는 원음이었다. 쉬는 시간이 길다는 지적이 있으면 `--max-gap 0.35`부터 줄여 본다.
- 문단 사이 쉼 0.5초(도구 기본값), 이음 쉼 0.3초(도구 기본값)는 그대로 둔다.

**절차** — **한입교양 전용 도구 `C:\영상편집\한입교양\_tool\azure_tts.py`를 쓴다**(우주와나 도구의 독립 사본. **우주와나 폴더의 도구는 쓰지 않는다**). 실행 위치 `C:\영상편집\한입교양\_tool`, 편 작업 폴더 `{편}` = `C:\영상편집\한입교양\{편 이름}`. 원고 정본은 이 폴더 `원고\{편 이름}\대본_최종.txt`이고 `{편}\원고.txt`는 그 복사본이다.
1. **최종 원고로 만든다.** 사용자가 채팅으로 대본을 주면 정본 `원고\{편 이름}\대본_최종.txt`(이미 있는 이름이면 그 이름 옆에 날짜)에 그대로 저장하고, 같은 글을 `{편}\원고.txt`로 복사한다(문단은 빈 줄). 대본이 아직 검토 중(v1 등)이면 시험 생성만 하고 최종본으로 다시 만든다. 사용자가 원문을 고치기로 하면 정본을 고친 뒤 `원고.txt`도 다시 복사한다.
2. **읽기용 초안:** `python azure_tts.py project "{편 이름}" --dry` (편 이름만 주면 `C:\영상편집\한입교양\` 아래에서 찾는다) → `{편}\_work\tts_읽기용.txt`, `{편}\_work\읽기변환_확인.txt`. 숫자·단위를 한글 읽기로 바꾼다(`1789년` → 천칠백팔십구년, `8.6그램` → 팔 점 육그램). ⚠ **`project`는 실행할 때마다 `tts_읽기용.txt`를 새로 만들어서 손으로 고친 내용을 덮어쓴다.** 그러니 `--dry`는 처음 한 번만 돌리고, 고친 뒤에는 `project`를 다시 돌리지 않는다(원문을 고쳐 다시 만들 때만 처음부터).
3. **내가 원문을 처음부터 끝까지 읽고 점검한다.** 소리만 바꾸는 것은 `tts_읽기용.txt`에만 고친다(4번에서 보여 준다). **원문(대본·자막)에서 고칠 곳이 하나라도 있으면 반드시 「원문 수정 제안」을 낸다 (사용자 지시 2026-09-25 — 빠뜨리지 않는다).** 조용히 넘어가거나 몰래 고치지 않는다. 고칠 곳이 없으면 "수정 제안 없음"이라고 알린다.
   - **제안 형식** (「유럽음식짠맛」 5건 때 쓴 형식): `①②…` 번호 · **원문 구절을 그대로 인용** · 제안(어떻게 고칠지) · **이유**(문법 기준, 앞뒤 문맥, 사실이면 근거 출처). 자막·음성에 미치는 영향도 적는다(예: 음성은 이미 "서너", 자막을 맞춰야 함).
   - 원문 수정은 **사용자 승인 뒤에만** 한다. 승인이 "다 수정"처럼 포괄적이면 제안한 대로 전부 적용하고, **실제로 바꾼 문장을 「수정 전 → 수정 후」로 다시 보여 준다.** 제안 때 문장을 정하지 못한 항목(사실 정정 등)은 내가 정한 문장을 함께 알린다.
   - **수정 적용 순서:** ① 정본 `대본_최종.txt` 수정 → ② `{편}\원고.txt`로 복사 → ③ `tts_읽기용.txt`의 같은 문장 수정 → ④ `python tts_patch.py {편 이름} --dry`로 바뀐 문단을 확인한 뒤 `python tts_patch.py {편 이름}` — **바뀐 문단만 다시 만들어 기존 `tts.mp3`에 이어 붙인다**(이미 검증한 나머지 문단의 소리가 달라지지 않는다. 옛 파일은 `_work\수정전_{날짜시각}\`에 보관). 문단 수가 달라졌으면 `synth`로 전체를 다시 만든다. ⑤ 바뀐 문단을 받아쓰기로 확인하고 재생 시간·글자 수를 편 진행상태에 다시 적는다.
   - 점검 대상:
   - 맞춤법·띄어쓰기 오류, 붙여 써서 끊어 읽기가 틀어지는 곳
   - 소리 나는 대로 적어야 바르게 읽는 낱말(외래어·고유명사·연음), 같은 글자 다른 소리(동형이의어)
   - 숫자 읽기: 연도·수량(고유어 세 개/한자어 삼 년), 소수·범위, 단위
   - 괄호·기호·가운뎃점(공용 B17: 가운뎃점 금지), 영문 약어
   - 숨 쉴 곳이 없는 아주 긴 문장의 쉼표 위치
   - 영문·기호가 남으면 도구가 멈춘다(exit 2) → 읽기를 정해 `{편}\_발음사전.txt`에 `원문=읽기`로 추가한다. 애매하면 사용자에게 묻는다.
4. **바뀐 곳만 사용자에게 보여 준다**(원문 → 읽기). 전체 대본을 다시 붙이지 않는다.
5. **생성:** `python azure_tts.py synth "{편}\_work\tts_읽기용.txt" --out "{편}\tts.mp3"` — 목소리·속도·쉼 압축은 이 도구의 기본값(현수 멀티, `--rate 10`, `--max-gap 0`)이라 옵션을 적지 않는다. `tts.chunks.json`에 문단별 시작 시각이 남는다. 다음 단계(`ae.bat align`, 장면 도구)는 `C:\영상편집\한입교양\CLAUDE.md` 절차를 따른다.
6. **재생 시간과 공백 제외 글자 수를 이 편 진행상태에 적는다.** 최소 10분(공용 B6)을 실제 재생 시간으로 확인한다.

- 발음사전은 한입교양 `_tool\발음사전.txt`(우주와나 사본에서 시작해 NASA·ISS 등 우주 용어가 남아 있다. 이 채널에서는 대부분 해당 없음)와 편 폴더의 `_발음사전.txt`를 함께 쓴다. 편 폴더의 것이 우선. 새 편은 앞 편 `_발음사전.txt`를 복사해 시작하면 된다.
