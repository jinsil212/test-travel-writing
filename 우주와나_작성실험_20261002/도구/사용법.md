# 단계 관문 사용법

실제 원문과 역할 문서를 읽은 총괄이 실행한다. 문서만으로 서브에이전트가 자동 생성되지는 않는다. 기준과 역할은 `지침/운영.md`를 따른다.

## 실행

PowerShell에서 `도구/runtime.json`의 Python 절대 경로와 `도구/pipeline.py`의 절대 경로를 작은따옴표로 감싸 실행한다. 훅 활성 상태에서는 변수·복합 셸 명령을 쓰지 않고 한 번에 한 명령을 실행한다.

형식: `& 'Python 절대 경로' '관문 스크립트 절대 경로' 명령 --episode 실행이름 ...`

모든 --input / --actors / --request 경로는 실험 프로젝트 루트 기준 상대 경로다. 외부 파일, ../, 연결 경로로 실험 밖을 가리키면 거부한다. JSON 템플릿은 `지침/양식/`에 있다. 입력은 파일 도구로 `실험/입력/`에 작성한다. 에피소드 결과는 CLI만 쓴다.

| 명령 | 필수 추가 인자 | 수행 |
|---|---|---|
| init | --actors 실험/입력/담당.json --request 실험/입력/요청.md --mode ASK 또는 AUTO --parts 파트수 [--max-minutes 상한] | 새 실행 생성. 기존 이름 거부 |
| decision | --stage plan/package/opening --actor 총괄ID --input 실험/입력/선택기록.md | 실제 사용자 발언을 단계별 선택 파일로 기록 |
| read-record | --role 역할 --actor 실제ID --input 실험/입력/열람.json | 원문 구절·적용 설명·해시 등록 |
| check | --stage 단계 | 앞 단계 PASS 및 현재 작성 담당 읽기 확인 |
| prepare | --stage 단계 --actor 실제ID --input 실험/입력/사전준비.json | 작성 전에 견본·약점·적용 근거 기록 |
| write | --stage 단계 --actor 실제ID --input 실험/입력/초안.txt | 선행 통과·사전 준비 검증 후 산출 저장 |
| review | --stage 단계 --actor 실제ID --input 실험/입력/검수.json [--kind final_fact 또는 final_flow] | 해당 버전 독립 판정 등록 |
| assemble | --stage final --actor 총괄ID | 모든 앞 단계 통과 후 낭독문 조립 |
| status | 추가 없음 | 처음 미통과 단계와 사유 / 최종 완료 여부 |

역할 키: coordinator, research, plan, package, opening, body, review, fact_review, flow_review. 부모 총괄 + 전담 7개다. 키는 9개이며 `review`와 `flow_review`가 같은 흐름검수 담당 ID를 쓰므로 에이전트 9명을 뜻하지 않는다. 사실검수 ID는 흐름검수·작성 담당과 분리한다. 담당 JSON에는 실제 생성된 에이전트 ID를 넣는다. 동시에 모두 생성하지 않는다. 기본 ASK. 사용자 선택이 필요한 단계에서 실제 대화 발언을 `실험/입력/선택기록.md`로 작성한 뒤, 해당 실행의 `decision_plan.md`·`decision_package.md`·`decision_opening.md`는 아래 decision 명령으로 저장한다. 단계별 선택을 따로 저장한다. 같은 단계의 선택을 변경하면 해당 단계와 후속 통과가 무효화된다.

## 추천 1안과 3세트의 선택 기록 — 최신 절차

init의 actors에는 현재 필요한 실제 담당만 넣는다. 새 역할을 실제 배정할 때 `roster --episode 실행이름 --actor 총괄ID --actors 실험/입력/추가담당.json`으로 추가한다. 기존 담당을 바꾸지 않으며 작성자/검수자 분리는 유지한다.

plan 결정에는 추천 1안 선정 위임의 실제 사용자 원문과 작업자 선정 이유를 기록한다. package PASS는 3세트 후보 내용 통과이며 selection.source=worker로 등록한다. 이 단계에서 사용자 선택을 기다리지 않는다. 도입 3개는 입력 후보 문서에 준비해 제목·썸네일과 함께 제출한다. 사용자가 고른 세트 ID·package 해시·제목·썸네일·도입 전문을 opening 결정에 연결한다. 선택 도입 한 개만 opening.txt에 write하고 검수한 뒤 본문으로 진행한다.

원문 변경 때문에 이전 실행의 관문은 현재 기준에서 재사용할 수 없다. 조사 자료 자체는 보존해 새 실행에서 변경·영향 범위만 재검토한다. 과거 PASS를 새 기준의 PASS로 표시하지 않는다.

## 열람 기록

배열의 각 원소: file, quote, application. 필수 파일은 `pipeline.required_readings(role, stage)` 목록과 `지침/운영.md`의 열람 기준에 따른다. 역할/운영 문서, 원문 5개, 공통 및 담당 묶음이 포함된다. 검수는 06 공통 정책, 단계 검수는 해당 작성 담당의 지침·묶음도 포함한다. 실제 사용할 벤치마크·분석지·합격원고·기타 원문을 추가한다. quote는 해당 파일의 실제 구절, application은 이번 편 적용 설명이다. 전문 열람과 동일 버전 기록 재사용 범위는 운영 문서에서 확인한다.

## prepare

purpose, benchmark_choice, weakness_to_avoid, evidence를 기록한다. 기획/포장/도입/파트/클로징에는 해당 벤치마크 근거 및 사용자 합격원고 실제 구절이 필요하다. 도입의 견본은 도입 원문이어야 하며 약점의 분석지 실제 근거도 별도 evidence로 넣는다. prepare 이후 열람 기록이나 견본을 바꾸면 prepare부터 다시 실행한다.

## review

검수 JSON에는 `artifact_sha256`, `verdict`, `unresolved`, `checks`를 넣는다. verdict=PASS이면 미해결 필수 문제 0건, 각 필수 key의 실제 구절·이유가 필요하다. FAIL이면 미해결 목록과 수정 방향을 남긴다. 검수자가 직접 해시를 확인해 명시하며 도구가 검수 대상의 버전을 대신 추정하지 않는다.

각 checks 원소: status(PASS/FAIL, 실사 미사용 image_sources만 NA 허용), reason, evidence 배열. 각 evidence는 file, quote, sha256. 각 필수 검사에 현재 검수 대상의 실제 구절이 최소 하나 필요하며 원자료·벤치마크 근거를 추가할 수 있다. 자료의 신뢰성과 인용의 타당성은 검수 담당이 확인한다. 코드가 문장의 재미를 점수로 판정하지 않는다.

plan/package/opening에는 selection을 추가한다. ASK: source=user, 실제 선택/위임 quote, reason, decision_sha256. AUTO: source=worker, reason. 실제 사용자 발언과 AI 선정의 진위를 코드가 판별하지 않으므로 총괄이 대화와 대조한다. 해당 단계 선택 파일이 바뀌면 그 단계 PASS와 후속 검수를 다시 수행한다.

최종 검수는 동일한 final.txt를 읽는다. `final_fact` PASS를 먼저 등록하고 `final_flow`를 등록한다. 최종 흐름 checks에는 6개 기본 키와 `criterion_01`~`criterion_25`를 모두 넣는다. `fact_review_reference`에는 actor(사실 담당 ID), artifact_sha256(같은 final 해시), receipt_sha256(현재 사실 receipt 해시), checks(최소 claims_sources/numbers_conditions/future_hypothesis)를 넣는다. 읽기·검토는 병렬 가능하다. 둘 중 하나라도 실패하면 완성 아님. 수정은 해당 도입/파트/클로징으로 돌아가고 final을 다시 assemble한다.

## 활성화

지침과 CLI는 즉시 사용 가능하다. native 훅은 다른 상태다. `.codex/hooks.json`은 프로젝트 계층과 정의의 신뢰 검토 후 실행된다. 작업 위치를 이 실험 폴더로 설정한 Codex에서 훅 목록/실행 로그를 확인한다. 중첩 .codex 계층이 자동 발견되지 않는 경우 `도구/우주실험_시작.ps1`이 프로젝트 로컬 JSON을 세션 인자로 전달한다(실행하면 별도 대화가 시작되므로 사용자 필요 시 사용). 상위 .codex와 사용자 전역 설정은 변경하지 않으며 신뢰 우회 옵션을 쓰지 않는다. 이미 실행 중인 이 채팅에 훅이 자동 적용됐다고 주장하지 않는다.

변경 기록과 시험 결과는 `실험/개편기록_20261002.json` 및 `실험/검증결과_20261002.json`에서 확인한다.
