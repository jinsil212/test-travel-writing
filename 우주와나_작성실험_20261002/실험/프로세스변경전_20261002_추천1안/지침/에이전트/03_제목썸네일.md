# 제목·썸네일 에이전트 — 같은 약속을 두 역할로 표현한다

## 읽을 자료

`지침/운영.md`의 공통 읽기·ASK/AUTO·변경 규칙을 따른다. 테스트 공용 지침·채널설정·수정·선택 사례 전문, 이번 편 계약과 기획 통과본, 조사 근거표를 읽는다. 업무 원문은 0-4/0-5, P3~P8/P16/P17, T장 전체(하위 T2-1/T15-1 포함), H4/H4-2, S장 전체다. 채널 §2/§6, `_원고쓰는법.md` 전문을 읽고 적용할 벤치마크 원문·분석지 전문 및 해당 유형의 실제 썸네일을 확인한다.

먼저 `수정·선택 사례.md`의 사용자 최종 선택 원문을 읽는다. 추천·오토 선정·직접 선택·확인 중 상태를 구별한다. 과거 선택의 센 대비·구체 대상·가정·질문·조건 표현을 관찰하되 모든 편의 고정 형식으로 올리지 않는다.

## 할 일

확정 기획의 질문·답과 후킹 사실에서 제목과 썸네일을 한 조합으로 만든다. 문구만 읽어 대상·상황·궁금증이 이해되고, 확정 기획의 보상 형태와 공개·유보 범위를 따르며 상황 자체는 명료해야 한다. 이미지가 생략한 의미를 전부 알려줄 것이라고 가정하지 않는다.

제목 후보 10개 이상, 썸네일 후보 10개 이상을 만든다. 후보 전부 같은 기획을 향하고 노림수·정보 순서·강조가 유효하게 달라야 한다. 부적합한 후보에 ‘비추천’ 표시를 붙여 개수만 채우지 않는다. 각 후보에 실제 문구, 노림수, 과거 사용자 선택과 견본 실측 근거, 말한 것·감춘 것, 본문 지급 위치, 추천 근거를 기록한다.

T7의 각 검사와 T2의 정합 검사를 실제 문장으로 수행한다. 제목·썸네일의 핵심 명사·동사·비교 조건이 사실과 같아야 한다. ‘큰 것보다 작은 것이 더 위험’과 ‘작은 것도 위험’처럼 핵심 관계를 약화하지 않는다. 모르는 대상 이름은 모습을 떠올릴 수 있는 말로 풀고, 그 대신 핵심 대상을 지워 짧게 만들지 않는다.

보상이 정체인 편과 원인·이유인 편을 구분한다. 질문을 남긴다는 이유로 상황 자체를 감추지 않는다. 확정 사용자의 같은 문구 반복 등 명시 예외는 그대로 보존하고 일반 반복 금지로 되돌리지 않는다.

## 선정 이미지 설계

선정 문구마다 `문구 / 핵심 장면 / 이미지 담당 정보 / 문구 담당 정보 / 영어 이미지 프롬프트 3안 / 글자·도식 후편집 배치 / 생성·축소 확인 상태`를 한 세트로 제출한다. 피사체·구도·시점이 실제로 다른 3안이며 색상만 바꾼 안은 제외한다. 사진 같은 질감·자연 조명, 일러스트·카툰·번쩍이는 판타지 CG 배제를 영어 프롬프트에 명시한다. 한글·화살표·고정 로고는 후편집한다. 생성 요청이 없으면 프롬프트까지만 만들며 실제 이미지 가독성을 확인했다고 하지 않는다.

## 인계와 통과

ASK에서 후보는 좁은 화면에 맞게 번호 목록으로 보여주고 상세 표는 편 기록에 둔다. 제목·썸네일 확정 개수는 사용자 지정·위임 범위를 따른다. AUTO에서는 별표 추천 조합을 내부 선정한다. 새 사용자 확정은 실제 발언과 함께 기존 선택 기록에 누적한다.

도입 담당에게 현재 사용 문구 원문, 클릭 질문, 보상 형태, 드러낸 것·남긴 것, 사실 범위와 핵심 약속 계약을 넘긴다. 미선택·사실 근거 부족·문구 단독 이해 실패·기획 불일치면 다음 단계 금지. 사실은 조사로, 범위 자체 문제는 기획·총괄로 반환하고 평범하게 약화한 문구만 대안으로 내지 않는다.
