- **참고 영상 여러 개가 있는 경우:** 제공 영상의 확보 가능한 원문을 읽고 공통 사실·서로 다른 평가·출처를 대조한다. 내용 재료와 기획·문체 견본의 역할을 구분한다(P0-1). 여러 영상의 순서와 문장을 이어 붙인 대본으로 대신하지 않는다.

2. **리서치·팩트 수집** — 대본에 쓸 사실은 이 단계에서 출처를 확인한다. 다 쓰고 나서 틀린 걸 고치면 두 번 일이다 — *"검수 자체 단계에서는 실제로 걸리는 것들이 없어야"*
3. **기획** — P장 전체. 팩트 브리핑 → 3안 → 확정 → 세부(제목·썸네일·첫 문장)
4. **집필** — 아웃라인(챕터별 사건과 반전)을 먼저 짜고, **파트별로 쓰고**, 조립한다. 한 번에 통째로 쓰지 않는다
5. **자가검수** — G장. 실제 문제와 명시 요구의 누락을 **보고하기 전에 고치고 다시 확인한다.** 지켰는지 확인해 달라는 게 아니라 지켜진 결과물을 낸다
6. **산출** — 대본 전문 + 제목·썸네일 확정안과 대체 후보 + 자가검수 결과표 + 「이렇게 썼습니다」(P18). 사용자가 채널별 전달처와 게시 준비 항목을 지정한 경우, 해당 채널 설정에서 현재 단계에 지정한 항목을 준비하고 승인된 전달처에 반영·재조회한 뒤 제출한다. 대본 단계와 편집 후 최종 업로드 정보 단계의 담당·범위를 구별한다.

2. **참고영상 검색 키워드 — 키워드만.** 원고 순서대로 구간을 나누고, 구간마다 검색어만 줄바꿈으로 나열한다. 장면 설명·아카이브 안내·주의사항은 이 댓글에 넣지 않는다. 사용자가 직접 소재를 찾을 때 그대로 복사해 쓰는 용도다. 만드는 절차는 아래 「키워드 댓글은 대본이 완성되면 자동으로」를 따른다.
3. **화면 타임스탬프 — TTS를 만든 뒤에만.** 음성 파일의 문단별 실제 시각(`tts.chunks.json` 등 정렬 결과)으로 적는다. TTS 전에는 이 댓글을 올리지 않으며, 부득이 추정 시간을 보여줄 때는 추정치라고 밝힌다. TTS를 만든 뒤에 추정 시간을 남겨 두지 않는다.

**키워드 댓글은 대본이 완성되면 자동으로 만든다.** 사용자가 따로 요청할 때까지 기다리지 않는다.

- **시점**: 최종 원고가 확정되어 보드에 등록하는 그 작업에서 같이 만든다. 원고 댓글과 **따로 된 댓글**로 올린다. TTS 전이어도 키워드 댓글은 올린다(타임스탬프 댓글만 TTS 뒤로 미룬다).

### P0-15. 클릭한 이유에 필요한 내용만 남긴다

기획 방향·제목·썸네일·도입이 약속하는 **핵심 질문과 이 편에서 줄 답**을 각각 한 문장으로 적는다. 관련 분야나 같은 대상이라는 이유로 포함하지 않는다. 소제목 수를 줄여도 내부에서 배우는 개념과 갈래가 그대로면 범위를 줄인 것이 아니다.

2026-09-14 반복 실패 보완: ‘핵심에 필요하다’, ‘쉽게 설명했다’, ‘같은 가스 이야기다’ 같은 작업자의 선언은 포함 근거가 아니다. **설명을 쉽게 만들기 전에 그 설명 자체가 필요한지 먼저 검사한다.**

집필 전 구성표에 다음을 기록하고, 파트 집필 뒤 실제 문단 기준으로 다시 대조한다. 표는 해당 편 작업 기록에 두며 별도 공용 지침으로 복제하지 않는다.

| 내용 단위 | 쓰기 직전 시청자가 아는 것·남은 궁금증 | 여기서 새로 이해할 관계 | 핵심 답에 필요한 실제 이유 | 삭제해 읽었을 때 생기는 구체적 이해 공백 | 유지·축약·제외 |
|---|---|---|---|---|---|
| 실제 장면·설명·비유를 적는다 | ‘블랙홀이 궁금하다’ 같은 범주 대신 직전 내용에서 생긴 의문을 적는다 | 새 명칭만 추가한 것은 새 이해가 아니다 | 원고의 어느 후속 문장이 이 설명에 의존하는지 대조한다 | ‘이해가 어려워진다’ 대신 어떤 인과·대상·조건이 빠지는지 적는다 | 내용의 필요성과 위치를 함께 판정한다 |

판정은 다음 순서로 한다.

1. **삭제해 연결해서 읽기:** 이 설명을 빼도 핵심 답을 이해하고 다음으로 자연스럽게 갈 수 있으면 제외하거나 제작 참고로 옮긴다. 핵심의 의미·감정에 필요한 장면은 무엇이 달라지는지 실제 구절로 설명한다. 기능 없는 압축을 강제하지 않는다.
2. **의존 관계 거꾸로 확인:** 뒤 문단이 필요로 해도 그 뒤 문단 자체가 곁가지라면 둘 다 보류한다. ‘뒤에서 다시 썼다’, ‘용어를 이미 넣었다’는 이유로 살리지 않는다.
3. **등장 시점 확인:** 설명을 시작할 때 시청자가 왜 듣는지 앞 맥락에서 알 수 있어야 한다. 필요성이 뒤늦게만 드러나면 핵심 상황을 먼저 보여주거나 설명을 필요한 자리로 옮긴다. 매번 ‘이걸 설명하는 이유는’이라는 안내 문장을 붙이라는 뜻이 아니다.
4. **선행 지식 비용 확인:** 답 하나를 이해하려고 다른 대상·용어·원리를 계속 배워야 하면 익숙한 상황으로 다시 풀거나 곁가지를 덜어낸다. ‘초보자니까 기초부터 전부’는 금지한다. 최소 선행 설명과 충분한 핵심 설명을 구별한다.

목표 시간이나 챕터 수를 채우려고 주제를 늘리지 않는다. 같은 핵심 안에서도 비유·재진술·해명을 늘리면 실패다. 분량 보강은 **현재 남아 있는 구체적인 이해 공백**을 해결하는 내용으로만 한다. 더 쓸 필요가 없는지 검토하지 않은 채 ‘더 깊게’라는 이름으로 확장하지 않는다. 필요한 근거가 부족하면 다시 조사·설계하며, 부족한 초안을 완성으로 제출하거나 기존 최소 길이를 임의로 해제하지 않는다.

제목이 실제 답보다 넓은 약속을 하면 최소 수정안을 제시하되 확정 문구를 임의로 바꾸지 않는다. 이 검사는 기획·집필·조립 모두 적용하며 새로 삽입한 설명도 예외가 아니다. 판정 결과가 원고와 다르면 원고를 먼저 고친다. 최종 재검사는 G5를 따른다.

### G5-2. 최종 제출에는 해당 원고에서 수행한 검사의 증거를 붙인다

**초보자 이해 검사는 H4-2의 실패 유형과 실행 순서를 사용한다.** 도입 후보·수정 예시 등 부분 제출에도 해당 범위에서 적용한다. 기획 일치, 벤치마크 구조 적용, 전문용어 미사용만으로 이해도를 통과시키지 않는다. 해당 편 검토에 실제 구절과 수정·유지 이유가 없으면 이해도 검사 완료로 보고하지 않는다. 알려진 공백은 먼저 고치며, 검사표에 적고 사용자에게 넘기는 것으로 끝내지 않는다.

2026-09-14 사용자 요청: 지침을 추가해도 실제 검사를 생략하는 것이 문제다. 최종 원고는 항상 검사한 뒤 보여주고, 적용된 결과로 확인할 수 있어야 한다.

**마지막 수정본 저장 → 그 파일을 다시 열어 전문 확인 → G4·G5·G5-1 검사 → 발견한 문제 수정 → 영향 구간과 전체 연결 재확인 → 근거와 함께 제출** 순서로 실행한다. 작성 전 계획, 과거 버전 검수, 도구 실행 성공을 마지막 수정본 내용 검사로 대체하지 않는다. 검토 중 본문을 바꾸면 바뀐 부분의 이전 판정을 그대로 두지 않는다.

해당 편의 기존 검토 문서에 검토한 파일·버전·검토 범위와 실제 문장을 기록한다. 사용자에게는 최종 대본 뒤 아래 항목을 간결한 표로 보여준다. 이는 공용 0-5의 확인 요약을 구체화한 것으로 별도 검토 문서를 중복 생성하라는 뜻이 아니다. 전체 결과를 첨부 파일로만 숨기거나 사용자가 검토표를 대신 채우게 하지 않는다.

|---|---|

## G6. 고칠 때 — 지적받은 유형을 원고 전체에서 확인한다

짚힌 문장만 고치지 않고 같은 종류의 문제를 전수 확인한다.

1. 지적의 패턴을 정의한다. 예:이미 답을 아는 질문,수치 나열 뒤 의미 없음,같은 결론의 재진술.
2. 원고 전체에서 해당 구절을 찾아 맥락과 함께 대조한다. 검색 횟수는 누락 탐지에 유용할 때만 기록한다.
3. 벤치마크의 실제 구절과 기능을 비교한다. 문제 표현과 필요한 설명을 구별하며 비슷한 수량을 목표로 삼지 않는다.
4. 문제가 있는 구절을 고친 뒤 전후 연결·사실·회수를 다시 읽는다. 전체에서 찾은 구절과 수정·유지 이유를 남긴다.
5. 문제가 다른 표현으로 옮겨갔는지 확인한다. 필요하면 관련 어휘를 다시 검색하되 계측을 위해 문장을 만들거나 삭제하지 않는다.

## 1. 가장 중요한 것 — 클릭한 이유를 끝까지 책임진다

시청자는 **제목과 썸네일이 던진 질문 하나** 때문에 영상을 누릅니다. 좋은 원고는 그 질문을 도입·본문·마무리까지 한 줄로 끌고 가서 답해 줍니다. 이 줄을 **약속 사슬**이라고 부르겠습니다.

```
제목·썸네일이 던진 질문
   ↓ 도입 마지막 문장이 같은 질문을 다시 묻는다
   ↓ 본문이 그 답을 준다 (늦게 줘도 되지만, 가는 길에 질문을 잊지 않게 한다)
   ↓ 마무리가 처음 장면이나 단어를 다시 불러 새 뜻으로 닫는다
```

18편 중 **13편이 이 사슬을 지켰고**, 3편은 일부만, 2편은 지키지 못했습니다. 지키지 못한 영상에는 공통점이 있었습니다.

**잘된 예 — 「타이탄」 (제목·썸네일·도입·본문이 한 점에 모인 기본형)**
- 제목: “타이탄에 생명체가 존재할 가능성이 높다고 합니다” / 썸네일: “타이탄의 바다에 / 생명체가 있다고?”
- 도입 끝: “이 타이탄의 생명체 존재 가능성을 한번 자세히 알아보자.”
- 본문: 근거 다섯 개를 하나씩, 가장 센 것을 마지막에 — “자 가장 중요한 단서는 이거예요”
- 마무리: “타이탄에 생명체가 있을 것 같다 없을 것 같다 여러분들의 의견 많이 많이 남겨 주시구요.”

**안된 예 — 「양자역학」**
- 제목은 “신이 존재하지 않는다는 결정적인 증거”인데, 도입 끝이 “도대체 이들은 어쩌다가 이런 생각에 이른 걸까?”로 **질문이 바뀝니다.** 본문은 과학자들의 이야기로 가고, ‘신’은 도입 뒤로 다시 나오지 않습니다.

**안된 예 — 「파피루스」**
- 썸네일이 “충격적인 내용”을 약속했지만 실제 내용 이야기는 전체의 17.6%뿐입니다. 댓글 5위(좋아요 140개)가 “4:55 … 여기부터”라고 **건너뛸 시간**을 적었습니다.

**우리 원고에서는 — 「화성 땅 밑 도시」**

| 자리 | 실제 문장 | 위치 |
|---|---|---|
| 제목 | 화성에 도시를 짓는다면, 땅 위가 아니라 땅 밑이어야 하는 이유 | — |
| 썸네일 | 화성에서 도시를 짓는다면 / 땅 위가 아니라 여기? | — |
| 도입 끝 | 그게 무엇인지 알면, 왜 하필 땅 밑에 도시를 지어야 하는지도 알 수 있어요. | 13% |
| 가는 길의 씨앗 | 과학자들이 도시를 땅 밑에 짓자고 하는 것도, 사라진 두 방패를 대신할 무언가가 필요해서예요. | 39% |
| 핵심 답 | 결국 땅을 파고 그 아래로 들어가는 쪽이 가장 확실해요. 과학자들이 땅 밑을 이야기하는 이유가 바로 이겁니다. | 58% |
| ‘여기’의 실제 후보 | 과학자들은 이 구멍들이 땅속 동굴로 이어지는 입구일 수 있다고 봅니다. | 79% |
| 마무리 | 그러니까 화성의 첫 도시는, 우주에서 내려다보면 거의 보이지 않을지도 모릅니다. | 96% |

**확인하는 법:** 위처럼 다섯 자리의 실제 문장을 한 표에 나란히 적어 보세요. 모두 같은 질문 이야기를 하고 있으면 통과입니다.

### 3-1. 짧게 — 대상을 세우고, 뜻밖의 사실 하나로 흔들고, 질문 하나로 모은다

**왜:** 18편 중 절반은 도입이 전체의 6% 이하, 문장 2~14개였습니다. 도입이 15%를 넘은 3편(「1광년」「카르다쇼프」「삼체」)은 분석에서 모두 ‘너무 길다’는 지적을 받았습니다. 도입에서 하는 일은 거의 같습니다.

```
① 대상(또는 누구나 아는 것)을 세운다
② 뜻밖의 사실·모순 하나로 흔든다
③ 질문 하나로 모은다  →  ④ 본문으로
```

**잘된 예 — 「공룡 멸종」 (단 2문장)**
> 지구 생명체의 무려 75%를 멸종시킨 다섯번째 대멸종. 티라노사우루스 … 같은 공룡들도 멸종, 하늘을 지배하던 익룡들도 멸종, 바다에 살던 암모나이트도 멸종합니다.
> 6500만 년 전 지구에는 도대체 어떤 일이 있었길래 대부분의 생명들이 사라지게 된 걸까?

**안된 예 — 「1광년」 (도입 23%)** 채널 근황 → 여러 행성 거리 → 은하 → 우주 끝 → 댓글 소개 → 진입. 좌표가 네 번 바뀌고 질문이 늦습니다.

**우리 원고에서는:** 도입은 전체의 약 14%로, 권장(12% 이하)보다 조금 깁니다. 사용자가 확정한 도입이라 그대로 두었습니다.
**확인하는 법:** 도입이 끝나는 문장을 찾고 전체에서 몇 %인지 잽니다. 도입 안의 사실이 모두 하나의 질문을 향하는지 봅니다. 하나를 빼도 질문이 서면 빼도 되는 사실입니다.

## 8. 완성 원고 검사표

원고를 다 쓰면 이 표를 이번 편 문서에 붙이고 **실제 문장과 위치(%)**로 채웁니다. ‘예’라고만 쓰면 통과가 아닙니다.

**A. 클릭 이유를 책임지는가 (가장 중요)**
1. 핵심 주제 한 문장이 제목·썸네일·첫 문장·도입 끝·마무리에 모두 이어지는가? (1장 표)
2. 도입 마지막 질문이 제목의 질문과 같은가? (3-2)
3. 도입에서 작은 답은 주되, 핵심 답은 남겼는가? 준 것과 남긴 것을 각각 적는다. (3-5)
4. 핵심 답은 몇 % 지점에서 나오는가? 그 전에 제목의 핵심 단어가 30% 넘게 사라지는 구간은 없는가? (4-2)
5. 제목의 약속과 상관없는 곁가지가 있는가? 덤이 있다면 핵심과 이어 주는 문장이 있는가?
6. 썸네일 문구의 약속이 본문 어디서 풀리는가? (2-2)
7. 마무리가 처음 것을 새 뜻으로 거두고, 새 정보가 있는가? (5-1)

**B. 도입과 흐름**
8. 뜻밖의 사실이 몇 번째 문장에 있는가? (2~3문장 안 권장, 3-3)
9. 도입은 전체의 몇 %인가? (12% 이하 권장, 3-1)
10. 첫 전환은 어디인가(44~68%)? 후반에 뜻을 바꾸는 전환이 있는가? (4-3)
11. 시청자 반박을 먼저 말하고 답한 곳은? (4-4)
12. 앞에 심은 단어·장면이 모두 회수되는가? (4-5)

2. **수정 요청·반영 대조표** — 담당자가 바꾼 구절마다 해결 여부를 확인한다.

| # | 위치(%) | 고치기 전 | 고친 뒤 | 기준 번호 | 이유(한 줄) |
|---|---|---|---|---|---|

3. **진단 표 전후 비교** — 약속 사슬 표, 구간 지도, 계측표를 초고 값 / 수정본 값으로.
4. **기준 1~25 판정표** — 기준마다 통과 / 수정 필요 / 확정 구간 문제, 근거가 된 실제 문장과 현재 해결 상태.
5. **확정 구간 의견** — 고정이라 고치지 않았지만 기준에 걸린 곳(예: 도입이 12%를 넘음).
6. **사실 의견** — 틀려 보이지만 고치지 않은 숫자·주장.

**보고서 규칙:** ‘자연스럽게 다듬음’처럼 뭉뚱그리지 않는다. 모든 변경은 기준 번호가 있어야 한다. 기준 번호를 댈 수 없는 수정은 하지 않는다.
