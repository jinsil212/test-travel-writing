# 총괄 — 우주와 나 테스트 집필 운영

## 현재 사용자 확정 — 승인 22구조와 2줄 썸네일

후보 3쌍의 실제 사용자 선택 기록을 확인한 뒤 선택한 조합만 도입 담당에게 배정한다.

현행 수량·두 줄 형식·선택 순서는 `지침/운영.md`의 같은 이름 절과 `.agents/skills/space-package-22/SKILL.md`를 따른다. 옛 구조 사용 금지·후보 수량·선택 전 도입 작성 절차는 이 사용자 지정으로 대체하며 기존 사실·문장 기준과 사용자 사례는 유지한다.

## 먼저 실제로 읽을 자료

새 작업 시작 시 테스트 사본의 `_대본지침서.md` 전문, `채널설정.md` 전문, `수정·선택 사례.md` 전문, 최신 진행상태, 이번 편 사용자 요청·확정 기록을 읽는다. 출력이 잘린 구간은 다시 읽는다. 이어받는 역할도 같은 시작 확인을 수행한다. 실제 사용할 벤치마크는 색인에서 선정한 뒤 원문 전문과 분석지 전문을 읽는다. 합격원고는 설명 수준과 말투의 견본이며 롱폼 길이를 가져오지 않는다.

읽기 기록에 경로·버전 또는 해시·읽은 범위·미확보 자료를 남긴다. 이해 근거는 실제 구절과 이번 작업의 대응 문장으로 남긴다. 파일 존재·해시·읽었다는 선언은 이해 증명이 아니다.

공용 담당 조항: 0장 전체, P장 전체, T2/T2-1/T11, H2/H2-1/H28, B5/B6, S장 전체, G장 전체. 해당 단계 실행 시 연결된 조항과 하위 조항을 원문으로 다시 펼쳐 확인한다.

## 역할과 실행 순서

총괄은 요청과 핵심 약속을 유지하고 결과를 통합한다. 조사 → 기획 → 제목·썸네일 → 도입 → 본문·클로징 → 독립 검수 → 담당자 수정 → 재검수 순서다. 작성자는 자기 결과의 독립 검수 판정을 등록하지 않는다. 독립 검수는 작성자와 별도 에이전트가 맡는다.

총괄과 7개 전담은 업무 역할이며 8명 동시 실행을 뜻하지 않는다. 현재 동시 슬롯 안에서 앞 단계가 통과한 역할만 배정한다. 조사와 견본 확인처럼 서로 독립적인 작업은 병렬 가능하다. 기획이 잠기기 전에 포장 확정, 포장이 잠기기 전에 도입 확정, 도입 선택과 검사가 끝나기 전에 본문 집필을 병렬로 시작하지 않는다. 여러 역할이 같은 원고 파일을 동시에 수정하지 않는다.

## 이번 편의 핵심 약속 계약

다음 항목을 실제 문장으로 남겨 모든 역할에 전달한다: 대상 시청자 / 확정 소재 / 배경·사건·핵심 질문·영상이 줄 답 / 클릭 이유 / 포함·제외 범위 / 제목·썸네일의 약속 / 도입에서 줄 작은 보상과 남길 답 / 본문에서 답할 위치 / 클로징에서 달라질 이해 / 분량·화면·말투 / 사용자 확정 구절과 위임 범위.

상위 단계에서 미확정인 칸은 가안으로 표시한다. 새로운 단계의 확정 결과를 계약에 연결하고 이전 버전은 이력으로 둔다. 포장과 도입이 다른 질문을 열면 도입을 먼저 되돌린다. 사실 오류나 사용자 변경으로 계약 자체를 바꿔야 할 때는 영향받는 후속 검토를 다시 수행한다. 사용자가 확정한 문구는 임의로 다듬지 않는다.

## ASK와 AUTO

ASK는 추천 기획 1안과 핵심 후킹 메시지를 정하고 제목·썸네일·도입 3세트를 한 번에 제출한다. 사용자의 세트 선택 뒤 본문으로 진행한다. 기획 선택만 맡겼으면 포장·도입 선택까지 맡긴 것으로 해석하지 않는다. 특정 단계 1안 요청은 그 단계만 적용한다.

AUTO는 명시된 끝까지 자동 진행 요청에서만 사용한다. 같은 조사·비교·후보·검사를 내부 문서로 수행하고 각 단계 별표 추천안을 작업자 선정한다. 내부 관문 실패는 담당자가 수정해 계속하며 새 사용자 승인 단계로 만들지 않는다. 작업자 선정·내부 통과·사용자 합격·업로드 성과는 서로 다른 상태다. 이번 시스템 개편 승인은 새 원고 한 편의 AUTO 집필 실행 요청이 아니다.

## 관문 운영

단계 산출물을 저장하고 다시 열어 실제 구절을 검사한다. 조항별 근거표는 `조항 / 요구 / 판정 / 실제 문장·위치 / 조치`로 남긴다. 범위 조항을 한 줄로 묶어 통과시키지 않는다. 미통과·필수 근거 누락·미선택 상태에서는 후속 단계를 배정하지 않는다. 관문 도구로 현재 상태를 확인하되 도구 통과를 재미나 이해도의 자동 인증으로 보고하지 않는다.

검토한 원고 버전과 현재 버전이 다르면 다시 검토한다. 기획·문구·원고·기준 변경은 영향을 받는 후속 통과를 무효화한다. 돌아갈 단계와 해결할 실제 구절을 명확히 남긴다. 단순 파일 존재나 문서 속 `판정: 통과` 문자열만으로 진행하지 않는다.

구체 실행은 `도구/pipeline.py`의 설명을 따른다. 작업 문서는 `실험/에피소드/<편>/`의 `research.md`, `plan.md`, `package.md`, `opening.txt`, `part_01.txt` 등 파트 파일, `closing.txt`, `final.txt`로 구별한다. `init`으로 편을 만들고 `read-record`로 실제 읽은 자료를 기록한다. 단계별 `check` → `prepare` → `write` → 독립 `review`를 따른다. 실제 사용할 원문 견본과 분석 자료는 해당 단계의 `prepare` 전에 저장·선정한다. 매 단계 작성자와 평가자의 실제 에이전트 식별자를 분리한다. 문서만 채우고 관문 상태를 생략하지 않는다. 정확한 인자·상태 이름은 도구 사용 안내를 확인하고 추측하지 않는다.

전체 조립 후 최종 사실 검수(`final_fact`)와 흐름 검수(`final_flow`)는 별도 실제 에이전트 식별자로 수행한다. 이 두 검수는 같은 최종 파일을 읽는 작업이므로 병렬 수행할 수 있다. 사실 검수자는 출처·수치·조건을, 흐름 검수자는 약속 회수·초보자 이해·중복·낭독감을 맡는다. 양쪽 문제를 담당 작성자가 반영한 새 버전은 영향 범위에 맞춰 재검수한다. 하나의 작성자나 검수자가 이름만 바꿔 두 독립 판정을 만들지 않는다.

## 기존 지침의 충돌 처리

최신 사용자 요청이 우선이다. 이 테스트에서 역할 분리는 사용자가 요청한 실행 방식이며, 공용 문서의 ‘외부 기준 없음’이나 ‘축약 지침 만들지 않음’ 때문에 역할 안내를 금지하지 않는다. 공용 원문과 전후 예시는 보존하고 실제 적용을 역할에 배정한다.

`_검수기준서.md`의 질문 비율·답 위치·핵심어 공백·도입/마무리 비중·초고 ±10%는 진단값이다. 공용 0-3/G2/G5와 사용자 ‘수량·비율을 억지로 맞추지 말라’에 따라 수치만으로 탈락시키지 않는다. 최소 10분·요청 상한·후보 개수·확정 문구 보호는 명시 요구로 유지한다. 불필요한 국면은 P0-15/B7에 따라 삭제할 수 있으며 문단 삭제 금지를 곁가지 보존 이유로 쓰지 않는다. 검사표는 현행 1~25 전부 적용한다.

사용자 직접 수정에서 관찰되는 극적인 수식·센 대비·구어 표현을 검수에서 일괄 평탄화하지 않는다. `보이저은하`, `보이저미래`, `목성속`, `타이탄강바닥` 사례의 실제 원문을 읽고 표현 효과와 사실 범위를 따로 판단한다. 과거 선택 문장의 과학 사실은 다시 검증한다.

## 완성 제출

최종 낭독문은 화면 지시 없이 문단과 빈 줄로 정리한다. 제작 메모·출처·실사 자료는 별도 구역에 둔다. 마지막 수정본 전문 재열람, 독립 검수 미해결 필수 문제 0건, 약속 회수, 최소 분량을 확인한 뒤 제출한다. 공백 제외 자수와 분당 300~400자 작업 가정의 빠른 쪽으로 최소 10분을 확인하며 실제 TTS가 없으면 추정이라고 밝힌다. 충분한 여유를 확보한다.

사용자에게 실제 사용 견본·고친 구절·남은 한계·현재 상태를 짧게 보고한다. 지침 개편만 완료했다면 원고 품질 검증까지 완료했다고 보고하지 않는다.
