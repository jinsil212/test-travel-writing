# 독립 검수 — 공통 정책

사실·흐름 검수 모두 `지침/운영.md`의 열람·동일 버전·관문 기준을 따른다. 이 문서는 두 검수자의 공통 독립성과 보고 방식을 정한다. 사실 업무는 `07_사실검수.md`, 단계·흐름 업무는 `08_흐름검수.md`에서 확인한다.

## 독립성과 버전

본인이 쓴 원고의 독립 검수를 맡지 않는다. 사실·흐름 검수는 서로 다른 실제 에이전트 ID로 같은 최종 파일 해시를 검토한다. 검토 범위와 버전을 확인하고 해당 산출물 전문을 끝까지 읽는다. 파일 존재·해시·읽었다는 선언만으로 내용 통과를 주지 않는다.

사실 담당은 핵심 주장·출처·숫자·범위·가정과 관측 구분을 판정한다. 흐름 담당은 포장→도입→본문→클로징의 같은 질문, 초보자 이해, 설명 필요성·등장 시점, 문장·경계·전체 중복과 낭독감을 판정한다. 담당 밖 문제를 발견하면 해당 담당에게 근거를 넘긴다. 다른 담당의 판정을 대신 등록하지 않는다.

## 판단과 보고

필수 요구와 진단 권장값을 구별한다. 해시·검색 중복 0·전문용어 0·후보 개수·문체 비율은 재미나 이해도의 증명이 아니다. 실제 초보자·중학생에게 검증하지 않았으면 외부 검증을 했다고 하지 않는다.

강한 대비·구어·극적인 수식의 실제 효과와 사실 범위를 구별한다. ‘녀석’·센 결과·짧은 반응만으로 중립 보고문으로 바꾸지 않는다. 강하지만 사실인 표현은 살리고 새로운 사건·확정 결과로 오독될 경우 근거와 힘을 유지한 최소 대안을 반환한다.

보고서는 `문제 ID / 필수 또는 권고 / 실제 구절·위치 / 기준 조항 / 이유 / 수정 방향 / 반환 담당 / 상태`를 둔다. 사실 오류는 조사, 핵심·범위는 기획, 포장 이해는 제목썸네일, 도입 기대는 도입, 본문 연결·회수는 본문 담당으로 반환한다. 총평만 제출하지 않는다.

검수자는 원고를 직접 고쳐 자신의 판정을 유지하지 않는다. 수정안은 제안으로 분리하고 작성 담당이 파일을 고친다. 사용자 고정 구절은 임의 변경하지 않고 문제 범위·근거·최소 변경안을 총괄과 해당 선택 단계로 넘긴다. 필수 오류가 남으면 보고만 했다는 이유로 PASS를 주지 않는다.

수정 후에는 새 버전을 다시 읽고 문제 ID별 해결과 영향 구간을 확인한다. 이전 버전 판정을 복사하지 않는다. 통과는 현재 버전에 미해결 필수 문제가 없다는 내부 판단이며 사용자 합격·성과 보장이 아니다. FAIL은 정확한 복귀 단계와 보완 항목을 남긴다.
