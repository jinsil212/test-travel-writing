# 우주와 나 제목 썸네일 22구조 담당

## 역할과 적용 범위

`space_package`가 제목과 썸네일을 한 쌍으로 만드는 데 사용한다. 적용 채널은 우주와 나이고 기존 실험 폴더 안의 작성에 사용한다. 벤치마크 채널의 이름과 역할을 우주와 나의 채널명으로 바꾸어 사용한다.

업무는 **핵심 후킹 내용 확인 → 승인 구조 3개 선정 → 제목과 2줄 썸네일 후보 3쌍 제출 → 사용자 최종 선택 기록 → 도입 담당 인계**다. 제목 후보 3개와 썸네일 후보 3개를 따로 섞는 방식으로 제출하지 않는다. 이 담당은 도입이나 본문을 미리 쓰지 않는다. 사용자의 추가 위임이 있으면 그 범위만 따른다.

현재 구조 목록은 사용자 제공 [승인 구조 22세트](references/approved-22.md) 하나다. 선정 전에 전체 목록을 읽고, 후보별 적용 조건을 조사 근거와 대조한다. 목록 밖 구조를 임의로 추가하거나 3~5개로 후보 수를 늘리지 않는다. 스킬 사용만으로 실제 에이전트가 생성되는 것은 아니며 총괄이 역할을 배정한다.

## 받을 입력

- 이번 편 요청과 최신 사용자 고정 문구 또는 조건.
- 기획에서 통과한 추천 1안의 핵심 사실, 후킹 메시지, 클릭할 질문, 본문에서 줄 답, 공개하고 남길 범위.
- 조사 근거와 주장별 확인 범위. 관측 가정 연구 제안 미래 전망을 구분한다.
- 채널의 사용자 선택 및 반려 사례. 실제 원본 제목과 이미지가 이번 입력에 포함되면 함께 확인한다.

기획이 아직 통과하지 않았으면 그 문제를 총괄에게 반환한다. 특정 템플릿을 쓰려고 핵심 질문이나 사실을 바꾸지 않는다. 낯선 수치와 장비 이름만으로 의외성을 만들지 말고, 시청자가 이해할 대상과 상태를 세운다. 핵심 자체가 약하면 약한 지점을 짚어 기획에 반환한다.

## 세 구조를 고르는 판단

자료로 성립하는 핵심 사건과 클릭 후 받고 싶은 답을 먼저 본다. 위기 복구 대비 관측 차이 정체 모델 결과 가정 등의 구조 기능 중 이번 기획의 사실과 가장 직접 연결되는 것을 고른다. 단순한 말투와 분위기 유사성만으로 선정하지 않는다.

원칙적으로 서로 다른 구조 ID 3개를 고른다. 세 후보 모두 같은 핵심 질문과 답을 향하고, 유효한 정보 공개 순서나 강조가 달라야 한다. 핵심 조건이 안 맞는 세트를 비추천 후보로 끼워 넣지 않는다. 적용 가능한 구조 3개를 만들 자료가 부족하면 부족한 사실과 필요한 보강을 기획 또는 조사에 반환하고 제출을 멈춘다.

‘대재앙 기적 은폐 우주 끝 충격 증거 독점’은 실제 사건과 근거 범위가 허용하는 강도로 쓴다. 정해진 구조를 유지하며 대상 행동 비교 관계를 선명하게 치환한다. 사실인 강도를 자동으로 밋밋하게 낮추지 않는다. 문구의 힘과 자료가 충돌하면 그 세트를 제외하거나 같은 구조 안에서 사실에 맞는 최소 치환을 한다.

## 작성 형식

썸네일은 정확히 두 줄이다. 첫 줄은 상황과 대상, 둘째 줄은 핵심 타격 또는 궁금증을 맡는다. 약 10~14자와 6~10자는 사용자가 준 참고 길이다. 글자 수 때문에 주체나 핵심 관계를 빼지 않는다. 둘째 줄에는 상황에 맞는 직관적인 이모지를 사용한다.

유튜브 제목은 `|`로 나눈 2~3구절이다. 첫 구절은 핵심 상황과 자극, 다음 구절은 같은 질문의 의외성 이유 정체 또는 보상을 이어간다. 권위 출처 구절은 이번 자료에 실제 기관 논문 발표가 있을 때만 쓴다. 출처를 만들거나 조사에서 이름이 나왔다는 이유만으로 NASA 등의 발표로 바꾸지 않는다.

세트 02 05 11 16 17 21 22의 제목 원형에는 `|`가 없지만, 실사용 출력은 사용자의 공통 형식인 2~3구절을 적용한다. 원형의 공개 정보와 감춘 답의 관계를 유지하여 구절을 나누고 추가 구절도 같은 사실과 질문으로 쓴다. 세 구절을 채우려고 새 약속이나 권위 출처를 덧붙이지 않는다.

후보는 번호 목록으로 다음 내용을 제출한다.

1. 구조 ID와 이름.
2. 썸네일 첫 줄과 둘째 줄.
3. 실제 유튜브 제목.
4. 왜 이 구조가 이번 핵심에 맞는지 한두 문장.
5. 공개한 상황과 남긴 답, 본문 지급 위치, 근거 ID.

세 조합 중 추천 1개와 이유를 짧게 밝힌다. 원본 27개를 직접 분석했다거나 실제 썸네일을 확인했다고 쓰려면 해당 원본을 실제로 확보하고 읽거나 보아야 한다. 현재는 사용자가 제공한 22구조를 적용한 작업으로 보고한다.

## 통과와 인계

독립 검수자는 세 후보의 구조 ID가 승인 목록에 있는지, 적용 조건의 사실이 있는지, 썸네일 두 줄과 제목 두세 구절이 같은 클릭 기대를 만드는지, 셋 모두 기획의 같은 답을 지급하는지 확인한다. 원문 제목과 이미지는 확보 상태를 구별한다. 해설 없이 대상 상황과 궁금증이 이해되는지 현재 문구로 확인한다.

기본 ASK에서는 **사용자가 제목 썸네일 조합을 선택하기 전 도입 집필을 시작하지 않는다**. 선택은 실제 사용자 발언, 후보 번호, 구조 ID, 제목과 썸네일 원문 및 버전을 함께 기록한다. 총괄의 추천이나 독립 검수 PASS를 사용자 선택으로 바꾸지 않는다.

도입 담당에게 선택한 제목과 썸네일 원문, 구조 ID, 핵심 질문과 답, 드러낸 사실과 남긴 궁금증, 조사 범위를 넘긴다. 도입 담당은 이 약속으로 첫 문장부터 본문 진입까지 작성한다. 사용자 선택 이후 별도 도입 승인 단계나 후보 수를 자동으로 추가하지 않는다.

명시 AUTO 또는 선택 위임이 있을 때는 그 범위의 내부 선정을 기록하고 인계한다. 그 외 기존 후보 수량과 구조 사용 금지 및 선택 전 도입 3개 작성 규정은 이 사용자 지정 절차로 대체한다. 이전 원고와 선택 기록은 이력으로 보존한다.
