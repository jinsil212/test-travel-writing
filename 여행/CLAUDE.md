# 여행 원고 (새 방식 테스트)

지침은 짧게 유지한다. 여기와 `참고/`에 없는 규칙을 다른 폴더(미드폼 작성 등)에서 가져오지 않는다.

## 실행 방법 (강제 장치)

- 참고 자료 전문은 이 파일 맨 아래 `@` 불러오기로 항상 들어와 있다. 사용자는 명령어 없이 평소 말로 요청한다("○○ 원고 쓰자", "여행 원고 하나 만들자", 링크 전달 등).
- **한 번에 끝까지 (2026-10-08 사용자 지시):** 0단계 중복 확인 → 1단계 기획 → **Claude가 제목·썸네일·도입 1안을 확정** → 2단계 대본까지 중간에 사용자 선택을 기다리지 않고 진행한다. 사용자에게 3안을 보여 주고 고르게 하지 않는다. 사용자가 나중에 수정을 말하면 그때 `선택.md`에 적고 v2로 고친다.
- `/trip-plan`, `/trip-script` 명령어는 선택 사항이다(같은 순서를 명시적으로 시작할 때).
- `.claude/hooks/gate.py`가 `원고/{주제}/기획.md`·`대본*.md` 저장을 검사한다. 조건(자료.md·중복 확인·유형1~5 점검·사례 번호 전부·선택.md·흐름 대응표·점검표)이 빠지면 저장이 거부된다. 거부 메시지를 받으면 참고 자료로 돌아가 빠진 항목을 채운다. 우회하지 않는다.
- 결과물 파일: `원고/{주제}/자료.md` → `기획.md` → (Claude 확정) `선택.md` → `대본_v1.md` → **`대본_v1_읽기용.txt`(사용자 검토용, 기본으로 보여 줌)** → ("최종" 때) `대본_최종_낭독문.txt`

## 0단계 — 기존 원고와 겹치는지 확인

목표는 **기존 대본과 겹치지 않는 원고를 많이 만드는 것**이다. 기획 전에 아래 목록을 모두 확인한다(주제 중복 확인용으로만 보고, 그쪽 규칙은 가져오지 않는다).

- 이 폴더 `원고/` 아래 주제 폴더 전부
- `C:/Users/진실/Downloads/미드폼 작성/여행/원고/` 아래 주제 폴더 전부와 `원고_상태목록.md`, `이전원고/`

판정: **같은 도시(지역) + 같은 시청자 질문(00의 판정 기준 표)**이면 중복이다. 같은 도시라도 질문이 다르면(예: 숙소 vs 맛집) 중복이 아니지만, 기존 원고와 핵심 정보가 절반 이상 겹치면 중복으로 본다.
- 사용자가 준 주제가 중복이면 겹치지 않는 각도(다른 도시·다른 질문)로 바꿔 진행하고, 바꾼 이유를 보고에 적는다.
- 사용자가 주제를 주지 않으면 겹치지 않는 주제를 Claude가 고른다. `내경험.md`에 쓸 경험이 있는 지역을 우선한다.
- `기획.md` 맨 위에 **중복 확인** 항목(확인한 기존 원고 목록과 판정)을 적는다.

## 1단계 — 제목·썸네일·도입 기획

**입력은 두 가지 중 하나:**
- **키워드만 줄 때:** 직접 웹 검색해 최신 정보를 찾는다. 찾은 출처는 `원고/{주제}/자료.md`에 남긴다.
- **참고 소스를 줄 때 (웹사이트·유튜브 영상 등):** 그 소스를 먼저 전부 읽고, 부족하거나 오래된 정보만 검색으로 보완한다. 외국 영상은 번역이 아니라 한국 시청자 기준으로 다시 짠다.

1. `00`, `01`, `내경험.md`를 읽는다.
2. **핵심 메시지** 한 줄, **후킹 포인트** 3개(손해·의외성·숫자·비교 등 실제 내용 근거)를 정리한다.
3. **유형 판정:** 5개 유형 전부를 한 줄씩 ○/△/× + 이유로 점검하고, 주 유형 1개(필요하면 보조 유형)를 정한다.
4. 판정된 유형 파일을 전부 읽는다.
5. 후보 각도를 속으로 비교한 뒤 **가장 좋은 1안을 확정**한다. 확정안은 한 세트로:
   - 제목 + 블록 1~4를 각각 무엇으로 채웠는지 (유형 템플릿 기반)
   - 썸네일: 상단 텍스트(박스 색) / 하단 텍스트(박스 색) / 메인 오브젝트 / 배경
   - 도입 첫 2~3문장 (제목·썸네일 약속과 100% 매칭, 경험담은 실제 경험 또는 `[각색]` 표시)
   - 왜 누르고 싶어지는지 한 줄
   - **확정 이유:** 버린 각도(한 줄씩)와 이 안이 이긴 이유 — `01`의 삼각 연관성·후킹 포인트 기준으로
6. `선택.md`에 "Claude 확정안"과 확정 이유를 적고, 사용자 선택을 기다리지 않고 바로 2단계로 간다.

## 2단계 — 원고 작성

1. `01`, `02`, 판정된 유형 파일, `내경험.md`, 확정안(`선택.md`)을 읽는다.
2. **흐름 원고 찾기** (사례 원고 `참고/사례원고/S??_*.md` — 전체 통독 금지)
   1. `03` 색인에서 주 유형과 같은 유형의 사례를 후보로 고른다.
   2. 주제 핵심 단어(예: 숙소·호텔)로 후보 원고를 검색해, 해당 대목이 많은 원고 2~4편을 고른다.
   3. 그 원고들에서 **주제 관련 대목과 앞뒤 문단만** 읽는다. 원고 전체를 처음부터 끝까지 읽지 않는다.
   4. 가장 잘 맞는 1편을 **뼈대**로 정하고, 필요하면 다른 1편의 대목을 더한다.
   5. 대본 위쪽에 **흐름 대응표**(대본 순서 ↔ 참고한 사례 번호·흐름)를 넣는다. 없으면 저장이 거부된다.
   - 가져오는 건 **흐름(전개 순서·장 구성·전환 방식)**뿐이다. 사례 원고의 문장·경험·숫자를 옮겨 쓰지 않는다.
   - **뼈대는 사례 1편으로 통일한다 (2026-10-09 사용자 지시).** 여러 사례에서 조금씩 빌려 오지 않는다. 흐름 대응표는 뼈대 사례의 블록 순서 ↔ 이번 대본 블록을 한 줄씩 짝지어 쓴다.
   - **억지로 짝짓지 않는다 (2026-10-09 사용자 지시: "억지로 하면 안 되고 실제로 도움되는 쪽으로").** 뼈대 원고는 영상 전체 흐름이 가장 비슷한 1편을 고른다(주제 대목이 한 구간뿐인 도시 가이드보다, 같은 종류의 고민을 처음부터 끝까지 푸는 원고). 대응표를 쓴 뒤 짝마다 "이 칸에 이 내용이 자연스러운가"를 스스로 판정해, 억지인 칸은 빼거나 합치거나 맞는 칸으로 옮긴다. 이번 주제에서 결론을 가르는 항목은 뼈대 원고보다 크게 다뤄도 된다. 판정 결과(억지 칸과 처리)를 대응표 아래 적는다.
   - **비교 범위는 제목·썸네일이 정한 대상까지만 (2026-10-09).** 예: "맨해튼 vs 뉴저지"면 브루클린·퀸스 같은 다른 동네를 넣지 않는다. 다른 대상은 별도 편으로 돌리고, 기존 원고와 겹치는 대상은 0단계 중복 판정을 따른다.
   - **도입이 건 말은 본문이 실제로 보여 준다.** 첫 문장이 결과를 말하면(예: "더 비싸게 지낼 수 있다") 그 결과가 실제로 생기는 예시를 본문에 넣고, 도입에서 건 질문은 본문에서 "처음에 말씀드린 ~"으로 답한다. 출처 없는 금액을 첫 문장에 실제 본 것처럼 쓰지 않는다.
   - **핵심 주제를 한 문장으로 대본 맨 위에 명시**하고, 도입·중간·합계·마무리에서 같은 문장으로 되풀이한다. 용어는 처음부터 끝까지 통일한다.
   - 확정한 제목·썸네일·도입이 본문 어디서 지켜지는지 **약속 대응표**를 대본 위에 둔다. 섹션마다 같은 박자(구분 → 숫자 → 혼자/둘이·추천/비추천 → 누적)를 반복해 듣기 쉽게 한다.
3. 도입은 5단계 훅, 본문은 뼈대 원고의 흐름 위에 유형 파일 B의 장치를 얹고, 문장은 `02`의 기술(숫자 줄이기 포함)을 따른다.
4. 분량은 `00`의 유형별 분량을 따르고, 본문 글자 수는 스크립트로 직접 세어 적는다(추정 금지).
5. 원고 끝에 `02`의 점검표 결과를 붙인다.
6. **대본을 보여 줄 때는 md가 아니라 읽기용 txt로 보여 준다 (2026-10-09 사용자 지정, 기본값).** 구성(흐름 대응표)을 잡은 뒤 원고를 처음 보여 줄 때와 고쳐서 다시 보여 줄 때마다 적용한다. 대화창에 전문을 붙이는 것으로 대신하지 않고(사용자가 대화창 텍스트를 따로 요청할 때만), 대화창에는 파일 위치와 바뀐 점만 짧게 쓴다. 오른쪽 파일 창이 별도 창으로 떠 있으면 그 사실만 알린다. 대본 md를 저장·수정할 때마다 아래 명령으로 `대본_vN_읽기용.txt`(장 제목 구분선 + 한 문장 한 줄 + 문단 사이 빈 줄)를 만들고, 오른쪽 파일 창(`show_pane`, file)에 그 txt를 띄운다. 이 폴더가 세션 폴더가 아니면 먼저 `request_directory`로 추가한다. 도구가 본문을 찾도록 대본 md의 낭독 본문 앞뒤에 `<!-- 본문 시작 -->` / `<!-- 본문 끝 -->`를 넣고, 본문 안에는 소제목(`##`)과 낭독 문장만 둔다(메모·출처·대응표는 본문 밖).
   `C:/Users/진실/AppData/Local/Python/pythoncore-3.14-64/python.exe -X utf8 .claude/tools/script_txt.py 읽기용 원고/{주제}/대본_vN.md`
7. 사용자에게는 확정한 제목·썸네일 1개, 읽기용 txt 위치, 중복 확인 결과를 함께 보고한다.

## 수정 단계 — 읽기용 txt로 피드백

- 사용자는 읽기용 txt의 줄을 골라 '댓글 추가'/'컨텍스트로 첨부'로 피드백한다. 원본은 대본 md다: md를 고친 뒤 읽기용 txt를 다시 만들어 띄운다(md와 txt가 어긋나지 않게). 사용자 수정 지시는 `선택.md` 사용자 수정 기록에 남긴다.
- 사용자가 읽기용 txt를 직접 고친 경우 그 내용을 md에도 반영한다.

## 최종 — 사용자가 "최종"이라고 하면

1. 사용자가 고친 최신 읽기용 txt를 기준으로 TTS용 클린 대본을 만든다(장 제목·구분선·메모 없이, 문단 1개 = 1줄, 문단 사이 빈 줄 — 기존 낭독문 형식):
   `C:/Users/진실/AppData/Local/Python/pythoncore-3.14-64/python.exe -X utf8 .claude/tools/script_txt.py 최종 원고/{주제}/대본_vN_읽기용.txt 원고/{주제}/대본_vN.md`
2. 도구가 "[알림] 읽기용과 md가 다름"을 내면 md에도 반영하고, "[경고]"(사례 번호·`[각색]`·저희·마크다운 표시)가 나오면 고친 뒤 다시 만든다. `[각색]`은 사용자 확인 없이 지우지 않는다.
3. `대본_최종_낭독문.txt`를 파일 창에 띄우고, 글자 수(도구 출력)와 함께 보고한다.

## 탈고 — 사용자가 "탈고"라고 하면 (2026-10-13 사용자 결정)

사용자가 대본을 다 고친 뒤 "탈고"라고 하면 묻지 않고 아래를 끝까지 한다. 탈고 뒤에 원고를 또 고치고 다시 "탈고"라고 해도 같은 순서를 다시 한다(트렐로 카드·편집 폴더는 새로 만들지 않고 갱신).

1. **최종 대본 만들기** — 위 「최종」 1~2번 그대로(최신 읽기용 txt 기준 → `대본_최종_낭독문.txt`).
2. **트렐로에 올리기** — 여행 보드 「탈고」 리스트. 카드 제목 = 확정 제목(`선택.md`). 카드 설명은 UTF-8 txt로 만들어 넘긴다(16,000자 이하):
   ```
   📌 핵심 주제: {대본 맨 위 핵심 주제 한 문장}
   🎬 확정 제목: {선택.md 확정 제목}
   🖼️ 확정 썸네일: 윗줄 {…} / 아랫줄 {…} / 메인 오브젝트 {…} / 배경 {…}
   📁 원고 폴더: 원고/{주제}/ · 편집 폴더: C:\여행영상소스\{주제}\
   ---
   {대본_최종_낭독문.txt 전문}
   ```

## 지킬 것

- **경험담:** 실제 경험 우선. 없으면 조사 기반 각색안을 `[각색]` 표시와 근거 출처를 붙여 추천한다 (`02` 0번).
- 참고 파일 속 가격·요금·벌금·규정 숫자는 **벤치마크 당시 예시**다. 원고에 쓸 땐 최신 정보로 확인하고, 확인한 출처를 원고 아래에 남긴다.
- 보상(체크리스트·구글 지도 링크 등)은 사용자가 실제로 준비한 것만 약속한다.
- **확실하게 확인 안 된 사실은 뺀다 (사용자 지시 2026-10-09: "확실하게 팩트 체크 안 되는 건 그냥 빼는 게 나아").** 원고의 수치·규정·시행일·소요 시간·배차 간격은 공식 출처나 여러 출처가 일치할 때만 쓴다. 여행 사이트 한 곳·오래된 기사 하나·2차 요약뿐이면 빼거나, 사실 주장이 아닌 확인 행동 안내("결제 화면에서 확인하세요", "노선도에서 확인하세요")로 바꾼다. 시행 예정인 제도를 지금 시행 중처럼 쓰지 않는다. 확인 수준은 `자료.md`에 출처와 함께 적는다.
- 결과물은 `원고/{주제}/` 폴더에 저장한다.
